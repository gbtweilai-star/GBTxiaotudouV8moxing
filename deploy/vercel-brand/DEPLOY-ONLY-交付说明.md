# GBT小土豆V8 · 品牌主页 · 「可部署、不可读源码」交付设计

⛔ 开发者：自由的风 · 永久钢印 · 禁止删除

---

## 〇、结论先行

**在 Vercel 上不存在「上传源码但对方读不到」的技术手段。** 这不是没找到方法，这是平台机理决定的。

Vercel 的部署模型是：**客户端上传明文源码 → 云端装依赖 → 云端构建 → 出产物**。构建这一步必须读明文。所以只要交付物是「一个源码目录」，读源码就只是 `cat` 一下的事。加密、改后缀、塞 zip、拆文件都不改变这一点。

因此本方案不解决「加密」，解决的是**「交付什么」**。按强度从高到低：

| # | 方案 | 强度 | 接收方能做 | 不能做 | 代价 |
|---|---|---|---|---|---|
| **①** | **只交部署触发器**（本方案推荐） | ★★★★★ 物理不可读 | 触发部署、看构建日志 | 读源码、改代码 | 改代码需回头找你 |
| ② | 交付编译产物（Nuitka / PyArmor / 仅 `.pyc`） | ★★★☆☆ 需逆向能力 | 部署、跑、改配置 | 直接读源码 | **Vercel 不适用**，须换自托管/容器 |
| ③ | 服务化（代码留你侧，只开 API） | ★★★★★ | 只能调接口 | 读源码、部署 | 需常在线、有运维成本 |
| ④ | 交付 strip 源码目录 | ★☆☆☆☆ 只挡「随手翻」 | 一切 | —— | 几乎无保护 |

### 对这个站，推荐 ①，三条理由

1. **该站没有需要藏起来的运行时逻辑。** 它是一个服务端渲染的公开品牌页：6 张能力卡、5 层架构、4 个只读端点。真正值钱的逻辑（统一密钥网关、触手视觉、镜像空间）**本来就在你自己的机器上**，不在这个目录里。
2. **④ 档在这里几乎无效，有实测数字。** `strip` 档把 22441 B 压到 20641 B，**只缩水 8%** —— 因为体积集中在 `PAGE` 那个 HTML 字符串里，那是**数据**而不是注释。剥注释剥不掉数据。所以拿 strip 产物当"保护"是自欺。
3. **① 是零额外基建的。** Vercel 自带 Deploy Hook，不需要 CI、不需要服务器、不需要容器。

## 一、为什么 ④ 档（strip/打包）不构成保护

实测数据（本机跑的，可复现）：

```
api/index.py   strip  22441 → 20641 B  (-8%)  语义等价=True
```

只有 8%。原因是这个站的结构：

| 成分 | 体积占比 | strip 能否消除 |
|---|---|---|
| `PAGE` 里的 HTML + CSS 字符串 | ≈ 85% | ✗ 这是数据，不是注释 |
| 6 条能力 + 5 层架构的文案常量 | ≈ 10% | ✗ 同上 |
| 注释 / 文档字符串 / 类型注解 | ≈ 8% | ✓ 已剥 |
| 函数逻辑 | < 2% | ✗ 剥了就不跑了 |

**结论**：strip 对该站是「把注释删掉」，阅读体验从"好读"变成"能读"而已。它只在**逻辑密集**的代码库里才有意义。

## 二、方案 ① 落地：部署触发器

### 2.1 机理

```
授权方（你）                       接收方（运维）               Vercel
──────────────                    ──────────────              ──────
私有仓库 / 本地源码  ──────────────✗ 看不到──────────────────┐
     │                                                       │
     └── 只交出 hook 地址 ──────→  deploy-trigger.py  ──POST──┴─→ 云端拉源码
                                                                   ↓
                                                              构建 → 部署
                                                                   ↓
                                                          www.gbtv8.com
```

源码自始至终在**你的**仓库里。接收方手里只有一个 POST 地址。他点一下，云端去**你授权的仓库**拉代码构建。

### 2.2 加固清单（缺一条这个模式就漏）

裸的 Deploy Hook 只是"一个能用的 URL"，直接交出去是不合格的。必须一并加固：

| # | 风险 | 加固措施 | 已实现位置 |
|---|---|---|---|
| 1 | 脚本里硬编码 hook，一泄露全泄 | hook 只从**环境变量**或**本地 0600 文件**读 | `deploy-trigger.py: load_hook()` |
| 2 | 日志/终端把完整 hook 打出来，被截图带走 | 打印一律**脱敏**（`…7xyz（共 72 字符）`） | `_mask()` |
| 3 | 误填第三方地址，等于把触发器送人 | **形态闸**：必须匹配 `api.vercel.com/v1/integrations/deploy/prj_*/…` | `HOOK_PATTERN`，已三重对照实测 |
| 4 | 脚本被套进循环，把构建配额烧穿 | **本地限流**：两次成功触发至少间隔 60s，`--force` 才可绕过 | `MIN_INTERVAL_S` |
| 5 | 出事查不到谁在什么时候触发过 | 每次触发写 **JSONL 审计记录**（时间/结果/脱敏地址） | `AUDIT_LOG` |
| 6 | hook 泄露后永久可用 | 泄露即在 Vercel 后台 **regenerate**，旧地址即刻失效 | 见 §2.4 轮换流程 |
| 7 | 接收方顺手把站点源码扒下来 | 站点是服务端渲染，HTML 里**无源码**；但 HTML/CSS 本身公开 —— 这是公开站点的正常属性，不是泄露 | 设计如此 |

### 2.3 操作步骤

**你（授权方）做一次：**

1. Vercel 后台 → 项目 `flask-python-boilerplate` → Settings → **Git** → 连接你的私有仓库（源码只在这里）
2. 同页 → **Deploy Hooks** → 新建一个 hook，名字填 `gbtv8-prod`，分支填 `main` → 生成
3. 复制生成的地址（形如 `https://api.vercel.com/v1/integrations/deploy/prj_xxx/yyy`）
4. 通过**安全信道**把它交给接收方（不要走聊天/邮件明文）

**接收方（运维）做一次：**

```bash
mkdir -p ~/gbtv8-deploy && cd ~/gbtv8-deploy
# 把 deploy-trigger.py 放进这个目录
printf '%s' 'https://api.vercel.com/v1/integrations/deploy/prj_xxx/yyy' > .gbt-deploy-hook
chmod 600 .gbt-deploy-hook          # Windows: icacls .gbt-deploy-hook /inheritance:r /grant:r "%USERNAME%:R"
python deploy-trigger.py --check    # 只校验，不发请求
```

**日常部署：**

```bash
python deploy-trigger.py --go             # 触发
python deploy-trigger.py --go --wait      # 触发并轮询到构建结束
```

### 2.4 hook 泄露后的轮换流程

1. Vercel 后台 → Deploy Hooks → 对旧 hook 点 **Delete**
2. 新建一个，把新地址通过安全信道给接收方
3. 接收方覆盖 `.gbt-deploy-hook`
4. 旧地址此刻已失效 —— 泄露窗口关闭

**轮换成本**：约 1 分钟。**建议周期**：接收方人员变动时立即轮换。

## 三、方案 ② 落地：交付编译产物（仅供自托管）

如果确实必须交出**能独立部署的运行体**，且愿意放弃 Vercel：

| 工具 | 产物 | 强度 | 备注 |
|---|---|---|---|
| `_protect.py bytecode` | 仅 `.pyc` | ★★☆☆☆ | 有 `uncompyle6`/`pycdc` 就能还原；**Vercel 不加载** |
| **Nuitka** | 原生二进制 | ★★★★☆ | `nuitka --standalone`，反编译成本极高；镜像体积大 |
| **PyArmor** | 混淆 + 运行时 | ★★★★☆ | 商业方案，支持 RFT 模式（字节码不落地） |

命令：

```bash
python _protect.py bytecode --out ./bycode   # 已实测可跑，产物自证跳过 Flask 判据
```

⚠️ **诚实提示**：以上三者都是**提高逆向成本**，不是**禁止逆向**。有资源有动机的人仍可还原。只有方案 ① 和 ③ 是数学上不可读。

## 四、工具清单（本目录）

| 文件 | 作用 | 谁用 |
|---|---|---|
| `_protect.py` | 三档保护构建器：`strip` / `bytecode` / `pack` / `verify` | 你 |
| `deploy-trigger.py` | 加固部署触发器（脱敏 / 形态闸 / 限流 / 审计） | **接收方** |
| `LICENSE-专有授权.txt` | 专有授权声明（授权声明单一真源） | 随包交付 |
| `_site_check.py` | 品牌合规判据 11 项，含正负对照防扫描器失明 | 你 / CI |
| `_live_smoke.py` | 真实 socket 四路冒烟（不走 test_client 短路） | 你 / CI |
| `_make_preview.py` | 生成离线自包含预览 | 你 |
| `DEPLOY-ONLY-交付说明.md` | 本文件 | 你 |

### 出货白名单（`_protect.py` 里写死）

出货用**白名单**而不是黑名单 —— 没登记的文件永远进不去，不存在"忘了排除某个内部脚本"这种事故：

```
requirements.txt             as-is
vercel.json                  as-is
api/index.py                 strip
api/assets/logo-256.png      as-is
api/assets/logo-512.png      as-is
api/assets/favicon-32.png    as-is
```
> `deploy-trigger.py` 单独交付给接收方，不在源码包里。
> `_site_check.py` / `_live_smoke.py` / `_protect.py` / `_make_preview.py` **永不交付**。

## 五、strip 档的自证纪律（防止"保护"把程序保护坏）

剥离不是"删注释就完事"，必须能证明**行为没变**。`_protect.py` 强制三道闸，任一不过即**删产物**：

1. **语义等价对拍** —— 剥前后各做一次 AST dump（都先去掉文档字符串），要求**逐字节相同**。
   实测：`语义等价=True`，偏差定位到具体偏移量便于排障。
2. **关键常量存活** —— 必须仍含 `--gbt-violet:#7C4DFF`（三色定义）与 `@@CARDS@@`（渲染占位符）。
   （这一条来自 R63 教训：三色声明了但 `var(--gbt-violet)` 全仓 0 命中 ⇒ 屏上少一色。）
3. **署名钢印存活** —— 剥离后仍必须有 `⛔ GBT小土豆V8 · 版权归属：自由的风 …`。
   品牌纪律：署名不可删除、不可篡改归属。**剥注释不能顺带把署名剥掉。**

过了这三道，再对产物树跑一遍全量判据（`_site_check.py` 11 项 + `_live_smoke.py` 真端口四路），全绿才算构建成功。实测已通过。

## 六、遗留与风险（如实列出）

1. **① 档下接收方无法自行改代码。** 任何文案/样式调整都要回来找你。这是保护强度的**代价**，不是缺陷 —— 需要权衡。
2. **Vercel 团队成员的权限粒度受平台限制。** 若走"加成员"而不是 Deploy Hook，成员能否看到仓库源码取决于项目与仓库的连接配置。**此项未经实测，不要凭猜。** 需要时先在测试项目上验证。
3. **`_protect.py bytecode` 档未经 Vercel 实测。** 已确认 Vercel Python runtime 加载 `.py`，`.pyc`-only 目录不被识别是本方案的**技术判断**，未做线上验证。要用于生产前请先自托管实测。
4. **LICENSE 不构成法律意见。** 正式商业化交付前请交执业律师审阅，并按需办理著作权登记。
5. **客户端 HTML/CSS 天然公开。** 任何网站的前端产物都可被浏览器查看，这不是泄露。真正的保护对象是**服务端逻辑与凭证**，本方案已覆盖。
6. **部署授权尚未打通的阻塞点**（与本设计无关，但影响上线）：
   - vercel 连接器**尚未被信任**（`mcp-approvals.json` = `{}`）
   - OAuth 未完成（缓存里只有 `codeVerifier`，无 `access_token`）
   - 授权服务器元数据的 `token_endpoint_auth_methods_supported` **不含 `none`**，而我们注册的是公共客户端（`token_endpoint_auth_method: "none"`）⇒ **令牌交换有可能被拒**
   - 备选路径已实测可达：npm registry 通（`vercel latest = 60.1.3`，577 ms）、`api.vercel.com` 无令牌返回 403（通路正常）。走**个人 Access Token** 更稳。
