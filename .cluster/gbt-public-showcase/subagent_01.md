## ① 一句话总评

**里子很厚、门面很薄**：三个官网方向页（site_a/b/c）内容完整、信任点齐全（费率 10/1.5/5 单据化、资金链路、安全审计、FAQ），但真正的公众入口 `index.html` 只是一个"卡片目录"——首屏价值主张含糊、没有主 CTA、没有信任条；而且官网页**根本点不进产品**、最关键的"条款与风险披露"链接是**死链**。作为"公众门面"，现在的第一眼印象是"一个还没整理好的内部导航页"，而不是"一家可托付的数字资产平台"。

## ② 缺陷清单

### 🔴 高

**缺陷 1｜官网三方向页没有任何通往产品（钱包/兑换/消息）的入口**
- 文件/行号：`site_a.html`（全文锚点清单）· `site_b.html` · `site_c.html`
- 证据：site_a 全站 `href` 只有 `#services/#fees/#flow/#safety/#ai/#faq/#top`、`href="terms"`、`href="data:,"`；经脚本全量扫描，三页 `/ui/` 引用数 = **0**（`site_a/b/c` 的 `ui_abs=[]`）。
- 为什么影响公众印象：门面（官网）与产品（钱包/兑换/消息）**完全断裂**。访客看完官网想"进去用"，找不到任何"进入平台 / 打开钱包 / 立即兑换"按钮——官网沦为纯 PPT，转化归零。

**缺陷 2｜合规入口"条款与风险披露"是死链（404）**
- 文件/行号：`site_a.html:210`（首屏 CTA）与 `site_a.html:338`（页脚）；三页各命中 **4 处** `href="terms"`
  - `210: <a class="cta ghost" href="terms">条款与风险披露</a>`
  - `338: ...<a href="#faq">常见问题</a><a href="terms">条款与风险披露</a>`
- 证据：`terms.html`、`terms` 在 `web/` 下均**不存在**（`Test-Path` 均 False）。
- 为什么影响公众印象：对数字资产平台，**合规入口是信任的命门**。首屏最显眼的次 CTA 一点就 404，等于当众承认"没准备好"，直接击穿信任。

### 🟠 中

**缺陷 3｜`index.html` 首屏 3 秒看不懂"这是做什么、怎么开始"**
- 文件/行号：`index.html:62`（H1）、`index.html:63`（lead）、`index.html:65-84`（三卡）
  - `62: <h1>一个平台，三个入口。</h1>`
  - `63: <p class="lead">数字资产钱包、量化交易、消息中心——全程资金由平台处理，费率透明（币→币 1.5% · 量化收益 5%），到账以平台确认及链上记录为准。</p>`
- 问题：H1 是**抽象口号**，没有说清"是什么业务"；页面**没有主 CTA 按钮**（只有卡片）、没有信任条、没有"三步开始"引导；费率只藏在小字 lead 里，且**遗漏了 10% 法币→币**（与官网/wallet 的口径不一致）。
- 为什么影响公众印象：首屏是唯一"3 秒评分"窗口。现在 3 秒内用户得出结论是"一个链接页"，而非"一个可信的量化收益平台"。

**缺陷 4｜信息架构混乱：三个"官网方向草案"被当成公众内容展示**
- 文件/行号：`index.html:86-105`（第二组 `.grid`）
  - `87: <h3>官网 · 方向 A（深海军蓝）</h3>` · `93: 方向 B（冷纸编辑）` · `99: 方向 C（品牌主角）`，标签均为 `预览 →`
- 问题：把内部**三个设计方向草案**并列摆给公众看，且与真功能入口（钱包/消息/兑换）**视觉权重相同**（同样的卡片规格）。
- 为什么影响公众印象：访客会困惑"到底有几个官网？我该点哪个？"——暴露了内部决策过程，显得不专业、未定型。

**缺陷 5｜跨页视觉一致性断档（深↔浅反转 + 导航形态不一）**
- 文件/行号：
  - `index.html:9` `--bg:#05070d`（近黑）· `wallet_v2.html:16` `#05070d` · `exchange.html:14` `--bg:#060a12` · `messages.html:13` `--bg:#080d15`（均为深色）
  - `site_b.html` 主题变量 `--paper:#F5F4F0;`（**冷纸白 / 浅色**），`site_a.html --bg:#0B1E33`、`site_c.html --bg:#0E1620`（深色）
- 问题：从 `index` 点进 `site_b` 会**全屏明暗反转**（`<html>` 无主题提示，无过渡）。导航形态也不统一：`wallet_v2.html:443-448` 用固定底部 `.tabbar`；`exchange.html:391-396` 用另一套 `.botnav`；`messages.html:336-341` 又是内联样式的固定底栏；官网页则用顶部 `<details class="nav-toggle">` 菜单。
- 为什么影响公众印象：每换一页都像换了一个产品，品牌感被切碎。

**缺陷 6｜移动端 `messages.html` 底部导航遮挡消息输入框**
- 文件/行号：`messages.html:23` `.app{display:flex;height:100vh}`（+`body{overflow:hidden}`）· `messages.html:87` `.chat-input-bar{padding:10px 14px;border-top:...}`（**无底部让位 padding**）· `messages.html:336-341` 固定底栏 `position:fixed;bottom:0;...`（另有 `messages.html:112` 仅把侧栏收窄到 70px）
- 问题：输入栏位于 100vh 弹性格线的底部，而固定底栏 ~40px 高叠在其上，**发送按钮/输入框被盖住**。
- 为什么影响公众印象：手机用户（数字资产高占比）在消息中心无法正常发消息。

**缺陷 7｜"演示 / 离线"措辞外露，削弱可信度**
- 文件/行号：`wallet_v2.html:329` `请确认使用与地址匹配的网络（TRON）进行转账。当前为演示数据，仅供界面预览。`；`wallet_v2.html:386` `say({cls:"pill-wait", txt:"服务离线 · 演示模式"});`
- 问题：公众首访若后端不可达，状态胶囊直接显示"服务离线 · 演示模式"，页面自曝是演示。
- 为什么影响公众印象：诚实值得肯定，但**面向公众的门面**应把"演示态"降级为内部提示，避免第一印象就是"假的/测试的"。

### 🟡 低

**缺陷 8｜SEO / 社交分享元信息缺失**
- 文件/行号：全站 `og:`/`twitter:` 计数 = **0**（`index`、`wallet_v2`、`exchange`、`messages`、`site_a/b/c`）；`canonical` = 0；`web/` 下无 `robots.txt`、`sitemap.xml`、`manifest.webmanifest`、`404.html`（`Test-Path` 均 False）
- 为什么影响公众印象：被分享到微信/推特时**无标题卡、无缩略图**；搜索收录无抓手；错误路径无 404 兜底。

**缺陷 9｜品牌图标缺失或不统一**
- 文件/行号：`index.html`/`wallet_v2.html`/`exchange.html`/`messages.html` **无 `<link rel="icon">`**；`site_a.html:8`、`site_b.html`、`site_c.html` 使用 `<link rel="icon" href="data:,">`（**空白占位**）
- 证据：`web/favicon.svg`（255B）**存在却未被任何公众页引用**。
- 为什么影响公众印象：浏览器标签页没有品牌标识，观感像未完成的本地页面。

**缺陷 10｜文案与口径不统一**
- 文件/行号：`exchange.html:6` `<title>GBT Exchange — 数字资产兑换</title>`（英文名，其余页为中文品牌名）；费率口径三处不一致：`index.html:63`（1.5% · 5%，缺 10%）vs `wallet_v2.html:261-263`（1.5% / 10% / 5%）vs `site_a.html:264-286`（10 / 1.5 / 5%）
- 为什么影响公众印象：品牌名与费率是"可信度"细节，前后不一会被认为不严谨。

**缺陷 11｜"区域合规待公告"像未完成**
- 文件/行号：`site_a.html:206` `<span class="pill">18+ · 区域合规待公告</span>`
- 为什么影响公众印象："待公告"三字在合规语境下会被读成"还没合规"，是信任减分项；应改为明确的合规声明或直接省略。

**缺陷 12｜`messages.html` 缺 meta description**
- 文件/行号：`messages.html:6` 是 `<title>`、`messages.html:7` 直接是 `<style>`——**无 `name="description"`**（其余页均有）。
- 为什么影响公众印象：消息页在搜索结果里无摘要描述。

> 备注（未核实）：`index.html` / `wallet_v2.html` 中的 `/ui/...` 链接，`_routes.json` 只定义了 `/exchange`、`/wallet.html` 等**无 `/ui/` 前缀**的路由，但 `tools/audit_flow.py:19-22` 显示生产公网入口确为 `https://wallet-api.gbtxiaotudou.com/ui/index.html`——即生产用反向代理把 `web/` 挂在 `/ui/` 下。**生产路由可用**；但本地 `_routes.json` 与生产前缀不一致，属潜在坑点（未在生产环境实测确认）。

## ④ 最该先改的 3 件事

**1. 补真实合规页 + 修死链（先止血）**
建 `web/terms.html`（条款与风险披露）并让 site_a/b/c 的 4 处 `href="terms"` 正确指向；顺带补 `privacy`/`404.html`。**这是首屏 CTA 直接 404 的信任事故，优先级最高。**

**2. 打通「官网 → 产品」转化，并弱化"预览"卡片**
在 site_a/b/c 首屏 Hero 增加主 CTA「进入平台 / 打开钱包」（指向 `/ui/wallet_v2.html`、`/ui/exchange.html`、`/ui/messages.html`）；`index.html` 把 `86-105` 行的"官网方向 A/B/C 预览"降级或移除，避免把内部草案当公众内容。

**3. 重写 `index.html` 首屏，做到"3 秒可读"**
把 `index.html:62` 的抽象口号换成说清业务的价值主张；在首屏加入**信任条 + 三步流程 + 主 CTA**；统一费率口径为 **10 / 1.5 / 5%**（与官网、钱包对齐）。配套修 `messages.html` 移动端底栏遮挡（缺陷 6）与全站 favicon/og meta，作为同一批"门面收口"。
