## 一 · 导演 AI 情绪内核（`gbt_allinone/tools/director_mood.py`）

**一句命门**：**导演自己要有七情六欲，才能投入。不懂人情世故的无奈，就拍不出人味。**

### 1.1 三条公理（写进图纸）

| # | 公理 | 含义 |
|---|---|---|
| **D1** | 导演有七情六欲，但**情绪只影响"怎么看"，不影响"看到什么"** | 情绪是镜头滤镜，不是剧本改写 |
| **D2** | 导演懂人情世故的无奈 —— 世间没有非黑即白 | 呈现时**保留灰度**，不替任何人下结论 |
| **D3** | 导演的投入必须**可观测** | 她的情绪状态要能被别人看见；**不能假装懂** |

### 1.2 状态机（情绪有半衰期，不是常驻）

- **七情**：喜 · 怒 · 哀 · 惧 · 爱 · 恶 · 欲
- **六欲（驱动方向）**：生（保住存续）· 繁（推进）· 闻（看见真相）· 言（如实呈现）· 触（感知改动）· 息（知道收手）
- `DirectorMood`：`emotion` · `drive` · `intensity(0–1)` · `since` · **`trigger`（什么事让她进入这个情绪）**
- **`decay(half_life_s)`**：情绪有半衰期 ⇒ 过了就淡（不许常驻）

### 1.3 四条红线（写死）

1. **情绪只影响"怎么看"，不影响"看到什么"** —— **数据不许因情绪被篡改**；
2. **情绪状态必须可查** —— 不许假装懂，必须留状态；
3. **情绪有半衰期** —— 不许常驻，过了就淡；
4. **导演仍然是只读** —— **情绪不是执行授权**。

### 1.4 情绪如何影响"怎么看"（不篡改事实）

| 情绪 | 影响 | **不许做** |
|---|---|---|
| 喜 | 呈现时多标一处亮点 | 不许把"待认领"写成"已完成" |
| 哀 | 保留灰度，不急着下结论 | 不许隐去真实红点 |
| 怒 | 更突出违规项 | **不许放大严重程度** |
| 无奈 | 标注"环境限制 ≠ 代码 bug" | 不许替谁洗白 |

> **核心**：情绪是镜头的**色温**，不是画面的**内容**。
> **诚实边界**：她可以哀、可以怒、可以无奈 —— 但她看到的是不是真的，**不由她的情绪决定，由盘上的读数决定**。

**落点**：`tools/director_mood.py`；沙盘 8866 的导演面板挂**只读**情绪状态。

## 四 · 调研 AI（`gbt_allinone/tools/music_research.py` · 2026-09-19 立项）

**一句命门**：**调研 AI 的核心不是"知道什么火"，是"知道这个用户现在不想听什么"。**
**"别胡乱唱"的工程实现，不是靠生成端更聪明，是靠调研端先把禁区画出来。**

### 4.1 四层能力（缺一不可）

| 层 | 回答什么问题 | 缺了会怎样 | 优先工具 |
|---|---|---|---|
| **L1 趋势感知** | 最近哪些歌/风格在涨 | 只做 L1 ⇒ **跟风** | Soundcharts MCP · Spotify Web API |
| **L2 偏好建模** | 他反复听的是什么 | 只做 L2 ⇒ **重复** | statsfm Skill · Yambda-5B |
| **L3 意图理解** | 他在什么场景下听、为什么 | 只做 L3 ⇒ **猜错** | Personal AI DJ（RAG：自然语言→播放列表） |
| **L4 反馈迭代** | 这次唱对没（听完/跳过/点赞） | 只做 L4 ⇒ **永远慢一步** | Prompt-Optimized Music Generation |

### 4.2 输出必须是结构化的（**没有 `forbidden` 的调研 = 没调研**）

```json
{
  "genre_distribution": {},      // 流派分布
  "mood_tendency": {},           // 情绪倾向
  "bpm_range": [0, 0],           // 节奏区间
  "scene_tags": [],              // 场景标签（通勤/健身/睡前）
  "forbidden": [],               // 禁忌项 —— **"别给我胡乱唱"就是靠这个字段兜底**
  "confidence": 0.0              // 置信度 0–1
}
```

### 4.3 三条红线（写进图纸）

1. **只读用户数据** —— 不写任何用户侧数据；
2. **结论必须带置信度**；**置信度低于阈值时，输出"建议先问用户"而不是直接生成**；
3. **调研 AI 的结论是生成 AI 的输入，不是指令** —— 生成 AI 仍**有过目权**。

### 4.4 落刀要点

- **数据流**：听歌历史 → 调研 AI（L1+L2+L3）→ 结构化结论 → 生成端（MusicFlow/Suno/Miuse）→ 用户反馈 → **回流更新偏好模型**；
- **五层内核归位**：趋势感知＝感知运动层（感知）· 偏好建模＝结构层 · 意图理解＝闭环层 · 反馈迭代＝可塑层 · 生成触发＝感知运动层（执行）；
- **沙盘呈现**：调研结果以**只读卡片**挂进 8866，与音乐平台面板并列；
- **不碰**：面板 8765 · 信号环 · 写路径 · 出网（沙箱出网被挡 ⇒ L1/L2 的外部数据源今天只能标"未核实"）。

### 🔴 新发现（本轮唯一真问题）：`vision_cap` 是一条**第二套密钥路径**

```
vision_cap.py:114  "key": os.environ.get("GBT_VISION_API_KEY", "")      ← 环境变量取
vision_cap.py:122  if _cl.PROVIDER and _cl.API_KEY and …               ← 回落到模块常量

```

它命中今天刚立的两条红线：
**① 密钥池红线②（密钥只存 DPAPI，不许明文）** —— 这里的 key 走 env/模块常量，且**明文进返回值**；

**待核**（本轮**没验**，不假装验过）：调用方 / 面板是否会把这个 `key` **回显出去**。
**下一刀**：收口 `vision_cap` 的密钥路径（改走 `deepseek_key` / `model_key_pool`），并加带牙用例锁死"返回值不许带明文 key"。
