## 一、`coverage_auditor` 点名的两个缺口（**能直接开工**）

```
G1  视觉面（眼）0/5   —— 无显式上报形状（待核）
G2  手/脑/门/网/镜    —— 上报未满
按组覆盖：8/8 已有（无结构性死角）
```
**它是本仓自己的覆盖审计器**，所以这不是我猜的：
- **G1**：视觉面 5 个上报形状一个都没落地 ⇒ **"眼"这条线的读数形状缺失**（待核 = 它自己也没定死）
- **G2**：手（tentacle）/脑（brain）/门（gate）/网（web）/镜（mirror）**上报不满**
**⇒ 这两条是可以直接排期修的**：给这些面补显式上报形状，覆盖审计器就会把它们从缺口里划掉。

## 二、`selfscan` 的 3 条审计异常（**都标 legacy，`runtime_faults: 0`**）

```json
{"window": 500, "anomalies": 3, "runtime_faults": 0,
 "by_event":  {"pipeline_blocked": 1, "svc_down": 2},
 "by_signal": {"runtime": 0, "guard": 0, "trace": 1, "legacy": 2, "recovered": 0}}
```
| 项 | 读数 | 念法 |
|---|---|---|
| `runtime_faults` | **0** | 无运行时故障 |
| `anomalies`（窗口 500 条内） | **3** | 1 条 `pipeline_blocked` + 2 条 `svc_down` |
| `by_signal` | `trace 1` · `legacy 2` | **`legacy` = 历史信号**，不是新的运行时崩 |
| `recovered` | 0 | 未标已恢复 |

**🔴 一处必须防的误读**：`errors_by_kind` 那张表列了十几个 kind
（`payment_gateway` · `blockchain_bridge` · `social_trading_v2` · `monitor_service` ·
`backtest_api_v2` · `cis_harvesting_v2` · `quant_api` · `cis_v42_trader` · `crypto_gateway` ·
`gbt_wallet_api` · `gbt_cap_bridge` · `hcl_control` · `gate_daemon` … 各 `legacy: 1`，
`payment_gateway` 是 `legacy: 2`）。
**把 legacy 全加起来远大于 2 ⇒ 那张是「历史累计表」，不是「当前有十几个在故障」。**
**⇒ 当前窗口内的真异常就是 3 条**，不许念成"钱包/链/量化一堆都在坏"。
