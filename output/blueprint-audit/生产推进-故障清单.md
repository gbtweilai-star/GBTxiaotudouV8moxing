### 6.1 🔴 缺陷：`cross_scan` 空参走**慢路径**，最坏 **24 分钟**，且**没有整体预算**
```
gbt_allinone/cross_scan.py
  153  def _x_run_isolated(kinds=_X_SCANNER_KINDS, timeout_s: int = 240, …)
  189      timeout=timeout_s, env=env      ← 每个子扫描器一个独立子进程，各 240s 上限
  218  except _TimeoutExpired: …           ← 超时只记进子结果，不约束整体
  签名:  scan(deep: bool = True)           ← 有 deep 参数；**空参走 deep=True 慢路径**
```
**实测**：
| 调法 | 用时 | 结果 |
|---|---|---|
| `run_task("cross_scan", {})` | **>560s 未返回**（两次：批内 600s 拖死整轮、单跑 560s 零输出） | — |
| `cross_scan.scan(deep=False)` | **17.9s** | 有实质结果（见 6.2） |

**子扫描器 6 个 × 240s = 最坏 24 分钟。**
**⇒ 任何调它的面板/巡检都会被挂死。**

### 6.1b 🔴 **更正我自己的建议**（上一轮我给的改法是错的）
我上一轮写「改法：门面让空参走 `deep=False`」—— **撤回**。查出分派点后发现：

```python
api.py:682   return cross_scan.scan(bool((payload or {}).get("deep", True)))
scan.__doc__ 「deep=True 时含 H 维（全能力运行时可达——较慢）」
```
**⇒ `deep=True` 才覆盖 H 维**（全能力**运行时**可达性）。把默认改成 `False`
**等于悄悄把 H 维的覆盖丢掉** —— 正是本仓最忌的「覆盖静默缩水」。
**我那条建议会用一个假绿灯换掉一个挂死，两样都坏。**

**⇒ 正确的修法（保留覆盖、只加护栏）**：保持 `deep=True`，给它一个**整体预算**
（deadline 穿过 `_x_run_isolated`），超了就把"**已超 / 只覆盖到第 N 个子扫描器**"
**如实报出来**，而不是缩小 `dims` 或把超时藏进子结果。
**未做（要动 440 行文件的调用链，我不盲改；等拍板）。**

### 7.6 🔴 本轮最重一条新故障：**覆盖面最薄的那一层是 fail-open**

`run_task` 的检查顺序（`gbt_allinone/api.py`，逐行读过）：

```
1546  decision = _policy.authorize(kind, payload)      ← 作用域门：拒了直接 return denied（fail-closed）
1578  guard = _preflight.before_action(kind, payload, decision=..., force=force)
1584  except Exception as e:                            ← 🔴 这里
1587      _audit("preflight_error", {...})               ← 只留痕
1591      guard = {"status": "not_guarded", "side_effect": False, "error": ...}
...
1675  lease = guard.get("lease")
1677  result = _run_benign(kind, payload, decision)      ← **照旧执行**
```

**⇒ `preflight.before_action()` 抛异常时，动作照跑。** 这是 `api.py` 里明写的取舍
（注释原文：**"感知层故障不能伪造『已检查』，也不能阻止原有能力；如实留痕后继续原路径。"**）——
它是**声明过的**取舍，不是偷偷摸摸的洞，但后果必须说清：

> 对 7.2 那 **11 个"零作用域但会改状态"的位**，`policy` 门根本不收口，
> **唯一挡它们的就是 `preflight`**。而这一层一旦抛异常（比如 action_guard 目录不可写、
> 指纹计算失败、子进程探测超时），**11 个写口全部变成无门可过**，只在审计里留一条
> `preflight_error`。

**两条修法（都不许我盲改，等拍板）**：
- **甲（收紧）**：`not_guarded` 且 `side_effect` 判定为真的动作 ⇒ 转成 `needs_confirmation` / `denied`，
  把"感知层坏了"变成"这次不执行"，而不是"这次当成没检查"。**代价**：感知层抖动会挡住正常能力。
- **乙（不改行为，只补可观测）**：保留 fail-open，但把 `preflight_error` 从"一条审计"
  升级为**框架声带（`alerts`）的显式告警 + `health` 的降级项**，让它在体检读数里现形。
  **代价**：洞还在，只是不再隐形。
- 🔴 **不做的事**：不许把 `not_guarded` 的 `side_effect` 直接改成 `False` 来"消掉告警"——
  那是把判据改成迎合读数（本仓最忌的一种假绿）。

**未做（要动 `api.py` 的分派主链，改错一处就是全能力面停摆；等主人拍板甲/乙）。**
