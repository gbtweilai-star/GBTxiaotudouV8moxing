# 进程内会话上下文块 · 现读（2026-09-26 第 53 轮 · F18 的一手证据）

## 这是什么

一张**从进程里读出来**的名册，不是从盘上渲染出来的。

- 读法：一个**临时 Cordis 宿主插件**（Host 半边，动态定义，未落仓）在 `apply()` 里调
  `ctx.get('systemPrompt').assemble({})`，把 `contexts[].name / .order / 文本长度 / 首行前 48 字`
  写进 `%TEMP%\ctx-blocks-live.txt`。
- 为什么非得这么读：宿主半边**只在进程启动时装载**，而此前所有闸（开机自检 · 验收单 ④⑥ ·
  装机副本漂移闸）**全都拿盘上的装机副本渲染** —— 它们能证明「代码对」，证明不了「进程里有没有」。
- 同一支探针还自己注册了一条上下文块（`name: 'gbt-probe-ctx-live'`, `order: 498`），用来证
  「注入通路是不是活的」。**它确实出现在了会话上下文里**（原样一行：
  `【探针 · 注入通路现读】这条探针块若出现在会话上下文里 ⇒ 宿主 systemPrompt.context 通路是活的。`）。

## 这张名册说明了什么

1. **`gbt-progress-ledger` 不在里面。** 主人要的「排查台账 · 重启之后自动读取」，
   在这一版进程里**从未生效**。
2. 通路本身是好的：探针自己注册的块到了；`gbt-master-panels`（order 500）与
   `gbt-digital-human`（501）也都在。
3. 时间线（UTC）解释了为什么：

   | 事件 | 时刻 |
   |---|---|
   | DSH web 进程启动（**装载宿主代码**） | 2026-09-25 10:33:32 |
   | 总面板块 / 数字人块 / `version:'1.8.1'` 入库（commit 946f3881） | 2026-09-25 10:40:12 |
   | **台账块**入库（commit b74142c5，第 34 轮） | **2026-09-25 21:03:15** |

   台账块比进程晚 **10.5 小时**，而 `version` 自 10:40:12 起**一字未动**
   ⇒ 验收单 ① 读「进程 1.8.1 == 源稿 1.8.1」判 **✅**。

## 复现方法

1. 定义一支 Host 半边动态 Cordis 插件，`apply()` 里
   `const sp = ctx.get('systemPrompt')` → `await sp.assemble({})` → 只取名册字段写文件；
2. 再 `sp.context({ name: 'gbt-probe-ctx-live', order: 498, text: '…' })` 注册一条探针块，
   看下一轮会话上下文里有没有它；
3. 跑完 `cordis_stop` / `cordis_undefine` 撤掉，别留在进程里。
