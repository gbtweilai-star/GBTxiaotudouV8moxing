## 甲、**真故障面**：可达组件里的 5 处（用户点得到）

> 可达 = 从 `/src/App.tsx` **传递可达**的 7 个文件：
> `App.tsx` · `context/AuthContext.tsx` · `components/LoginForm.tsx` · `pages/Dashboard.tsx`
> · `components/Sidebar.tsx` · `components/TopBar.tsx` · `components/DashboardStats.tsx`
> 另外 11 个文件**无人 import**（见丙）。

### F1 · 侧栏三条导航**全是死链**（`Sidebar.tsx` L17 / L22 / L27）
**现状原文**：
```tsx
<a href="#" className="flex items-center p-2 rounded-lg text-foreground hover:bg-brand/5">Overview</a>
<a href="#" className="flex items-center p-2 rounded-lg text-foreground hover:bg-brand/5">Analytics</a>
<a href="#" className="flex items-center p-2 rounded-lg text-foreground hover:bg-brand/5">Settings</a>
```
**根因**：`App.tsx` 只有两条路由（`/login`、`/`），**这三条没有对应路由** ⇒ 点击只把 URL 变成 `#`，页面无反应。
**改法（两档，选一）**：
- **最小档（不新增页面）**：既然没有目的地，就别伪装成链接 —— 改成
  `<span className="... cursor-default opacity-60">Overview</span>` 或去掉。
  判据：点它**不再改变 URL**，且视觉上不呈现为可点链接。
- **完整档**：`App.tsx` 加三条路由 + Sidebar 换 `<NavLink to="/overview">`。
  判据：点击后 URL 变为对应路径、右侧内容切换、该条呈 active 态。

### F2 · `Dashboard` 只挂了一个组件，其余是死代码（`pages/Dashboard.tsx` L17）
**现状原文**：
```tsx
<main className="p-6">
  <DashboardStats />
  {/* Other dashboard components */}
</main>
```
**实测后果**：登录后的 DOM 里 `svgs: 0 · canvases: 0 · imgs: 0` —— **一个叫 Dashboard 的页面零图表零图标零图**。
而 `ChartDashboard.tsx`（含 12 个月 revenue/users 数据）**已存在却没被挂载**。
**改法**：把已有组件接上，例如
```tsx
<DashboardStats />
<ChartDashboard />
```
**判据**：Dashboard 页面 DOM 里 `svgs + canvases > 0`（现在是 0）。

### F3 · 统计卡是**硬编码样例数据**（`DashboardStats.tsx` L3）
**现状原文**：`const stats = [ { label: "Total Users", value: "12,847", change: "+12.5%", up: true }, … ]`
**风险**：界面上看起来是真实指标（12,847 用户 / $48,295 收入），**其实写死在源码里**。
**改法**：接数据源；**短期内至少**在源码/界面上明确标注是示例数据。
**判据**：数值来自请求；或该处有显式「示例数据」标注。

### F4 · 标题 `Dashboard` **重复出现两次**
**现状源码**（两处）：
- `Sidebar.tsx`：`<h1 className="text-xl font-bold">Dashboard</h1>`
- `TopBar.tsx`：`<h2 className="text-lg font-semibold">Dashboard</h2>`
**DOM 实证**：`headings = ["H1: Dashboard", "H2: Dashboard"]`
**改法**：侧栏那处改成品牌/区段名（如 `GBT小土豆V8`），顶栏保留页面名。
**判据**：页面上以「Dashboard」为标题的元素只剩 1 个。

### F5 · App **没有 `<title>`**
**实测**：`iframe.contentDocument.title === ""`，srcdoc 里 `hasTitleTag: false`
**改法**：给构建产物/模板加 `<title>`。
**判据**：`contentDocument.title` 非空。

## 乙、**页面级故障**（在 builder 侧，不在 App 源码里）

### P1 · 检查点保护拦下了那次视觉修复 —— **至今未落地**（报错卡仍在）
**DOM 原文（4 行，同一张卡）**：
```
This change was not applied.
It would have broken something that already works in your app:
the / page would stop existing
Your app is untouched. Try asking again more specifically, or turn off the protection
for this in the checkpoints panel if the change was intentional.
```
**被拦的请求**是一条「让 AI 自评截图并修视觉问题」的长提示词 ⇒ **视觉问题至今还在**（F2/F3/F4/F5 就是它本该处理的）。
**改法**：在 checkpoints 面板关掉该保护，或把请求拆小、明确"保留 `/` 页面"。
**判据**：该卡片消失，且出现一条"已应用"的改动记录。

### P2 · Agent 活动行**重复两条**
**DOM 实证**：两个各自独立的包裹层（`div.group.relative`，各 70px 高、各 1 个子节点），
内容逐字相同，**没有任何 key/id/data-* 可区分**：
```
Fix security issue: No authentication checks found in codebase
Fix security issue: No authentication checks found in codebase
```
**改法**：查 builder 侧活动记录的去重（同内容相邻条目应合并或去重）。
**判据**：同一活动在同一会话里只出现一次。
> 附注：这条活动本身说明 **agent 自己发现了"代码里没有认证校验"**，而 `AuthContext.login()`
> 确实是桩（任意邮箱+密码即放行）——**报告出来了，修复没进去**（被 P1 拦住）。
