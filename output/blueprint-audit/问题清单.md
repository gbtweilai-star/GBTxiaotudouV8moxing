## 一、查实：**我们框架自己的缺陷**（本任务过程中真跑出来的）

### H1 · api 层手写白名单静默丢掉参数 ✅ 已修
`gbt_allinone/api.py` 的 browser 分支原来只转发 7 个键：
`("act","action","cmd","selector","value","out","headless")`。
**白名单之外的一切参数被静默丢弃且不报错**，调用方只看到引擎报「缺参数」。

实测后果（逐条真跑过）：

| 动作 | 症状 |
|---|---|
| `execute_script` / `inject_script` | 连 `1+1` 都报 `missing 1 required positional argument: 'js'` |
| `type_text` | `text` 被丢 |
| `activate_tab` / `close_tab` | `tab_id` 被丢 |
| `pin_window` | `rect`/`topmost` 被丢（手动置顶落位失效） |
| `dom_query` | `limit` 被丢 ⇒ **永远退回默认 50** |

**讽刺点**：`browser_cap.native()` 的设计注释写着「按**目标动作的真实签名**裁剪」，
**参数根本走不到它那儿就被砍了** —— 设计意图与实现脱节。
**修法**：native 系**全量转发**（只排掉门面自己的键），把裁剪权交还给 `native()`。

**复验**：`execute_script 1+1 → ok=True result=2`；`dom_query limit=3 → 命中 3 条`；
`get_text` 仍可用；非 native 的 `op=status` 仍可用。

### H2 · `click_element` 只发合成 `click`，点了没反应却报成功 ✅ 已修
原实现是 `e.click()`。对挂在 **`pointerdown`/`mousedown`** 上的触发器（Radix 下拉一类）
**完全无效**，却仍返回 `clicked:true`。

现场证据：对 projectaal 的 `Build` 菜单触发器，
`.click()` 前后 `document.querySelectorAll('*').length` **都是 528**、`aria-expanded` **仍是 false** ⇒
典型的「报成功、什么都没干」。

**修法**：**CDP `Input.dispatchMouseEvent`（首选）→ 完整指针事件序列（退路）**。
CDP 走渲染器进程、不经操作系统 ⇒ **天生无视遮挡物**。

**复验（有真实状态变化作证）**：
```
点前 visibleMenuItems = 0
click_element → clicked:true  via:"cdp-input"
点后 visibleMenuItems = 6  →  Build/Plan/Fix/Edit/Clone/Component
```

### H3 · `type_text` 直接改 `e.value`，对 React 受控输入无效却报成功 ✅ 已修
原实现 `e.value = value` + 手工 `input`/`change`。**React 用自己缓存的 value 回写**，
直接赋值会被覆盖或让 value 追踪器失真（看着输进去了、state 没变、提交是空的），
而返回值照样 `typed:true`。

**修法**：**CDP `Input.insertText`（首选）→ 原生 value setter + input 事件（退路）**；
并返回 `value_len_before/after` 作为**页面真实读数**，明确写「`typed` 只说字已发出」。

### H4 · worker 的 `LLM_ENDPOINT` 是个会自己说谎的指示灯 ⛔ 未修（等你拍板）
`deploy/cloud-10/wrangler.toml` 第 47 行写着「要走我们自己的权重，就把 `LLM_ENDPOINT`
指向自建端点（**那时优先走它**）」。
**但代码里没有这个分支**：`worker.js` 里 `LLM_ENDPOINT` 只出现一次 ——

```js
272:  weights_ours: Boolean(e.LLM_ENDPOINT),
```

而真正发请求的地方**无条件**走 Workers AI（321–329 行流式，非流式同理）：
```js
const wid = (body.model && body.model !== "gbt-potato-v8") ? body.model : e.WORKERS_AI_MODEL;
upstream = await e.AI.run(wid, { messages: norm, ... });
```
**后果**：一旦把 `LLM_ENDPOINT` 填上，读数立刻变 `weights_ours: true`（"权重是我们的"），
而流量**照旧烧 Workers AI 的神经元**。

### H5 · `gbt-potato-v8` 当前的 502 = Cloudflare 免费神经元配额用尽（非代码缺陷）
报错：`4006: you have used up your daily free allocation of 10,000 neurons`。
**能吐出 4006 恰恰证明先前的 `5006`（content 数组类型不符）已修好** —— 性质从"真 bug"变成"配额墙"。
恢复：Cloudflare 按 **00:00 UTC** 重置（北京时间约早 08:00）。
另注：`weights_ours: false` ⇒ **它现在不是"我们的模型"**，跑的是 `@cf/openai/gpt-oss-120b`。

**实测（`output/blueprint-audit/p10-tokens.json`）**：

| 判据 | 读数 |
|---|---|
| `:root` 上的 CSS 变量 | `--background` / `--brand` / `--primary` / `--card` … **全部「(未定义)」**（假设的这一半成立） |
