## F7 · `RichTextEditor.tsx` —— **两层**问题，一起修

**问题一（会抛错）**：用了 `DOMPurify`，但预览里没有这个库、也没有 import。
**问题二（React 里互斥）**：同一个元素上既有 `contentEditable` 又有 `dangerouslySetInnerHTML`
⇒ 用户一输入就被 React 的 state 回写覆盖、光标乱跳，行为不可用。

**原文**（L26–L31）：
```tsx
      <div
        contentEditable
        className="min-h-[200px] p-4 outline-none prose prose-sm"
        style={{ fontWeight: isBold ? 'bold' : 'normal', fontStyle: isItalic ? 'italic' : 'normal' }}
        dangerouslySetInnerHTML={{ __html: DOMPurify.sanitize(content) }}
      />
```
**改后（推荐：去掉危险路径 + 去掉互斥写法，改成受控的 contentEditable）**：
```tsx
      <div
        contentEditable
        suppressContentEditableWarning
        className="min-h-[200px] p-4 outline-none prose prose-sm"
        style={{ fontWeight: isBold ? 'bold' : 'normal', fontStyle: isItalic ? 'italic' : 'normal' }}
        onInput={(e) => setContent((e.target as HTMLDivElement).innerHTML)}
      >
        {content}
      </div>
```
**备选（若确实要 `dangerouslySetInnerHTML`）**：必须补 `import DOMPurify from 'dompurify';`
**并把它加进预览的依赖加载表**（srcdoc 目前只加载 tailwindcss / react / react-dom / babel / framer-motion）——
否则依旧是 `ReferenceError`。**二选一，不能只补 import 不改依赖表。**
**判据**：该组件渲染不抛错；输入文字后 state 跟着变。

## 己、本补丁集已过**机器验证**（2026-09-25）

补丁"看着对"和"真能编译"是两件事 —— 所以补丁也过机器，不靠读。

**两个工具**（都可重复跑）：

| `tools/codex-scripts/bp-transpile-check.js` | 用**预览同款 Babel**（`@babel/standalone@7.26.4`）把原件与补丁件各转译一遍 |

### 验证结果（现读）

（覆盖 `.tsx`/`.ts`；`/src/index.css` 是 CSS，不在这一步的口径内。）
施加结果：**8 个文件被改，13 条补丁全部命中。**

### 🔴 施加器为什么要"断言命中"——它当场抓到了一次静默失效
`bp-apply-patches.py` 里每条 `str.replace()` 都**断言命中恰好 1 次**，否则报错退出。
**第一次跑就抓到一处**：

**F7 的补丁原文对不上真实文件 —— 命中 0 次。**
逐字节对照后发现：真实第 26 行是 **`'      <div '`（带一个尾随空格）**，
而补丁写的是 `'      <div\n'`（无空格）。

**⇒ 一个尾随空格就能让"字面补丁"静默什么都不做；没有断言的话，读的人会以为已经改了。**
这与本次排雷一路抓到的是**同一类病**：参数被静默丢弃、`e.click()` 报成功、散文串被当成真调用。

### 剩下的风险（不许念过头）
**编译通过 ≠ 真能跑。** Babel 只剥类型、不做类型检查，也不验证
`ChartDashboard` 在运行时**真的解析得到**（那要有打包器/运行时）。
⇒ **"接上就能出图"这句话，仍必须在真实预览里按各条「判据」复核过才算数。**
