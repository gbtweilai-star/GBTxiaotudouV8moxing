# 触手自动化工作流 V2

开发者：自由的风 · GBT小土豆V8

## V2 新增

- 12 个框架可视化域：指挥、岗位、运行、证据、资源、模型、记忆、安全、长线任务、媒体、主动情报和系统健康。
- 每个岗位明确职级、专业方法、标准交付、能力绑定和岗位红线。
- `long_run_supervisor` 用租约、心跳、检查点、有界重试、安全接管和主人升级保持长线任务可续作。
- 收益循环：机会发现 → 收益假设 → 成本上限 → 长视频生产 → 质量审计 → 主人审批 → 发布归因 → 复盘进化。
- 长视频由 10 岗协作：商业机会、收益策略、事实研究、长篇编剧、分镜导演、视觉制片、声音导演、长片剪辑、独立质审、发布归因。

`revenue_video_blueprint` 提供机器可读策略；真实生成、发布与收益数据仍由外部适配器提供，发布必须由主人授权。

## 已实现交互

职业触手搜索与添加；节点拖动与选中；输出端到输入端连线；拒绝自连、重复连线和环路；
节点名称、指令、模型策略、超时、重试、房间、证据要求编辑；依赖解除；节点复制与删除；
40 步撤销/重做；本机保存；JSON 导入导出；三种模板；缩放与适应画布；预检历史；
暂无运行证据状态；移动端配置抽屉与添加触手抽屉。

预检仅验证结构与声明，不证明操作系统隔离、真实授权或证据真实性。
超时和重试当前是执行契约配置，尚无运行后端消费。
模型策略仅为草稿策略，不表示模型已接入。

## 后端接线契约

1. UI 提交带版本号、幂等键的 DAG 草稿；后端重新校验，不能信任浏览器预检结果。
2. 总控通过统一 run_task 拆分调度，按触手绑定独立房间与模型会话。
3. 事件流以 task_id / node_id / attempt 标识事件；乱序事件不能倒退状态。
4. 节点状态：queued → running → succeeded / failed / timed_out / cancelled；
   待审批使用 waiting_approval，不能自动跳成 succeeded。
5. 失败重试受节点上限、总预算和截止时间约束；成功产物按摘要复用。
6. 独立复核必须核验 checker 与执行者不同；不满足则阻断主人审批。
7. 发布必须由后端消费有效授权，校验回滚点和产物摘要；浏览器不能发卡。
8. 证据面板只展示运行端返回的文件与 trace_store 指针，不生成虚构读数。
