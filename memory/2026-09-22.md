```powershell

py -3.14 -m gbt_allinone.tools.sync_exec open  "这一步要干什么" <要观察的文件...>

# 收步（**必须交证据**；证据不够或带失败字样 ⇒ 判 partial，不许说完成）

# 量自己（brainless_ratio 量的是框架侧；agent_* 才是量"我"）
py -3.14 -m gbt_allinone.tools.sync_exec ruler

# 走真链（耳→route→execute→verify→health→嘴）
py -3.14 -m gbt_allinone.tools.sync_exec run   "目标" <要观察的文件...>
```

**规矩**：直接调工具/函数 = 例外，**必须说出为什么不走这条路**。说不出理由的直接调用 = 违规。

**钉子**（谁删了机制它就红）：

## 🔴 事故 + 修复：换代清理把整页插件打挂了（兼容壳救回）

**现象**：主人发的 `desktop_control` 到手后，我按 F5 刷新 → 页面变成红字错页
`Failed to import loader entry … (gbt-potato-master-v6)`，**整个 Web 端插件全挂**（侧栏、会话全没了）。

**根因**：DSH 模块加载器把 **package metadata 按 Loader specifier 缓存到进程重启**
（`dsh-client-modules` README 原文 "cached per Loader specifier … **until restart**"）。
我做过"换代 = 换包名 + 删掉上一代包"，于是缓存里**仍指着已删的 `gbt-potato-master-v6`** ⇒ import 失败 ⇒ 整页插件加载一起失败。

**修法（已验证）**：放一个**同名同路径**的兼容壳包
`plugins/gbt-master-compat-v6`（`name: gbt-potato-master-v6`，host/client 两半都**故意空转**，
client 只把该 id 注册成无副作用空壳），`dsh plugin --profile web add file:` 装到
`~/.dsh/profiles/web/node_modules/gbt-potato-master-v6` —— 正是缓存里记的那个解析路径。
再按一次 F5 ⇒ **页面恢复**（截图：侧栏、会话、我们的两个头部入口都在）。

**纪律（写死）**：**换代清理前必须先重启 DSH，或者保留一个兼容壳包**；
"删掉上一代"这个动作本身会把还活着的进程打挂。**这条比"部署后清理律"优先级更高**——
清理律的前提是"不影响还活着的进程"。

### 第三十八轮补记：**顺着"偶发超时"挖到一个真性能故障（目录路由 N+1 顺序等待）**

收尾复跑时，`check-panel-syntax --all` 与 `verify-index-panel` **偶发**报"取不到面板目录 / 超时"。

```

```

⇒ **不是负载，是稳定的慢**（4.8 KB 的 JSON 每次 8–10 秒）。

**根因**（宿主 `catalog()`）：对 12 个面板**逐个 `await statOf()`**（每个又是 `resolve`+`stat` 两次往返），
再加一次 `fs.listDir(await fs.resolve(render/))` ⇒ **26 次 `fs` 服务顺序 await**。
后果：总索引台账 / 能力球现读对齐都要等它，**验收器前置取数偶发超时**（正是它把这条暴露出来的）。

**修法**：这些 stat 彼此独立 ⇒ 一次 `Promise.all` 并发（renders 计数并进去），N 个来回压成一个。
**A/B 实测**（同一支门 / 同一 600 ms 打桩延迟 / 同样 54 次调用）：

| | 耗时 | 结论 |
|---|---|---|
| 改前（装机副本 = 现役运行代码） | **15,716 ms** | 🔴 顺序 exit 1 |
| 改后（源稿） | **1,211 ms** | ✅ 并行 exit 0 |

**新门** `plugins/gbt-master/tools/verify-catalog-latency.mjs`：把 `fs` 打桩成固定延迟，
跑**真实的路由处理器**，断言 `elapsed < 4×延迟`（顺序≈13×、并行≈1×，阈值离两头都远）；
可指向任意 host.js 做改前/改后对照。README §4.12 记全。

⚠️ **生效时机**：宿主半边是**进程启动时装载**的 ⇒ 提速要**下次 DSH 重启**才落到正在跑的进程；
装机副本已同步，重启后即时生效。

**教训**：验收器报"超时/取不到"时**先怀疑门**是对的，但**不能停在门这一步** ——
把"偶发"当"抖动"放过，就会漏掉一个**稳定慢 10 倍**的真故障（它只是恰好只在重负载下越过超时线）。

### 一、`check-panel-syntax.py` 对 `type="importmap"` 从来没验过

原来对 importmap 走 `continue`（`node --check` 查不了 JSON），**跳过之后就再没验过**。
而 importmap 在本项目是**载荷声明**（three.js 解析全靠它），坏了的表现是**白屏** ——
正是这道门存在的理由（宿主目录里 `exists=true`、`size` 正常，看目录看不出来）。

| 夹具 | 旧行为 | 现在 |
|---|---|---|
| importmap JSON 坏（尾逗号） | ✅「通过」（**假绿**） | 🔴 不是合法 JSON |
| importmap `imports` 不是对象 | ✅「通过」 | 🔴 `imports` 不是对象（是 str） |
| importmap 顶层不是对象 | ✅「通过」 | 🔴 顶层不是对象（是 list） |
| 内联 JS 语法错 | 🔴 正确报错 | 🔴 不变 |
| 干净页（正对照） | ✅ | ✅ 不变 |

**现读有没有真面板中招**：**没有**。12 面板 + `avatar.html` 全量扫过，只有 `index.html` 与
