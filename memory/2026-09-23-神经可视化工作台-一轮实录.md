### `tools/codex-scripts/audit_skin.py`：「别混皮肤」从口头变成读数

- **准用集现算**：`window.css` + `deck3d.css` + 任何 `skin-*.css` 的 `:root`（约定：专业皮肤必须以 `skin-` 开头并在文件头写明出处）
- **禁用集现算**：从退役的 `holo_pet/styles.css` 现读高频色 + 14 个 AI 指纹色
- **它抓到的真东西**：
  · 新壳自己的 `shell/blocked.html` / `connect.html` **各带一整套另一套配色**（42 处）→ 已改
  · **我自己写的** `brain.js` 两处"更亮一点的青"（`0xb4faff`/`0x9beaff`）→ 亮度改走加法混合，不加色号
- **修掉器自己的两个洞**（都是首跑暴露的）：
  · JS 的 `0xRRGGBB` 数字色**扫不到** ⇒ 换掉品牌色会报"干净"（**假绿**）
  · **注释被当代码扫** ⇒ 在 HTML/CSS/JS 注释里写"这里原来是什么色"会永远报红 ⇒
    **人会选择不记录历史**，那比色号混入更贵。三种注释都要剥。
- 终态：**零混入 · 旧皮肤 0 · AI 指纹 0**；准用集 15 色（品牌/3D 层 10 + mission-control 表面 5）

## 2. 数据面：连接**从源码算**，不画假线

`tools/codex-scripts/brain-feed.py`（唯一出口）：

| 层 | 真出处 | 现读 |
|---|---|---|
| 束长环 | `caps_registry` 的 `domain` 字段 | **29 个真实能力域**（**不是**参考稿编的 22） |
| 触手层 | `caps_registry` 每一个能力位 | **150 实现 + 11 仅登记**（参考稿编的是 186） |
| 技能雾 | `state/skill_atlas.json` | 341 条 |
| 门禁环 | `security/policy.py` | 14 个作用域 |
| **能力位之间的连接** | `handler` 字段 → AST 找定义文件 → AST 取真实 import | **108 条真边** |
| 执行脉冲 | `audit.jsonl` 的 `call` 事件 | 90 条（近 6h 内 90） |

### 连接的取法（试了两版才对）

1. **第一版**：按 `handler` 找同名函数 → **只有 11/150 命中**。因为多数能力位不是独立函数。
2. **第二版（正解）**：AST 解析 `api.py` 的 `_run_benign` —— 那里有 **143 处 `kind ==` 比较**，
   那才是**真实分派结构**。每条支路里 `import` 了什么模块 + 调了哪个顶层函数 = 它的真实依赖面。
3. **噪音边必须滤**：第一版跑出来 1500 条边**全是** `api.py → __init__.py` ⇒
   每个能力位连到每个能力位，**满屏线但零信息**。滤掉包初始化与 `api.py` 自身之后剩 108 条，
   每条都能回查：`health --(security_brain.py)--> sec_scan`。

### 一条性能坑

`gbt_allinone/` 底下挂着 `store/native_browser/profile/`（浏览器 profile，上万个文件）——
不剪枝的话 AST 全盘扫**跑到超时**，数据面直接卡死。**这是"能不能产出"的问题，不是优化。**

## 4. 四个"只有真跑才能发现"的 bug

`tools/codex-scripts/render_page.py`（本轮升级：WebGL + 控制台 + **失败请求** + **stack**）逐个抓出来：

| # | 症状 | 真因 |
|---|---|---|
| 1 | 页面**静默空白**、左栏停在"读数据中…" | **`file://` 下 `<script type="module">` 被 CORS 挡死**（`net::ERR_FAILED`）。壳的 `main.cjs` 没关 `webSecurity` ⇒ **壳里也一样跑不起来**。⇒ three 转经典脚本 |
| 2 | 4 次 `Class extends value undefined` + `ShaderPass is not a constructor` | 后处理链全都 `extends Pass`，而 **`Pass.js` 住在自己的文件里**，漏 vendor 了 |
| 3 | `reading 'x'` | 顶点数与颜色数**差一**：一条曲线 `seg` 段 = `seg×2` 顶点，我按 `(seg+1)×2` 推颜色 |
| 4 | 同一条错，换行号再报 | `getPoints(seg, optionalTarget)` **这个版本不往传入数组里填** ⇒ 别赌签名，吃返回值 |

外加两个 CSP 真限制（不是 bug，是纪律）：
- **`el.style.left=` 被 `style-src 'self'` 挡**（实测报 6 次）⇒ 浮动 tooltip 改成**固定读数条**
- **内联 `style=` 属性同样被挡** ⇒ 图例色块改 class

**这三条合起来解释了为什么"可拖拽"放在 WebGL 里做**：拖三维节点只是改 `position`，
一行内联样式都不用；拖 DOM 面板则必须动 `style`，当场被 CSP 挡。

## 5. 旧页面清理（**风哥说了三次，本轮真做**）

判据定死为「**被超越**」，不是「看着旧」：

| 档 | 判据 |
|---|---|
| `archive/V<n> X.html` | 仓根存在**同后缀的更高版**（V22）才算被超越；找不到更高版 ⇒ **留着**（不靠猜删历史） |
| 生成镜像 | 工具生成 + `.gitignore` 已列 ⇒ 可重建（`.shadow-repo/` 生成器在盘上） |
| 临时/备份页 | 显式清单，逐条写理由 |

**三条护栏**：现行版永不搬 · `referenced_names()` 命中就不搬（宁多留）· 不碰别人的页面（`_upstream`/`vendor`/`gbt_allinone`/`审美相关skill`）。

**顺手修了守卫自己的一个真窟窿**：引用底账的正则**不含空格** ⇒
`archive/V21 GBT小土豆V8-可交互原型.html` 这种**带空格的中文页名，守卫一个字都匹配不到**
—— 而本仓最要紧的那批交付页全是这个形状。加上空格后底账从 9146 → **10042** 个文件名。

**结果**：**48 项 / 227 MB 进回收站**；仓内 HTML 从 **810 个 / 56.5 MB → 565 个 / 15.9 MB**。
`.shadow-repo/`（190 MB · 206 页）· `archive/` V1–V21（42 页）· `.openclaw/tmp` · `.scratch` 旧版 ·
`outputs/*/archive` · `holo_pet/archive`。**现行 V22 双交付页、新壳、capabilities.html 全部在**（已复核）。

### 8.2 窗 1 / 5 / 6 全部接上专业皮肤（**不改 window.css 一行**）

做法：在 `skin-mission-control.css` 里加一层**语义 token 映射**
（`--gbt-bg/--gbt-panel/--gbt-line/--gbt-radius` → MC 的值），靠**加载顺序**生效。
⇒ **一处映射，三个窗全变**；反过来（去 window.css 逐条改规则）就是把同一个决定写两遍。

顺带修掉一个**真缺陷**：`--gbt-bg` 原本是 `rgba(5,7,17,.74)`（**74% 透明**）⇒
整扇窗的观感**取决于桌面壁纸**，白底下发灰。MC §1 原话正好对上：任务控制是低光环境，
面板要"3 米外、18 小时没睡的人也读得清"—— 依赖壁纸的窗做不到。改成不透明。

### 8.3 【又一次认错】窗 6 的"2 条失败请求"不是 bug

渲染取证器报窗 6 首屏 2 条失败请求，我当场说"抓出真 bug"。**查证后：报早了。**
`h1.js` 是**设计好的三层兜底**（preload IPC → 同源 `/api/h1` → 回环 `127.0.0.1:8765/api/h1`），
注释写得很清楚，而且那个端点**真存在**（`HTTP 200`，真 JSON）。
`/api/h1` 在 `file://` 下失败是**它的前提不成立**；回环那条是取证器**禁网**挡的。

**但确有一处真改进**：`file://` 下同源那条**永远不可能成立**，却每次开窗白跑一趟 + 打红字。
⇒ 加**前提短路** `SAME_ORIGIN_POSSIBLE = /^https?:$/.test(location.protocol)`，
判据写在**代码里**而不是注释里（前提是可机检的事实，不是给人读的心得）。
读数：失败请求 **2 → 1** · 控制台 **3 → 1**。
