## 二 · 🔴 实测踩到的坑（下次直接用）

**`webServer.register({ kind:'prefix', path:'/x/' })` 带尾斜杠 = 永远匹配不上。**

DSH 源码 `dsh-host-webserver/lib/index.js` 的匹配规则是：

```js
if (pathname !== prefix && !pathname.startsWith(`${prefix}/`)) continue
```

所以注册 `/gbt-master/fs/` 时，它要求 `pathname` 以 `/gbt-master/fs//` 开头 —— 永远不成立，
请求全部落到 SPA 兜底，**回 404 且响应体为空**（不是 401，别再往权限上查）。
**正确写法：前缀不带尾斜杠（`/gbt-master`），在 handler 里自己按 `/gbt-master/fs/` 切。**

排查要点：404 **响应体为空** = 不是你的 handler 答的（你的 404 一定带自己的文案）。

## 七 · 持久化（2026-09-22 落成 · 一等公民包）

**动态版只是原型；持久版是 `plugins/gbt-master/`（正式包）+ web profile 挂载：**

```
包        <工作区>/plugins/gbt-master/{package.json, lib/host.js, lib/client.js, README.md}
安装      dsh plugin --profile web add "link:<工作区>/plugins/gbt-master"   ← link: 不是 file:
挂载      ~/.dsh/profiles/web/cordis.patch.yml 里 - insert: [{id: gbt-master, name: 'gbt-master', config:{workspace: ...}}]
备份      ~/.dsh/profiles/web/.gbt-backup/{package.json.bak, cordis.patch.yml.bak}
```

**三条实测结论（下次直接用）：**

1. **profile 是 `patchReload: live`** —— 改 `cordis.patch.yml` 会热重组：加行即装载、`disabled: true` 即卸载，秒级生效，**不需要重启**。
2. **但插件代码不会热更新**：DSH 把每个 specifier 的包元数据**缓存到进程重启为止**；
   实测过换入口文件（index.js → host.js）也不重新 import。⇒ **首次挂载后要重启一次 `dsh web`**，之后每次开机自动加载。
3. **`file:` 装出来是硬链接**（`node_modules/gbt-master/lib/index.js` 是 HardLink 到工作区），
   `import.meta.url` 落在 profile 里 ⇒ 按路径推工作区会推成 `profiles/web`（实测 present=0）。
   改用 **`link:`** 安装后 `node_modules/gbt-master` 是 SymbolicLink，realpath 指回工作区（实测解析正确）；
   工作区根同时由组合行 `config.workspace` 显式声明，双保险。

**浏览器半边的真契约**（读 `dsh-client-ui-brand-official` 实证，不是推测）：
必须是**已构建**的 bundle，形态为 `window.__ModuleLoader__.load({ id, factory: (require) => {...} })`，
`factory` 里 `require("react")`（React 在平台基座表里，`dsh-client-ui-*` 都这么用），导出 `{ apply, inject }`；
`package.json` 声明 `dsh.client = { inject: [...], platform: "web" }` 与 `exports["./client"]`。

## 八 · 补记（同日 · 做到"不重启、无缺口"）

Owner 追了一句「要做到真正的持久化不能重启有缺失啊」，于是把缺口补掉。四条新结论：

1. **换代码 = 换 specifier**。DSH 按 specifier 缓存包元数据到进程重启为止；实测换入口文件、disable→enable 都不重新 import。
   唯一不重启就换代的办法：**改包名**（本包 `gbt-master` → **`gbt-potato-master`**），行重建后当场重新解析装载。
   ⚠️ 子路径 specifier（`gbt-master/host`）**不行**：行直接不激活。⚠️ 改名会**残留旧 id 的浏览器名册条目**（对账只认当前 entry 名），
   所以在 bundle 顶部给旧 id 注册一个**无副作用空壳**，页面不会报"找不到模块"。
2. **安装要用 `file:` 不能用 `link:`**。浏览器名册只扫 profile 树内的包：`link:` 把真身指到树外 ⇒ 名册里没有这一条。
   `file:` 落进 `node_modules/`（硬链接）⇒ 名册认，但 `import.meta.url` 落在 profile 里 ⇒ **工作区根必须由组合行 `config.workspace` 显式声明**。
3. **bundle 探测形状是 combo URL**：`/plugins/??<id>/client.js&rev=<rev>`。直接探 `/plugins/<id>/client.js` 回 404，会误判成"没供"（我误判过一次）。
   查名册的可靠办法：宿主侧读 `ctx.clientModules.graph()` / `clientPath(id)`（本轮用一个只读诊断包取证，见 `.scratch/_gbt_boot_graph.json` 的历史）。
4. **服务端零重启 ≠ 浏览器零刷新**。客户端模块随页面引导载荷入册，已开页面不会凭空多出插件；
   `dsh-client-hmr` 只管"已存在模块被重建"，管不了"新模块首次入册"。⇒ **服务端零重启 + 浏览器 F5 一次**，此后开机自动挂载。

**右上角入口的落点（读插槽契约定的，不是猜）**：
`conversation.session.header.corner` 是 **single 且已被官方控件占住**（占它会顶掉人家）⇒ 不能装；
`conversation.session.header.utilities` 是**追加式 list**（现挂 open-in-app / session-log-download）⇒
上帝视角入口装在最右（`id: gbt-godview, order: 20`），点开独立窗口拉起 W3 六页签驾驶舱。

| 自愈器本体 | `GET /gbt-master/heal.js` | **HTTP 200 · 3,001 B · 含 `setInterval`**（世代对比 + 60s 复查） |
| 本代 bundle 有没有入册 | 读渲染出的 `__DSH_BOOT__.entries` | **含 `gbt-potato-master-v9`** ✅ |
| bundle 真供不供得出来 | `GET /plugins/??gbt-potato-master-v9/client.js&rev=…` | **HTTP 200 · 17,173 B**，含 `dataset.gbtGen`(1) · `/gbt-master/diag`(3) · `sidebar.brand.mark`(2) · `sidebar.brand.name`(2) |
| 索引注入清单 | `webServer.collectIndexInjections()` | 6 条（loader 脚本 / preload / script-src / `__DSH_BOOT__` / 主题脚本 / 连接恢复） |

**结论**：缺的**只有一次页面重载**（F5）。重载后本代 bundle 会跑 `apply()` → 打上 `dataset.gbtGen=v9`、
发出 `POST /gbt-master/diag`，`/gbt-master` 的 `clientDiag` 由 `null` 变成带 `gen` 的对象 —— 那一刻才算"已生效"。
此后由 `heal.js`（60s 间隔）负责，**换代不再需要人按 F5**。

**同轮修掉的一处报告层假绿（宿主半边，`lib/host.js`）**：注入给每一轮会话的上下文里，
原来**写死**一句"左栏品牌行＝土豆 Logo + GBT小土豆V8"。那是"部署就绪"被讲成了"已生效" ——
**每一轮重启的模型都被这句话带偏**。现改成按 payload 里的 `clientDiag` 分三种说法：
① `null` → "部署就绪、尚未在任何页面生效（需要一次 F5）"；② `gen === gbt-potato-master-v9` → "该页已按本代加载（附诊断时间）"；
③ 收到过诊断但 gen 不符 → "诊断里的 gen 与本代不符（那张页面是别的世代）"。
三分支都用真函数抽出来跑过（语法 `node --check` 通过）。
⚠️ **生效时机**：宿主半边在 DSH 进程启动时装载，所以这段修正**下次 DSH 重启才生效**（不是热更新）。
