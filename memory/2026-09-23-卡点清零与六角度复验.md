### 🔴 补的过程中复核出来的一条关键判据：**门是 fail-closed，不按 op 白名单判**

```
policy.evaluate("code_patch", {})                 → []                    （默认 dry_run，免卡）
policy.evaluate("code_patch", {"op": "apply"})    → ['filesystem_write']
policy.evaluate("code_patch", {"op": "nope"})     → ['filesystem_write']  ← **未知 op 也要卡**
policy.evaluate("git_write",  {"op": "nope"})     → ['filesystem_write']  ← 同上
policy.evaluate("git_read",   {"op": "nope"})     → []                    ← 只读面，未知 op 也不卡
```

**别读成"零作用域所以只读"**：`code_patch` 空参求值确实是 `[]`，但那是**默认走 dry_run**。
门的判据是「**非 dry_run**」，不是「op 在白名单里」——
后者一旦漏写一个新 op 就是白送一次写盘，前者漏不掉。

**未验账照实写**（`honest_unverified_marks` 14 处）：真 apply 一次 / rollback 一次 /
`git_read` 其余 5 个 op 逐个真跑 / `git_write` commit 的「不动索引里别的暂存内容」——**一律未验**，
卡在哪都写清了。
