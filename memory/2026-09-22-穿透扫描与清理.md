## 二、接上了什么（**7 个真断点**，全部实测抓出、全部修掉）

| # | 断点 | 根因 | 修法 + 证据 |
|---|---|---|---|
| 1 | **宿主 JSON 被截断** | `sendJson` 的 `content-length` 报的是 **JS 字符串字符数**，不是 UTF-8 字节数。中文一多，头小于身 ⇒ 严格客户端按头截断 | 改按 `Buffer.byteLength(body,'utf8')` 报头。**证据**：修前 curl 落盘 3415 B 而真身 4671 B（`Unterminated string`）；修后头 4671 = 真字节 4671 |
| 2 | **两个面板点不到** | 登记表 **9** 条，盘上 **11** 条 —— 「赏金台 h1」「大脑执行层 brain」只在文件里 | 补进登记表 + 换代上线。**证据**：现役 12 条，h1/brain 各 http=200 + 渲染 err=0 |
| 3 | **数字人成品页打不开** | `avatar.html`（数字人主线成品）从未进登记表 | 补为第 07 条。**证据**：http=200 · 渲染 err=0 · canvas 出画面 |
| 4 | **主控台 3D 形象 404** | `local-avatar-3d.js` 指向 `assets/digital-human/tripo-human.glb`，而**该文件全树不存在**（资产已整理进 `raw/` 分层）⇒ `localAvatar3d="failed"` | 改指 `raw/rig/model-rigged-anim.glb`（3.37 MB · 22 骨 · idle 8.0s/walk 1.10s）。**证据**：3D=ready，页面文本从"加载失败"恢复成完整 UI |
| 5 | **总索引页自述不诚实** | 顶部台账人工写死（PANELS 10 / RENDERS 26 / PAYLOAD 1,726 KB），页面却自称"与登记表同源" | 改为**打开即同源现读** `/gbt-master`：台账、每张卡片字节数、在/缺 chip、每节张数全部按当次真值填；取不到就显示「取不到」+ 原因。**证据**：页面文本现为 `PANELS 12 RENDERS 67` |
| 6 | **每页一条 404 红字** | 4 个面板页没声明 `rel="icon"` ⇒ 浏览器自动请求 `/favicon.ico` 落空 | 补内联 `data:` icon（不依赖路径，CSP `img-src data:` 放行）。**证据**：12 页 icon 全 True，index/pet/avatar 控制台错 1→0 |

## 三、换代码为什么不重启就能生效（读官方原文定的，不是猜）

`@deepseek-ai/dsh-client-modules/README.md` 原文：

> 「Package metadata is cached per Loader specifier and owning-tree base URL **until restart**,
> while the resolved **manifest package name** identifies the browser module.」

⇒ **同 specifier 改源码不会重新 import**（换入口文件、`disabled:true`→再启用都实测无效）。
唯一不重启换代 = **换包名 / 换组合行 name**。本包本轮走过四代：

```
gbt-potato-master → -v2 → -v3 → gbt-potato-master-v4（现役，v1.3.0）
```

旧 id 在 bundle 顶部用 `__gbtStub('<旧id>')` 留**无副作用空壳**（页面不报"找不到模块"），
**重启后随名册重算自然消失** —— 这是唯一该留的兼容壳。

### 写盘机制（我在同一处连踩三次才吃透 · 这是 Owner 第二条指令的由来）

**`file:` 安装 = 硬链接：工作区的包文件与 profile 里那份是同一个 inode（同一个文件）。**
`fsutil hardlink list` 实证：`plugins/gbt-master/lib/host.js` 与
`profiles/web/node_modules/gbt-potato-master-v4/lib/host.js` 是**两条路径、一个文件**。

⇒ **正确次序**：先把源码全部改完 → **最后只跑一次** `dsh plugin … add`（只为登记新 specifier 名，
内容根本不用同步）→ 换组合行 `name` → `remove` 上一世代。
⇒ **我的反例**：编辑一次就跑一次 `pnpm add` ⇒ pnpm 重新物化包、同一 inode 的 mtime 被改写 ⇒
编辑器随后报「file changed since it was read」。**那不是文件被别人改了，是我自己踩的。**

## 五、我自己犯的错（留证，免得下次重犯）

扫描器第一版**把好的东西误报成断点**，还把**真实的副作用打出去了**。三条是我的错，不是仓里的错：

1. **路径不编码 ⇒ 把 4 个活面板判成"路由断了"**：`V22 GBT小土豆V8-可交互原型.html` 带中文+空格，
   urllib 直接拒（`InvalidURL`）⇒ 报 `http=None`。按段 `urllib.parse.quote` 才对。
2. **探 SSE 漏了 `/gbt-master` 前缀 ⇒ 打到 DSH 自己的网关（401）**，被我写成"事件流断了"。
   真路由 `/gbt-master/api/events` = **200 `text/event-stream`**。
3. **一律用 GET 探 ⇒ 把 POST 路由全误报 404**（`/api/social`、`/api/research`…）。
   必须按对方**声明的** method 探（现读 `APP_SURFACE`）。
4. **🔴 探针把真实副作用打出去了**：第一版拿 `{}` 把 26 条路由**全打一遍**，其中
   `/api/new-thread` **真开了新线程**、`/api/bluetooth` **真受理了**、`/api/interrupt` **真打断了回合**。
   违反仓里《零副作用铁律》。**改后**：只读（GET）才真打；会改状态的一律**静态对账**
   （路由表 ⇔ 源码 `parsed.path ==`）；端到端只留**一条**零副作用动态钉子。
5. **探针查错了位**：画面自证我读 `body.dataset.painted`（恒 null），而形象页声明的是
   `window.__painted`/`__spread`。⇒ **改探针去读页面自己声明的契约，不是改页面迁就探针。**
6. **写盘次序错**（见第三节）：编辑一次就跑一次 `pnpm add`，导致同一 inode 被反复改写、
   编辑器连续报"读过之后又变了"。**先把源码改完，最后只装一次。**

**教训两句话**：
- `None` / `null` 的读数**先怀疑探针**，再怀疑被测对象 —— 否则就是在给好的东西扣帽子。
- **诊断工具本身也会伤到被测系统**：探针要么只读，要么先证明它零副作用，再打。
