## 一、为什么要这一件：**没有一格会去动一下窗**

| 已有的器 | 它做什么 | 为什么照不到这一格 |
|---|---|---|
| `preflight.cjs` | 验模块与注册表 | **刻意不启动**（启动会在主人屏幕上开窗） |
| `rehearse.cjs` | 逐窗建 BrowserWindow 验载入 | 只验"载不载得起来"，**不动窗** |
| `shots.cjs` | 每扇窗拍真图 | 只拍，**不动窗** |

⇒ 「单例锁 / 托盘 / 挪窗落盘 / 吸附」这四件事，**只有真引导链 + 真动手**才照得到。

### 做法：不另写一条链，让**真链自己跑一遍**

`GBT_W3_STARTUP_PROBE=1` **只改 `createWindow` 里两个字段**（屏幕外 + 不显示），
引导链**一个环节都不跳**：单例锁 → `registerIpc` → `startSse` → 建窗 → `buildTray` → `refreshTrayMenu` → 布局落盘。

`startup.cjs` `require("./main.cjs")` ⇒ 它的 `whenReady` 回调比预演器**先注册**，
所以真引导先跑；预演器再等一拍去**观察效果**（全是公开 API 上的效果，不读内部变量）：

| 格 | 看什么 |
|---|---|
| `S:lock` | 单例锁拿到了吗（拿不到 main.cjs 自己 quit ⇒ 一个窗都不会有） |
| `S:windows` | 建了几扇（`BrowserWindow.getAllWindows()`） |
| `S:loaded` | 每扇都载到 `file://` 且已停止载入 |
| `S:tray` | **托盘图标真构造一次**（它失败会让 `startSse` 永远不跑且无声） |
| `S:layout` | **主动挪一下窗**，看布局文件会不会被重写 |
| `S:noreport` | 引导期有没有 `[w3] … 失败` 留痕 |

## 二 🔴、抓到的真缺陷：`moved` 在 Windows 上是死代码

`S:layout` 判红：**挪了一次窗，布局文件没被重写**。查下去：

```
main.cjs:  win.on("moved", () => { …吸附对齐… saveWindowState(); });
Electron 文档对 BrowserWindow 的 `moved` 事件原文：**"macOS only"**
本机：Windows 11
```

⇒ 这段（**吸附对齐 + 挪窗后落盘**）**在本机从来没跑过**。
位置只在 `resized` / `close` 时才会被保存。

**修法**：抽出 `onMoved()`，两个事件都接上 ——
`moved`（macOS）+ `move`（Windows/Linux 全平台）。
`move` 在拖动期间**连续**触发，所以做 **220ms 防抖**：每次拖动都跑一遍吸附 + 写盘会白烧磁盘。
`closed` 时清掉定时器。

**复验**：`✅ S:layout PASS 动一次窗 ⇒ window-layout.json 真的被重写`，
整器 **PASS 7 · FAIL 0 · exit 0**。

## 三、探针自己犯的三次错（**每次都报成"产品缺陷"**）

这一节必须写下来 —— 三轮调试里，**红全是探针自己的**：

| # | 症状 | 真因 |
|---|---|---|
| 1 | `S:tray FAIL 托盘图标构造抛了：M is not defined` | 我把 `M` 写成了 `main()` 的局部变量，`whenReady` 回调里根本看不到 ⇒ **"探针抛了"被报成"托盘坏了"** |
| 2 | `S:tray FAIL … reading '0'` | `trayIcon(size, fill, edge)` 是**三参**，我只传了 `size` ⇒ `fill[0]` 抛 |
| 3 | `S:layout FAIL 动了一次窗，持久化这条线断了` | ① 第一版我在 `setBounds` 之后**同步**比 mtime，而 `moved` 是**异步**事件；② 改成等 700ms 后**仍然红** —— 那一次才是**真缺陷** |

**教训**：新写的量具，**头几次判红先怀疑量具**。
判断方法不是猜，是**看错误信息指哪儿** —— 第 1、2 次的错都在探针自己那几行上。
