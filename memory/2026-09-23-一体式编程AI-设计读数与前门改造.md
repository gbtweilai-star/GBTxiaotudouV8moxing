## 一 🔴、先看再动：**差点拿假读数下设计结论**

我第一版用 `render_page.py`（裸 Chromium）渲主窗，看到**四个大格全写「取不到：没有接上宿主进程（gbtw3 未注入）」**，
差点得出"主窗是空的、框架设计失败"的结论。

**查了一下才明白**：`window.js:19` 读的是 `window.gbtW3` —— 那是 `preload.cjs` 经
`contextBridge` 注入的，**裸浏览器里当然没有**。页面走的是 `noBridge()` 优雅降级，
提示文案还把小写 `gbtw3` 写进了字符串（名字本身是对的）。

⇒ **看窗必须用真壳看。** 而这件事**从来没有机检过** —— `rehearse.cjs` 的 docstring
自己写着：「不验：**窗口长什么样**（要真显示）」。

### `shell/shots.cjs`：真壳取证器（补的就是这一格）

- 按 `windows.json` 逐扇建 BrowserWindow，用与 `main.cjs` **同一套 webPreferences**；
- 🔴 **`show: true` + 屏幕外**（`x = -20000`），**不是** `show: false` ——
  隐藏窗口在 Windows 上**不绘制**，`capturePage()` 会拿到**空白帧**，
  而空白帧和"这扇窗本来就是空的"**长得一模一样**，正是最容易误判的那种假读数；
- 🔴 **空白帧自检**：抽样看像素，整幅只有 ≤3 种颜色就标 `BLANK`。
  —— 量具必须能测出"我这次没量到东西"；
- 🔴 **复用真壳接线**：`GBT_W3_WIRE_ONLY=1` 让 `main.cjs` **只接线、不开窗**
  （新增一个分支，不设变量时行为一个字节不动）。
  **首跑就踩到**：我一开始只挂了 preload、没接主进程那一半，页面对宿主喊
  `w3:eigenflux` / `w3:h1`，主机回 `No handler registered` —— **截出来是"半个宿主"的样子**，
  照着那份图做设计判断就是拿假读数下结论。⇒ 一处接线，两个消费者。

## 二、设计读数：主窗的四坨 JSON

真壳拍出来的主窗是这样的（`%TEMP%\gbt-shots2\godview.png`）：

- 四格各一个 `<pre class="gbt-json">`，把 `payload.data` 整个 `JSON.stringify(…, null, 2)` 铺在屏上；
- **明文带本机绝对路径**：`C:\Users\ADMIN\AppData\Local\Programs\OpenAI\Codex\bin\codex.exe`；
- 服务表把 `host: "127.0.0.1"` / `port` 一起铺出来；
- 层级、状态色、扫读性：**一样都没有**。

本仓 `AGENTS.md` 明写「**不要暴露内部地址、端口、配置**」。⇒ 这既是设计问题，也是暴露面问题。

## 三、改造：四格 → 控制台

| 格 | 改前 | 改后 |
|---|---|---|
| **看自己** | 整份 state JSON | 瓦片带（子系统/正常/故障/无读数）+ 子系统表（状态点 + 读数），**路径掩码 `…\Codex\bin\codex.exe`** |
| **看任务** | 整份 tasks JSON | 瓦片带（总数/已达标/未达标/待升级）+ 任务表（ID/任务/类型/状态点/尝试） |
| **看环境** | 整份 env JSON | 瓦片带（受管服务/在线/离线/监听面）+ 服务表，**`host` 一列故意不上屏** |
| **看账本** | 整份 ledger JSON | 瓦片带（条数/种类/最多/来源）+ 遥测时间线（时间·事件·kind） |

三条纪律写进了代码：

1. **颜色只编码状态**（绿=好 / 黄=降级 / 红=故障 / 灰=没数据），不做装饰 —— 全部走既有令牌，
   机检 `audit_skin.py` **零混入**；
2. **灰 = 不知道**，绝不许渲染成绿（沿用本文件 §3 假绿铁律）。`stateOfValue()` 读不出状态就返回灰；
3. **`{}` 不是"一切正常"** —— `w3State()` / `w3Env()` 是**缓存驱动**的，冷启动实测**合法地返回 `{}`**
   （形状探针量的，不是猜的）⇒ 页面如实显示「宿主数据面还没回值（缓存驱动，等下一次刷新）」。

顺手删掉死代码：`put(el, payload, pretty)` 四视图改完之后**一个调用点都不剩**。
（`.gbt-json` 样式**保留** —— 驾驶舱与侧栏两处还在用。）

## 四、抓到的两处真缺陷

### 缺陷 1 🔴 打包白名单漏了**一整扇窗**

`package.json` 的 `files` 里有 `brain/` `code-deck/` `exec-deck/` `eigenflux/` `h1/`，
**没有 `eye/`** —— 第 30 轮加了第 8 扇窗，漏了打包白名单。
⇒ 打出来的包里**整整少一扇窗**，而预检当时**全绿**。

根因：`K:globs` 验的是「**每条** files 规则匹配得到实物」，**方向是反的** ——
它验不出「**有扇窗没被任何规则覆盖**」。

修法：新增 `K:winfiles`（预检 **13 → 14** 项），**从窗口注册表出发逐扇问**；
判据抽在 `shell/pack-coverage.cjs`，**预检与回归测试共用同一份**（复制必然漂）。

### 缺陷 2 🔴 **我自己的判据太松，被负对照当场抓住**

第一版判据照抄了 `K:globs` 的 `r.test(f) || r.test(path.basename(f))`。
负对照（拿掉 `eye` 规则，必须报得出 `eye`）**判红** —— 因为 `*.html` 命中了 basename `index.html`
⇒ 判据**一律判绿**。而 electron-builder 的 `files` 是**按相对路径**匹配的（`*.html` 只管根层）。

⇒ 去掉按文件名回退。**这就是《扫描器自证律》的用处**：
不带负对照的话，这格门会一直是绿的，而且没人看得出来。

**新增回归** `tests/test_pack_windows.cjs`（6 项，含正负对照）：壳测试 **37 → 43**。

## 六、下一步（还没做完的，留给下一轮）

按读数，剩下的三处硬缺口：

1. **数据机制不统一** —— 8 扇窗现在有**五种**取数方式：godview 走 IPC 实时、
   exec-deck/code-deck 是**静态快照**（页上写着"重生成命令"）、brain 是**生成的数据文件**、
   eye 是**文件轮询**。这跟「**一体式**」是矛盾的。
2. **没有统一的导航/状态条** —— 每扇窗各自为政，看不出"这是一个 App"。
3. **打包仍未真跑**（闸二，等主人点头）；`eye/` 那一格已补，
   但**打包产物里到底有没有这 8 扇窗**只有真打一次才知道 —— `K:winfiles` 验的是**配置**，
   不是**产物**。产物级验证要等打包。
