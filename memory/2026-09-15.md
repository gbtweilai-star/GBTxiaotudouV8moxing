## 架构收敛心得（2026-09-15 · 风哥要求入库）

> 一句话总纲：**补丁是止疼药，收敛是手术刀。**

### 病例：auth_consumed 传不出来

现象：`test_auth_gate_flow` 断言 `result.auth_consumed` 为 None。
我连续三次"补丁"都没修好——因为 apply_patch 每次都匹配**第一个**相同代码块，
三行注入全堆在同一个站点（L767），而真正的**主成功出口（第 3 个站点）一行都没打上**。

### 三条教训（比这个 bug 值钱）

1. **同一段代码被复制 N 份，就有 N-1 个会漏。**
   `body["authorization"] = {...}` 在 api.py 里被复制了三处，于是"漏一处"变成必然。
2. **重复的修补动作本身会伪装成"已修复"。**
   "注入了 3 处"听起来像完成，实际是同一处堆了三遍——**没有验证就不算修好**。
3. **验证必须打到最内层。**
   我第一次只看了 `r["result"].get("auth_consumed")`（外壳层）就下结论，
   真正该看的是 `r["result"]["result"]`（能力载荷层）。层次没数清，结论就是错的。

### 做法（手术刀）

- 先 grep 全量出口（`body["authorization"]`），拿到**站点清单**再动手；
- 注入点放在 `stamp_result()` **之前**，保证钢印覆盖最终内容；
- 改完立刻三重验收：编译 → 单测 → 全量回归，用**红项数量变化**证明有效（18 → 17）；
- 把"补丁"留在临时态、把"收敛"留在代码里：清理重复行，让每类出口各只有一处职责。

### 待办（下一刀）

- 把三个出口进一步收敛为唯一的 `_attach_authorization(body, decision)` 助手；
- `pipeline_submit` / `autopilot` 补齐 `status` / `rounds_used`（真形状缺陷，非环境）；
- 加“契约冒烟”体检项：走真实授权链，而不是 `_probe` 探测。
