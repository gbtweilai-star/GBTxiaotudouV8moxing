## 2. 本机实况（真扫，不是猜）：**这一档我们早就有，只是没接进流程**

```
~/.openclaw-autoclaw/skills/
  taste-skill                 1216 行   1 文件   ← leonxlnx 那条（410K 安装量）
  aesthetic-preset-library     600 行   2 文件   ← 19KB：20 种设计哲学（5 流派 × 4 设计师）
  frontend-design               68 行   3 文件   ← 官方那条，但**是改版前的旧版**
  ui-ux-pro-max                 43 行  57 文件
  design-brief                 252 行   1 文件
  gbt-aesthetic                353 行   3 文件   ← 我们自己的（24KB）
```

**两条真结论**：

1. 🔴 **`frontend-design` 我们盘上的是旧版** —— 还是「NEVER use Inter/Roboto/Arial」的黑名单写法。
   外面已经改成：**三种默认长相的描述** + 六个设计原则 + **两遍流程** + **克制律** + 一整章写作。
   **差了整整一个世代**，而它就在盘上、没人发现。
2. 🔴 **`gbt-aesthetic` 之前没引用过 `taste-skill` 与 `aesthetic-preset-library`。**
   技能在盘上、流程里没有 = **有文件 ≠ 有流程**（本仓老毛病，这次又抓到一次）。

## 3. 真正值得偷的三条（外面有、我们今天之前没有）

| # | 招 | 为什么值钱 | 落在哪 |
|---|---|---|---|
| ① | **把黑名单换成失败模式描述** | 「禁用字体清单在出现新默认字体那天就作废；**描述**能泛化到任何字体、任何框架、任何年份」 | `gbt-aesthetic` §3.0（新增） |
| ② | **两遍流程**：先定紧凑 token 系统（命名调色板 / 字体配对 / 布局 / **一个签名元素**）→ **批判它是否平庸** → 最后才写代码 | 代码是**第三步**。我们过去都是"边写边拗"，所以每次都长一个样 | `gbt-aesthetic` §1.6（新增） |
| ③ | **克制律**：把大胆花在**一个地方** + 香奈儿镜子法则（交付前**再去掉一件配饰**）+「至少做一个你能辩护的审美冒险」 | 治"到处都炫 = 到处都不炫" | `gbt-aesthetic` §1.6（新增） |

## 4. 外面那套的**诚实短板**（我们不抄，我们补）

官方那条自带的说明书写得很坦白：它**优化的是"不像模板"，几乎不含工程** ——
只有一条 CSS 特异性警告 + 一条质量底线（响应式 / 键盘焦点 / 减少动态），
**没有无障碍深度、没有性能预算**。garden-skills 的四模块同样是"审美 + 素材"，不是"可验证"。

**而"可机检"正好是我们的强项。** 所以我们的定位不是再抄一份规则，而是
**「审美规则 × 可机检取证」的合体** —— 这是上面八家**都没有**的东西：

| 我们的件 | 它把什么变成了读数 |
|---|---|
| `tools/codex-scripts/audit_aesthetic.py` | AI 味（P0 必修那 6 条）从"感觉"变成**能指行号、能让退出码非零** |
| **`tools/codex-scripts/render_page.py`**（本轮新建） | **审美从"我说好看"变成"渲成 PNG 自己看"**；顺手实测**零出网**（拦获 0 条） |
| `desktop-shell-guard.py` **B8**（本轮新建） | 「立体层必须惰性（零脚本零外链）**且**真三维（透视/分层/层距/自转/无障碍五项齐）」变成守卫能红能绿的**契约** |
| `holo_pet_w3/tests/test_brand_tokens.cjs` | 「声明了没人用」这类假绿 |
| `accept-all-angles.py` | 六视角验收（用户/开发者/运维/安全/审计/交付） |

## 5. 哪些页面要重做 —— **已定，且有依据**

依据不是喜好，是**本轮渲图渲出来的教训** + 外部原文：

> 数据台首版让整块板面自转（5.5°），渲染取证拍出来**满页数字是歪的，像排版坏了**；
> 而 taste-skill 原文正好写着「Landing pages, portfolios, and redesigns.
> **Not dashboards, not data tables, not multi-step product UI.**」

⇒ **分流（已写进 `gbt-aesthetic` §1.5）**：

| 类别 | 页面 | 现在的状态 | 该怎么做 |
|---|---|---|---|
| **数据台（要静）** | 窗 C 执行台 · 窗 D 代码台 | ✅ 本轮已按"静止纵深 + 一个签名元素"改完（swing 收到 0.9°、字正、头部 3D 地面） | 保持；后续只加数据不加花 |
| **数据台（要静）** | 窗 1 上帝视角（默认就开着那扇） | ⏳ **待重做**：`window.css` 还是纯平面（无纵深/无签名元素） | 挂同一份 `deck3d.css`，只做加法：头部签名 + 卡片分层 + 地面；**不动** `window.js`、**不放宽** CSP |
| **数据台（要静）** | 窗 5 AI 朋友圈 · 窗 6 赏金台 | ⏳ 待同一套 |
| **门面页（可花）** | 数字人形象页 | ⏳ **待重做**（这里才放真自转 / 大立方体 / 整屏运动） | 走 §1.5 门面档：变奏 8–10、动效 8–10 |
| **门面页（可花）** | 桌面壳启动页 / 落地页 | ⏳ 尚不存在 | 新建；这是"一体式桌面 APP"的门面 |

**顺序**：窗 1 上帝视角（默认可见，收益最大）→ 门面页 → 窗 5/6 → 数字人形象页。

## 6. 一条自证（免得这份变成自我表扬）

本轮改的 `deck3d.css`，**三次渲图三次改**，每次都是"我以为对了、拍出来发现不对"：

| 轮 | 我以为 | 拍出来看到 | 改法 |
|---|---|---|---|
| 1 | 立体层做完了 | 卡片几乎无视差、**网格地面完全不存在**、立方体只是个小方块 | 拉大层距、立方体 58→84px、加光环 |
| 2 | 加自转就有冲击 | **满页数字是歪的**，像排版坏了 | swing 5.5°→3.2° |
| 3 | 地面提亮就能看见 | 固定地面**永远在卡片背后**，被玻璃 + `blur()` 糊没 | 改成**头部留白带里的真 3D 地面** |
| 4 | 收尾 | 立方体外光环贴边被切 | 板面左右留白加大 |

**四次里有三次是"我判断错了"。** 这就是为什么这一件必须有 ——
**没有渲染取证，"好看"就只能靠我嘴说**，而今天四次嘴说全错。
