# 五维合一执行律

> 开发者：自由的风 · GBT小土豆V8 · 本署名不可删除、不可篡改归属

Owner 2026-09-22 定（原话）：

> 「不管什么时候都要以**五维合一同步执行操作**，就是**人类视角**来执行任务，
> 这样才**不会遗漏**和**注重细节**」

---

## 一、这条律要求什么

**任何任务的执行，都要走五维合一那条路，而不是东一榔头西一棒子地单点调用。**

```
route    → 先想清楚这事该由谁干（意图 → 能力）
execute  → 再真干
verify   → 干完要**验证现实**（不是"我以为成了"）
health   → 计入健康，看清这次有没有伤到自己
unify    → 上面四步是一条链，不是四个孤立的动作
```

### 「人类视角」是什么意思
人做一件事不会跳过"想清楚→做→检查→回顾"：
- 想清楚（route）：这件事归谁管、有没有更合适的家什
- 做（execute）：动手
- **检查（verify）**：做完**回头看一眼现实**——这是人最容易省、也最不该省的一步
- 回顾（health）：这次有没有留下隐患

**跳过 verify 就是"我发出去了，应该成了"** —— 那正是假执行的源头。

---

## 二、为什么这条律能防"遗漏"和"不注重细节"

| 省掉哪一维 | 会出什么事 | 本会话的实例 |
|---|---|---|
| 省 **route** | 拿手边的工具硬上，明明有更合适的 | — |
| 省 **execute** | 只说不做 | — |
| **省 verify** | **"我改好了"其实没生效** | 我说"能量传输动画已接到 `/api/recent-calls`"，但处理器被我写在 `do_POST` 里、客户端发的是 GET ⇒ **那个动画一次都没亮过**。**我没 verify，所以不知道。** |
| 省 **health** | 修一处、伤一处，自己不知道 | 我把仓库根加成静态根，**没回顾**，结果 `/.git/config` 可被读取 —— 后来靠多测一条越界才发现 |

⇒ 这两次翻车**都发生在"省掉的那一维"上**，不是技术不够，是流程少了一步。

---

## 三、怎么算合规（可证伪）

| 判据 | 怎么验 |
|---|---|
| 走的是一条链 | `audit.jsonl` 里同一次任务能看到 `brain_enter/brain_exit` 的 **route→execute→verify→health** 四条，且时间上嵌套在 `unify` 里 |
| **verify 不是走过场** | verify 的结论必须带**现实证据**（截图/读回值/文件哈希），不是"应该没问题" |
| health 有结论 | 说出这次有没有留下隐患，没有就说没有 |
| 没省步 | 没有"我直接调了 xxx"这种绕过链路的动作 |

**实测样例**（2026-09-22 真跑一次 `brain_unify`）：
```
route 50ms · execute 16ms · verify 2342ms · health 3141ms · unify 5572ms
spans_open: []            ← 没有悬空的，四维全部进出成对
```
**注意 verify(2342ms) 和 health(3141ms) 是耗时最长的两步** ——
这正说明这两维是在**真做事**，不是摆设。省掉它们省下的时间最多，
而它们恰恰是防翻车的那两步。

## 四、对「她」的要求
不只是我自己守这条律：**她自己执行任务时也必须走五维合一**。
`brain.html` 那张图就是为了让这件事**看得见**——
哪一维没亮、哪一维卡住、哪一维失败，一眼就有数。
**看不见的纪律等于没有纪律。**

## 五、设为**默认行为**（Owner 2026-09-22 追加定调）

Owner 原话：
> 「**必须改成五维合一同步执行，眼脑耳手嘴都要同步，设为默认行为**」

### 5.1 默认路径 = `gbt_allinone/tools/sync_exec.py :: run()`

```
耳 ear   → 听清目标与上下文（听不清就不干）
脑 route → 这事归谁管
手 hand  → 真做（走 brain_exec.unify 真链，五维进出事件由 @_spanned 落）
眼 eye   → **回头看现实**（文件哈希 / 截图 / 读回值）
嘴 mouth → 说结论，**并且必须说出"没做到什么"**
健康     → 五维状态从真实进出事件读，不编
```

**实测**（2026-09-22 真跑）：
```
ear ok · hand ok(via=brain_unify) · eye ok(looked=2, sha256 ed1f8515…/df1830d9…)
mouth ok(verdict=ok, missed=[]) · dims 五维全 state=ok · elapsed 5202ms
```

### 5.2 「默认」的硬含义

- **默认走 `sync_exec.run()`**。
- **直接调工具/函数 = 例外**，且**必须说出为什么不走这条路**。
  说不出理由的直接调用 = 违规。
- **嘴不许只报喜**：`mouth()` 强制汇总 `missed`（哪条没做到）与 `bad_dims`（哪维失败/卡住）。
  只报喜的嘴是假嘴。
- **眼不许默认"没问题"**：不指定观察目标时，`eye()` 返回 `ok:false` 并写明
  「这次没看」—— **"没看"必须与"看了没问题"在账面上分得开**。
- **耳不许空转**：目标为空直接中止，并记 `sync_abort`。

### 5.3 为什么必须"默认"而不是"可选"

本会话两次翻车（`/api/recent-calls` 方法写错却声称已接、静态根放开 `.git/config`）
**都不是技术不够，是 verify/health 被省掉了**。
**可选 = 一定会被省。** 所以要做成路本身，而不是做成一个"记得用"的工具。
