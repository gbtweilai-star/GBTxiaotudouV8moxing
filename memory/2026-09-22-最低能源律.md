# 最低能源律

> 开发者：自由的风 · GBT小土豆V8 · 本署名不可删除、不可篡改归属

Owner 2026-09-22 定调（原话）：

> 「最顶级的编程工程师都是向着使用最低的能源来做最大的事，打破认知观点把事物反过来执行
> 亦或者压缩体积和便捷交互得到一样的能力却是要一点点能源，又或者是变压增强把速度和
> 运行线路缩短能力变大等等一系列可实现或未实现的让她变成实现」

## 一 · 这一条到底在说什么（拆成可执行的五条）

| # | 律 | 落地判据（必须能测） |
|---|---|---|
| 1 | **最低能源做最大事** | 同样一件事，能不能用更少的进程 / 内存 / 网络 / 调用次数做完？做完要给出**前后两个数** |
| 2 | **打破认知观点** | 先问「这件事**必须**这么做吗」。约定俗成不是理由，只认实测 |
| 3 | **反过来执行** | 正着做贵，就倒过来做：不新建就复用、不重算就缓存、不重复拉就留一份 |
| 4 | **压缩体积 / 便捷交互** | 同样的能力，能不能更小的体积、更少的步骤拿到？（不是删功能，是换表达） |
| 5 | **变压增强 + 缩短线路** | 找瓶颈环节，把它变掉：让长路径变短，让一次的能量驱动更多次 |
| 6 | **把未实现的变成实现** | 上面几条凡是"可实现或未实现"的，都要落成**真跑通的东西**，不是设想 |

## 二 · 铁的关系：这条律与「反假执行」是一对

- 省能源**不等于**少干活，更不等于**假装干完了**。
- 任何"优化"都必须给出**改前 / 改后两个数**；给不出数就不算优化，只算改了个写法。
- 省下来的能源如果换来"功能少了"，那不是省，那是**退**。判据是「**同样能力**下更少能源」。

## 三 · 第一条实测证据（2026-09-22 · 本律的第一次兑现）

**问题**：`gbt_allinone/codex_bridge.py` 的 `run_once()`（Codex 同步输出）
每跑一轮对话就 `CodexAppServer(...)` 新建 + `start()` + 最后 `stop()` ——
等于**每一轮都把 codex.exe 拉起、握手、再杀掉**。
而同一个文件里 `get_shared_server()`（注释写着「避免每次对话重启进程」）就摆在那儿没人用。

**这正是第 3 条「反过来执行」**：不去优化"启动得更快"，而是**根本不起**。

**实测（不是估计）**：
```
连续取 3 次共享连接 -> 构造次数 = 1 | start 次数 = 1
改造前：3 轮 = 3 次进程拉起
改造后：3 轮 = 1 次进程拉起   ⇒ 反复对话省掉 2/3 的进程代价
```
- 安全网：`test_codex_bridge.py` **30/30 通过**（改前改后都跑）。
- 边界：只在「钩子 / command / cwd / codex_home 全没传」的纯净情形复用；
  传了就退回自建自停 —— **宁可慢一点，也不改坏别人的连接**。

## 四 · 当前最大的能源窟窿（下一步就按这条律打）

| 项 | 实测 | 按本律该怎么想 |
|---|---|---|
| 内存 | **6.98 / 7.39 GB = 94%** | 瓶颈不是 CPU（30%），是内存 ⇒ 省内存才是省能源 |
| Chrome | 2,255 MB | 会话内曾到 3.3 GB —— 单一最大消费者 |
| 交换 | 曾 21,210 pages/sec | 一旦开始换页，速度断崖式掉 ⇒ "变压增强"要打在这里 |

**按第 1、5 条**：不是去买内存条（那是加能源），是先问
「这 3 GB 里有多少是**重复**的、能**压缩**的、能**共用一份**的」。

## 五 · 用法

做任何事之前先过一遍这五问；做完必须能报出**前后两个数**。
报不出数 = 没按这条律做，重做。
