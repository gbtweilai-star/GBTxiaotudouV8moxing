## 一、设计读数：八扇窗摆在一起看，结论很难看

上一轮做出的真壳取证器 (`shell/shots.cjs`) 把 8 扇窗的真图摆在一起，量出来是这样：

| 窗 | 顶栏 | 品牌串 |
|---|---|---|
| 上帝视角 / AI 朋友圈 / 赏金台 | 有 | `GBT小土豆V8 · xxx` |
| 触手视觉回传 | 有 | **`触手视觉回传`（少了 `GBT小土豆V8 ·` 前缀）** |
| 执行面 / 代码台 / 神经工作台 | **没有**（被大球 hero 顶掉） | 只有 `<title>` |

⇒ 八扇窗是**八个各自为政的网页**：品牌串不一致、有的有顶栏有的没有、**没有任何跨窗跳转**。
这跟「一体式」是矛盾的。

---

## 二、怎么解：**壳这一层注入**，而不是改那 8 个页面

改 8 个页面 = 同一个决定写 8 遍 ⇒ 必然漂（本仓为"两份判据不一致"付过代价）。

⇒ `shell/chrome.cjs`：**一处定义**，`webContents.insertCSS()` + `executeJavaScript()` 注入。
调用方两个：`main.cjs` 的 `createWindow`（用户真跑的）与 `shots.cjs`（取证拍的）——
**同一份定义，不重写第二份**（否则拍出来的就不是用户看到的样子，又一种假读数）。

🔴 **DSH 那扇窗（`dsh-chat`）一行都不碰** —— 硬约束。它是这个 App 的窗，
但**它的内容不是我们的**：不在注入名单里。别窗能看到它、能跳过去，没人往它里面塞东西。

### 铬长什么样

```
● GBT小土豆V8 ｜ 执行面 ｜ [上帝视角][AI 朋友圈][赏金台][对话 ⋯][执行面●][代码台][神经工作台][触手视觉回传] ｜ ● 宿主已接 11:47:13
```

- 左边：土豆金圆点 + 品牌（`GBT` + **金**`小土豆` + `V8`）+ 当前窗名；
- 中间：**8 扇窗的芯片**（当前那扇高亮、点了就跳）；需要主人给 URL 的那扇带 `⋯`；
- 右边：**宿主灯**（接没接上）+ 实时时钟；
- 整条可拖拽窗口（`-webkit-app-region: drag`），芯片区 `no-drag`。

## 三、抓到的三处真缺陷

### 缺陷 1 🔴 芯片换行，把 30px 的栏撑成两行（**我自己第一版拍出来的丑**）

首拍（`%TEMP%\gbt-chrome\exec-deck.png`）：8 个中文芯片挤不下就换行，
标签从中间断开 —— 「上帝视 / 角」「赏金 / 台」「神经工 / 作台」。**看着就是没做完的样子。**

修：`#gbt-chrome { flex-wrap: nowrap; overflow: hidden }` +
导航 `flex-wrap: nowrap; overflow-x: auto` + 芯片 `white-space: nowrap`。
**宽度不够就让导航横向滚，栏高永远是 30px。**

### 缺陷 2 🔴 60px 内出现两次品牌

上帝视角那几扇窗**自己**就有一条写着「GBT小土豆V8 · 上帝视角」的栏；
App 铬再写一遍 ⇒ 两行连着同一个名字。

修：**运行期问页面**（`document.querySelector(".gbt-topbar")` 存在就不写窗名），
**不是按页写死一张名单** —— 名单会漂，探测不会。

### 缺陷 3 🔴 「铬在场」这件事**以前没有任何机检**

注入脚本抛一行错、或 `NEVER` 名单写错，表面上"窗照样拍得出、照样 PASS"，
实际那扇窗就是没有 App 铬的孤儿。

修：取证器里加**铬在场断言**（`!!document.getElementById('gbt-chrome')`），
并且 `shots.cjs` 自己也要挂铬 —— 不挂的话拍的是"没有 App 铬的样子"，又一种假读数。

**实测：7 扇全部 `铬=true`。**

## 四、跨窗跳转：判据抽出来才测得了

第一版把跳转逻辑内联在 `registerIpc()` 的闭包里 —— `wins` / `registry` 都拿不到，
**"跳得动吗"永远只能靠真启动壳去点一下**才知道，等于没验。

⇒ 抽成 `chrome.showWindow(registry, wins, payload)` 纯函数（本仓既有做法：
`url-policy.cjs` 的"单一决策点，可单测"）。**七路都能在纯 node 里测**：

| 用例 | 判据 |
|---|---|
| 认得出的窗 + 活着 | 真 `show` + `focus` |
| 最小化 | 先 `restore` 再 `show`+`focus` |
| **白名单** | `""` / `nope` / `../../etc` / `{id:1}` 一律拒，**且不许动窗口** |
| 注册表有、窗没建 | 如实报「还没建起来」，不假装成功 |
| 已销毁 | 拒 |
| 窗口自己抛异常 | 不冒泡，转结构化拒绝（不许把主进程带崩） |
| **注册表里每一扇** | 都跳得动（少一扇就是孤岛） |

`preload.cjs` 的 `non_readonly_capability` 那一行**同步登记**了 `showWindow`
（它不改数据但是**动作口**）："只认注册表里已有的窗 id；只改可见性/焦点，不写文件、不出网、不 kill 进程"。

## 七、还剩的硬缺口（下一轮）

1. **h1 的路径暴露**（见 §五，本轮新发现）；
2. **数据机制仍不统一** —— 8 扇窗现在有**五种**取数方式：godview 走 IPC 实时、
   exec-deck/code-deck 是**静态快照**（页上写着"重生成命令"）、brain 是**生成的数据文件**、
   eye 是**文件轮询**。铬统一了"长相"，**没统一"血路"**；
3. **打包仍未真跑**（闸二）—— `K:winfiles` 验的是配置不是产物。
