### B. 违规确证（一手读数，不是推断）

被审对象：`gbt_allinone/llm/` 下三个带 `# gbt-capability:` 标记的模块
（`key_gateway` / `multimodal_port` / `genoffice_bridge`）。

**修前四处互锁点全为 0**：

| 互锁点 | 修前读数 |
|---|---|
| `caps_registry.BENIGN_CAPS` | 总数 202，三名**均不在册** |
| `api.py` 出现次数 | **0** |
| `state/skill_atlas.json` | 202 条，命中 **0** |
| `state/unimplemented.json` | 对三名 **0** 登记 |

**⚠️ 关键：这四处全零，而两条判据照样全绿**：

```
python tools/framework_state.py      → ✅ 全绿（registry=202 · undispatched=[] · not_in_atlas=[]）
test_cap_bind_bidirectional          → Ran 5 tests · OK
```

**为什么绿**：该判据的循环是 `for k in BENIGN_CAPS:` —— **看不见没注册的东西**，
没注册自然不报红。「死角不是不会，是**不会还不说**」（`docs/触手覆盖矩阵.md:32`）。

**可观测后果**（这才是"故障与断连"的实证，不是"没记录"这么轻）：

```python
run_task("key_gateway",      {"op":"status"})  → unknown capability（没有这个能力位名）
run_task("multimodal_port",  {"op":"status"})  → unknown capability（没有这个能力位名）
run_task("genoffice_bridge", {"op":"status"})  → unknown capability（没有这个能力位名）。
                                                你是不是要：genoffice   ← 邻近匹配建议也是错的
```

成因唯一：`api.py::_run_task_core_body` 第 **1772** 行 `if kind not in BENIGN_CAPS:`
⇒ **注册是"可被触手叫出"的硬前提**，不只是元数据。

### C. 修复（五处，逐处落点）

| # | 文件 | 动作 |
|---|---|---|
| 1 | `llm/genoffice_bridge.py` | **补薄 `run(op)`**（它原先只有 `serve/selftest/main`，当不成能力位） |

**为什么 policy 那处必须补（这是个真洞，不是锦上添花）**：
`evaluate()` 对**未列出的 kind 是 fail-open** —— `scopes=()` ⇒ `decision.restricted` 为假
⇒ `authorize()` 直接放行。只注册名字不声明作用域 = 让新位**带着写盘与出网能力裸奔**。
（同族先例：R-H98 / R-H99c「声明与执行漂移」。）

**作用域口径（逐 op 现读验证过）**：

| 能力位 | 读类（零作用域） | 写/出网类（收口） |
|---|---|---|
| `key_gateway` | status/whoami/energy/plan/keys/compat/mask/classify/verify/selftest | `mint`·`revoke`·`note`·`reset` → `filesystem_write`；**`materialize` → `external_llm`**（唯一返明文密钥的路 R-H201，且全部调用方取钥都是为随后出网调模型）；未知 op 一律 fail-closed |
| `multimodal_port` | status/port/catalog/redlines/selftest | `probe` → `external_llm`；未知 op fail-closed |
| `genoffice_bridge` | status/probe | `selftest` → `filesystem_write`+`network_private`+`external_llm`（它 `KG.mint()` 铸钥 + 起临时监听 + 真出网，三样都占）；`serve` → `network_private` |

**门挂在哪**：挂 **cap 边界**（`policy.evaluate`），与本域既有口径一致
（`llm/unified.py::status()` 的 `gate` 字段原话：
"external_llm 人工授权门装在 cap 边界（api.run_task('llm_chat')）"）。
**不在模块里自挂第二道闸** —— 同一件事两处真相，迟早漂移。

## 二、主人令（新）：**默认走小土豆自己的扫描能力**，不许拿传统扫描当主力

> 「直接默认调用小土豆的扫描能力比你传统扫描好一百倍，传统扫描拿来扫灰都先碍事」

**落法（今后默认）**：
* 要**读框架自身状态 / 对账 / 找缺口** ⇒ 先走框架能力位：
  `cross_scan`（A 维注册表↔路由 · X 维多扫描器互证）·
  `coverage_auditor`（覆盖矩阵）· `truth_scan`（真执行）· `selfscan`（模块清单↔导入）·
  `framework_state.py`（六面读数）。
* 传统 grep/glob/read 只用于**定位具体文件与行**（动手前的取证），
  或框架扫描器没覆盖的**一次性小范围问题**。
* 判据口径：**框架扫描器的读数优先于我自己拼的扫描脚本**；
  自建脚本只在框架没有该维度时才做，并要说明"框架缺哪一维"。
