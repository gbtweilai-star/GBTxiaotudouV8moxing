二、灭杀的 5 个根因

根因 1 · scan() 只认硬编码邻域清单
磁盘实有 523 caps + 227 brain 模块，扫描只报 516——brain/ 目录 227 个模块只登记 34 个，其余 193 个对拓扑不可见；caps/ 非吞噬类新能力也进不了扫描。
修复：装入全量兜底归集，新增"🧠 脑模块层"（186 模块）+ "📦 未归类能力"（35 个）两个动态域。
根因 2 · topology() 与 scan() 口径分裂
scan 已报 737，topology 还数硬编码清单的 360。
修复：topology() 改为以 scan() 全量口径为准（带回退兜底）。
根因 3 · 交叉引用孤儿误判
actual 升到 714 但 defined 还是 494 → 221 个新归集模块全被当"孤儿"，deep_scan 假报 408 断连。
修复：动态兜底域计入 defined → 714 = 714 全对齐。
根因 4 · integrity 脑模块层误检
integrity 只认"🧠 多脑域"是 brain 模块，新增"🧠 脑模块层"186 个 .py 被当 caps 目录查 capability.json → 188 处误报。
修复：is_brain 判定扩展到两个脑域 → 188 → 3。
根因 5 · 3 个 cap 真实数据损坏
aliens_eye_scan（UTF-8 BOM 致 JSON 解析失败）、api_fuzzer 与 container_escape（缺 name/actions 字段）。
修复：去 BOM 回写、补 name + 从 run.py 提取 actions，全部修复。
