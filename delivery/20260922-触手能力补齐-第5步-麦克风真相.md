## 一、🔴 本步最重要的收获：**同一个事实我连错两次**

| 第几次 | 我的说法 | 依据 | 对不对 |
|---|---|---|---|
| 1 | 「**本机真的没有麦克风**」 | `winmm` 的 `waveInGetNumDevs = 0` | ❌ **错** |
| 2 | 「**本机有麦克风**（蓝牙免提）」 | `Get-PnpDevice -Class AudioEndpoint` 显示 `麦克风 (iPhone Hands-Free HF Audio)` [OK] | ❌ **也不准** |
| 3 | **按 WASAPI 状态掩码实测** | `EnumAudioEndpoints(eCapture, mask)` | ✅ **准** |

**第三次的实测数**（这才是事实）：

```
eCapture ACTIVE     = 0     ← 活动录音端点：0 个
eCapture DISABLED   = 1     ← 有 1 个处于「被禁用」
eCapture NOTPRESENT = 3
eCapture UNPLUGGED  = 1
eCapture ALL        = 5     ← 系统在册 5 个录音端点
eRender  ACTIVE     = 1   ALL = 22
```

**准确说法**：本机在册录音端点 5 个、**活动 0 个、其中 1 个被禁用**。
既不是"没有麦克风"（第 1 次），也不是"有麦克风"（第 2 次）。

**根因（两条都是我方法上的错）**：
- `winmm` 的 `waveIn` **只枚举传统 MME 设备**，现代蓝牙/WASAPI-only 端点根本不在里面 ⇒ 报 0 **不等于**没有。
- PnP 的 `AudioEndpoint` 报 OK **只说明设备节点在**，**不代表它在 WASAPI 层是"活动"的**（被禁用的设备在 PnP 里也可能显示在册）。
⇒ **一个数据源的一个数，不是事实。必须换个层面交叉验证。**

要真录麦克风，**得主人去「声音设置 → 录制 → 显示禁用的设备」里启用它** —— 那是改系统设置，
**我不代劳、也不假装能做**。这条已写进 `AUDIO_GAPS` 与 `TENTACLE_MANIFEST`。

## 二、顺带补上的两件真东西

### 2.1 `capture(flow=...)` 参数化：回环与麦克风共用同一套机器

`wasapi_loop.py` 从"只有回环"扩成 `capture(seconds, flow="loopback"|"mic")`：

| flow | dataFlow | StreamFlags |
|---|---|---|
| `loopback` | `eRender` | `AUDCLNT_STREAMFLAGS_LOOPBACK` |
| `mic` | `eCapture` | `0` |

### 2.2 没有默认端点时**枚举活动端点回退**（这是"麦克风好像没有"的第二个原因）

实测：`GetDefaultAudioEndpoint(eCapture, ...)` 抛
`COMError (-2147023728, '找不到元素')` = `ERROR_NOT_FOUND` ——
**端点存在，但没被设成默认录音设备**。

⇒ 补上 `IMMDeviceEnumerator::EnumAudioEndpoints` + `IMMDeviceCollection`（`GetCount`/`Item`），
取第一个活动端点；并把 `used_fallback`（含 `active_endpoints` / `picked_index` / `why`）
**如实带回返回值**，不让"用了回退"这件事藏着。

### 2.3 采集语义细化：`chain_ok` ≠ `verified`

首版让 **0 帧也回 `verified=True`** —— 那是**过度声称**。现在分开：

- `chain_ok` = 链路打通（Initialize + Start + GetService 都成功）
- **`verified` = `chain_ok` 且真抓到了帧**
- 0 帧时**必须带 `note`** 说明为什么（回环=系统没在出声；麦克风=没在采集）

用例也跟着改成两层契约 —— **测试要跟着更严的语义走，不是把语义放松去迁就测试**。

## 四、本步自己抓到自己 4 个错（全部写进注释）

1. `DEVICE_STATE_ACTIVE` 常量漏定义 ⇒ `NameError`
2. `EnumAudioEndpoints` 原来声明成**无参**（我图省事留的占位）⇒ 必须按头文件补全 3 个参数 + `IMMDeviceCollection`
3. `audio_loopback` 重组字典时**弄丢 `chain_ok`**（那正是"链路通"与"真抓到"的区别）
4. 同一处又**弄丢 `note`** ⇒ 被用例当场抓住（"没抓到帧必须说明原因"）
5. 探针脚本**第 3 次**中英文引号混用（`"默认录音设备"` 用 ASCII 引号截断字符串）
