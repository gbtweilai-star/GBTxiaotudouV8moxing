## 一、"无所遁形"落成什么（不是口号，是恒等式）

本仓已有 **6 台**扫描器，各管一摊，**我不另立第二套真相**：

| 工具 | 管什么 |
|---|---|
| `code_exhaustive_scan` | **每一行**文本有没有毛病（已立闭合律） |
| `cross_scan` | **关系**无死角（注册表↔路由↔导入↔影子↔运行时可达） |
| `host_security_scan` | 主机面安全 |
| `caps_called_audit` | 能力位有没有人调 |
| `coverage_auditor` | 触手覆盖矩阵 |
| `scan_scope` | 扫描**范围口径**（谁扫仓都从它取） |

上面六台**都不管"藏匿面"**：一个东西藏得好，在"逐行"和"关系"里都是**看不见**的。
新引擎 `gbt_allinone/tools/scan_engine.py` 补的就是这一层，并把它做成**可证**：

### 1.1 覆盖闭合律（D1）—— 恒等式，不是自检

```
枚举到的文件  ==  已扫 + 已声明排除 + 工具/缓存排除 + 读不到
```

对不上 = 有东西没落账 ⇒ **判红**。

| D3 | 扩展名分布 | `-002` | 每个后缀的文件数与体积（找野后缀） |

## 四、最重的一处：我修掉了一个**假绿**

第一版账本把嵌在 `gbt_allinone/store/`（**深层**排除）里的两万个文件算成**"已扫"** ——
它们只被"数过"、从没被读过。

```
引擎报 已扫 23,089   ← 假
同一份剪枝口径只走得到  2,495   ← 真
恒等式 `枚举 == 三桶之和` 照样成立，**但标签在撒谎**：
它把"从没读过"记成了"扫过没问题"。
```

**铁律（已写进代码注释与被测）**：`walk 走得到的才算「已扫」；剪掉的一律进排除桶，并写明是谁剪的。`
修后 `已扫 2,496`，且 `ADS 问过 2,496 == 已扫 2,496` —— 两个数自洽，"藏匿 0"才立得住。
这条正是"无所遁形"的要害：**账本撒谎时，覆盖率是最漂亮的假话。**
