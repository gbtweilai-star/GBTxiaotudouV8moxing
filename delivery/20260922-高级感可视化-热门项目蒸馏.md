## 二、蒸馏：我们取什么、不取什么

### 2.1 取（技法，重写）

| # | 技法 | 为什么这是"高级感"的根 |
|---|---|---|
| **1** | **后处理辉光（bloom）代替逐元素光晕** | 🔴 **这条直接解释了我上次为什么糊**：我现在的做法是**每个元素各自画 radial-gradient 冒充辉光**，叠在一起就是一团雾。专业做法是：主画面先画**硬的**（芯线、实心点），**再对整张画面做一次高斯模糊 + 加色合成** ⇒ 辉光是**全图统一**的，亮部溢出、暗部干净 |
| **2** | **FBO 帧反馈做运动残影** | 不清屏，把上一帧按衰减率叠加 ⇒ **物理正确的运动模糊**。能量的拖尾是"真的走过"，不是画上去的尾巴 |
| **3** | **Instanced / 批量绘制** | 一次 draw call 画全部节点与边。我们现在是 forEach 逐个 stroke —— 158 个还撑得住，但这是**上限** |
| **4** | **TypedArray 传坐标** | 零对象分配，每帧不产生垃圾 ⇒ 不掉帧。掉帧本身就是"假"的来源 |
| **5** | **真实时间轴对齐** | 事件带真实 `ts`（我们 `audit.jsonl` 每条都有），动画按**真实间隔**播放，不是固定节奏 |
| **6** | **span 进/出成对的状态机** | 节点状态 = `entered→running→exited`；**只进不出 ⇒ 真卡住**（变琥珀 + 计时），出错退出 ⇒ 红。这与 NeMo/mobilerun 的 trace 模型一致 |

### 2.2 不取（以及为什么不取）

| 不取 | 理由 |
|---|---|
| 装 `cosmograph` / `sigma.js` / `deck.gl` / `pixi.js` | 我们是**本地优先、零新依赖**；而且目标是**几十个节点**，不是百万级。为几十个点装一个百万级引擎，是"用大炮打蚊子"，还平白多几百 MB |
| 装 `@vysmo/effects` 之类的后处理库 | **后处理管线本身很短**（两趟模糊 + 一次合成，约 60 行 WebGL），自己写可控、可调、可解释；装库反而被它的抽象框住 |
| 用现成的图布局库（dagre/elkjs） | 我们**已经自己写了 Sugiyama 分层 + 重心法**（`brain_graph.layout()`），实测有效（execute/route 因有边而相邻） |

**⇒ 一句话：取他们的"物理与管线"，不取他们的"包"。**

## 三、"逼真最重要"落到哪几条硬判据

逼真 = **每一帧都能追溯到一条真事件**。以下每条都可证伪：

| 判据 | 怎么验 |
|---|---|
| 动画只在有真事件时发生 | 停掉一切调用 ⇒ 图必须是**暗的、静的**（除了存活心跳） |
| 时长 = 真实耗时 | 某维真跑了 3.2s ⇒ 那一段就亮 3.2s，不是固定 0.6s |
| 路径 = 真实路径 | 亮的这条必须能在 `audit.jsonl` 里找到对应事件；找不到就是假的 |
| 卡住 = 真卡住 | 进事件有、出事件超时没有 ⇒ 琥珀 + 秒表走；**不许自动"假装完成"** |
| 失败 = 真失败 | 真 `error`/`denied` ⇒ 停在那维变红，不抹平、不重试掩盖 |
| 静默 = 真静默 | 无事发生时不放任何装饰性循环动画 |

**最后一条与"高级感"不矛盾，反而是它**：只有平时是暗的，亮起来那一下才有分量。

## 四、落地到 `brain.html` 的技术栈（零新依赖）

```
第 1 层  数据      /api/brain-graph（结构 + Sugiyama 布局 + 真实事件）   ← 已完成
第 2 层  时间轴    真实 ts 驱动；事件进/出成对判定状态                    ← 待做
第 3 层  主画面    Canvas2D 画**硬**的：芯线、实心点、等宽数字            ← 待做
第 4 层  后处理    offscreen 画布 → 高斯模糊 → 加色合成（辉光）
                  + 帧反馈残影（运动模糊）                              ← 待做
第 5 层  色彩      OKLCH 感知均匀 + 色盲安全四态色                        ← 待做
第 6 层  动效     cubic-bezier 缓动 + `prefers-reduced-motion`           ← 待做
```

**关键顺序**：**先画硬的，再做辉光。** 我上次的错就是把"软"画在了元素上，
所以放大是糊的——正确做法是元素硬、辉光在全图层统一做。
