## 三、要 Owner 拍板的：源码怎么"单独一个文件夹"

⚠️ **为什么不能我自己动手**：这三个大件（store 1.48 GB / .pylibs 274 MB /
node_modules 399 MB）全都**被正在运行的代码按固定路径引用**：

| 大件 | 谁在引用 | 搬动风险 |
|---|---|---|
| `store/` | `gbt_allinone/_paths.py:11` 默认 `_BASE/"store"` | 改了默认值，**正在跑的面板/HUD 可能读不到自己的状态** |
| `.pylibs/` | `gbt_allinone/dependency_paths.py` | 第三方依赖 import 会断 |
| `node_modules` | `holo_pet` 的 Node 侧 | 面板 Node 功能会断（`npm install` 可恢复） |

主人明令「**不去修改环境，要不然到时候我的电脑带不动触手了**」+「不会影响你运行的」
⇒ **我不擅自动这 1.6 GB 的活状态。**

### 方案 A（推荐）· 只动外来物，源码不动

```
GBT小土豆V8/
├── gbt_allinone/          ← 源码留在原地（import 路径不变，零风险）
├── holo_pet/  potato_pet/  tools/  plugins/  holo_pet_w3/
├── data/store/            ← 从 gbt_allinone/store 搬来（改 1 行默认值 + 设 env 双保险）
├── vendor/pylibs/         ← 从 gbt_allinone/.pylibs 搬来
├── vendor/node_modules/   ← 从 holo_pet/node_modules 搬来（或直接删，可 npm install 再生）
├── docs/                  ← memory/ delivery/ projects/ 与根目录 32 个 .md 归拢
├── archive/               ← V1→V21
└── .scratch/ .trash/      ← 临时区，明确不算源码
```
- 结果：`gbt_allinone/` 从 18,779 个文件降到 **约 500 个**，成为**纯源码树**。
- 代价：改 `_paths.py` 1 行 + 动 1.6 GB（**分步做，每步可回滚**）。

### 方案 B · 源码收进一个 `src/`

```
src/gbt_allinone/  src/holo_pet/  src/potato_pet/  src/tools/  src/plugins/
```
- 最贴合"单独一个文件夹"。
- 代价：**要改所有 import 入口** —— pytest 的 rootdir、`test_*.py`、
  `holo_pet/panel_server.py`、各个 `.bat` 启动器、DSH 插件路径。
- 风险：**很可能把正在用的面板弄断**。我不建议在你在用的时候做。

## 五、重复的：106 MB 里**大部分是故意的**，不能一刀切

全仓扫了 15,395 个文件 / 1,513 MB，找出 **440 组重复 · 1,978 个多余副本 · 白占 106.27 MB**。

但重复的**大头是设计使然**：

| 重复项 | 份数 | 为什么不能删 |
|---|---:|---|
| `mirror_space/rooms/.../llny.moc3` | 3 | `dimension/`(沙盒) `reality/`(生产) `timelines/v1`(版本) —— **镜像多维度就是靠"各存一份、互不污染"**，删了镜像纪律就废了 |
| `.../haru/Haru.2048/texture_00.png` | 4 | 三份同上 + `potato_pet/resources/` 一份 |
| `mirror_space/timelines/v1..v19/jquery.min.js` | **19** | 每个时间线版本各一份 ⇒ **这一项是真冗余**（1.7 MB） |
| `store/pipeline/.../_eye_test.png` 系列 | 2-3 | 流水线暂存与版本副本 |

**⇒ 结论：不能按"同名同内容就删"批量去重**，那会破坏镜像与版本回退。
真正该动的只有 `jquery.min.js` ×19 这类（1.7 MB），收益小、风险中。
**我建议：重复这件事先不动，等 store 搬去 `data/` 之后再单独做去重盘点。**

## 六、执行结果（2026-09-22 实做，Owner 选方案 A）

### 6.1 做成两件（673 MB 搬出源码树，路径不变所以零代码改动）

| 大件 | 结果 | 验证 |
|---|---|---|
| `gbt_allinone/.pylibs/` 274.2 MB | → `vendor/pylibs/` + **junction** | ✔ 经 junction 读到 **123 个包**；`local_dependency_paths()` 认 `cp314` 与基座两条路径；**只装在 .pylibs 里的 `adodbapi` / `Crypto` 现在仍能 import**（解析到 `gbt_allinone\.pylibs\...`） |
| `holo_pet/node_modules/` 399.0 MB | → `vendor/node_modules/` + **junction** | ✔ 经 junction 读到 **15 个包** |

**为什么用 junction**：路径完全不变 ⇒ `_paths.py`、`dependency_paths.py`、Node 的
`node_modules` 解析**一行都不用改**，零破坏风险。物理体量已经搬出源码树。

### 6.2 `store/` 1,481 MB —— **搬失败，已完整回滚**（这一节必须留着）

```
──── gbt_allinone\store -> data\store ────
  搬前: 13,156 个文件 · 1,481.3 MB
  ✘ 失败: The process cannot access the file because it is being used by another process.
```

**危险点：`Move-Item` 是搬了一半才失败的**，不是原子操作。实测：

| 位置 | 文件数 | 体积 |
|---|---:|---:|
| `gbt_allinone\store`（残留） | 10,555 | 1,260.2 MB |
| `data\store`（被搬走） | 2,601 | 221.2 MB |
| **合计** | **13,156** | **1,481.4 MB** ✅ 与搬前**逐数吻合** |

**⇒ 一个字节都没丢，但当时框架读的目录少了 221 MB —— 是个活的隐患。**

**立刻回滚**：把 `data\store` 的东西并回原位。
```
并回 26 项 · 已有跳过 0 · 失败 0
复核: gbt_allinone\store 现在 13,156 个文件 · 1,481.3 MB
基线: 13,156 个文件 · 1,481.3 MB      ⇒ 完全一致，零残留
```
并回后复核：`STORE_DIR` 解析正常、`run_task("health")` 正常、
store 文件数 **13,156 = 基线**、`data\store` 残留 **0 个文件**、空目录已清。

### 6.3 谁占着 store（实测）

```
PID 6204  python.exe  C:\Users\ADMIN\Desktop\GBT小土豆V8\gbt_allinone\deploy\codex_relay_watchdog.py --once
```
**是我们自己的看门狗脚本**（`codex_relay_watchdog.py`）。另外 `store` 根目录本身可写
（能建能删探针目录）⇒ 不是整棵树被锁，是**里面某些文件被按着**。
⇒ 结论：**store 只能在"我们自己的进程都不跑"的窗口里搬。**

### 6.4 教训（写下来免得重犯）

1. **`Move-Item` 不是原子的**：跨大目录树搬动可能"搬一半失败"。
   以后搬这种量级必须先算**总数基线**，搬完立刻对数 ——
   这次正是靠"13,156 vs 10,555+2,601"这个对账才发现搬残了。
2. **失败分支的提示话术不能拍脑袋**：我脚本里写的
   「（数据已在新位置，未挂 junction）」是**猜的**，真实情况是"一半一半"。
   凡提示语涉及状态，必须**实测后再打印**。
3. **junction 是这类搬家的正确工具**：路径不变 ⇒ 零代码改动 ⇒ 零破坏风险。

### 6.5 `store` 的正确搬法（等你不用面板时执行）

```powershell
# 前置：确认没有我们自己的进程在跑（尤其 codex_relay_watchdog）
Get-CimInstance Win32_Process -Filter "Name='python.exe'" |
  Where-Object { $_.CommandLine -like '*GBT小土豆V8*' } | Select-Object ProcessId,CommandLine

# 基线（必须先记下来对账）
(Get-ChildItem 'gbt_allinone\store' -Recurse -File -Force | Measure-Object).Count   # 应为 13,156

# 搬 + 挂 junction
New-Item -ItemType Directory -Force -Path data | Out-Null
Move-Item 'gbt_allinone\store' 'data\store'
New-Item -ItemType Junction -Path 'gbt_allinone\store' -Target (Resolve-Path 'data\store').Path

# 立刻对账（必须仍是 13,156；不是就并回去）
(Get-ChildItem 'gbt_allinone\store' -Recurse -File -Force | Measure-Object).Count
```
