## 一、🌟 最要紧的那半补上了：**WASAPI 回环（她真的能听见电脑在放什么）**

### 1.1 先抓核心资料，再动手

Microsoft Learn《Loopback Recording》读透，原文给了**两处关键改动**（照做，不自己发明）：

- `IMMDeviceEnumerator::GetDefaultAudioEndpoint` 第一个参数 `eCapture` → **`eRender`**
- `IAudioClient::Initialize` 第二参数 `StreamFlags` 从 `0` → **`AUDCLNT_STREAMFLAGS_LOOPBACK`**

另两条原文约束照录：**回环只能共享模式**（独占模式不行）；
Windows 10 1703 之前事件驱动回环收不到事件，**1703+ 已支持**（我们走轮询，对该差异免疫）。

### 1.2 为什么这条路是唯一可行的（先量后定）

| 依赖 | 本机实测 | 结论 |
|---|---|---|
| `sounddevice` / `pyaudio` / `soundcard` | **全无** | 常规采集库全不可用 |
| `waveInGetNumDevs` | **= 0** | **本机真的没有麦克风** ⇒ "听麦克风"根本不通 |
| `waveOutGetNumDevs` | = 1（`扬声器 (Realtek(R) Audio)`） | **扬声器在** ⇒ 只有回环能听见东西 |
| **`comtypes`** | **有** | ⇒ WASAPI 走 COM 可行 |

### 1.3 落成 `gbt_allinone/tentacle/wasapi_loop.py`（零新增依赖）

用 **comtypes 手写 COM 接口**（WASAPI 的接口在 `Mmdeviceapi.h`/`Audioclient.h` 里，
**没有 typelib**，必须自己按 vtable 顺序声明，顺序错一个就静默调错函数）：

`IMMDeviceEnumerator`(5 方法) · `IMMDevice`(4) · `IAudioClient`(12) · `IAudioCaptureClient`(3)
—— 每个接口都注明来源头文件；关键常量（CLSID / IID / `AUDCLNT_STREAMFLAGS_LOOPBACK` /
共享模式 / `REFTIMES_PER_SEC`）逐条列出。

### 1.4 🔴 实测证据（不是"应该能行"）

```
=== WASAPI 回环采集 1.2 秒（同时用 winsound 放一段 440Hz 音）===
  ok=True  verified=True
  格式: 48000 Hz / 2 声道 / 32 bit / block=8
  抓到: 57600 帧  1.200 秒  460800 字节
  峰值 = 32767 / 32767   均方根 = 17750.8
  >>> 判定: **听到声音了**（非静音）
  落盘: {"ok": true, "bytes": 460800}
  复读: 48000Hz / 2 声道 / sampwidth 4 / 57600 帧 / 1.2 秒 ✓
```

**这就是"耳朵"**：放音与采集同时进行，抓回来的 PCM 峰值打满、均方根 17750.8 —— 真听到了。

### 1.5 过程中的三次失败（都写进注释防再犯）

| # | 报错 | 根因 |
|---|---|---|
| 1 | `expected LP_GUID instance instead of _GUID` | 我自己定义了 `_GUID(Structure)`；**comtypes 只认它自己的 `GUID`** |
| 2 | `... instead of pointer to _GUID` | 改成 `byref` 反而更错 —— comtypes 对 `POINTER(GUID)` 参数**自动转换**，直接传实例就对 |
| 3 | `waveOutGetDevCapsW` 返回 11 | `WAVEOUTCAPSW` 漏了最后一个 `dwSupport` 字段 ⇒ `sizeof` 不对（上一步已修） |

### 1.6 接口（第 10 域 audio 现 10 个方法）

- **`audio_loopback(seconds, path)`** —— 听电脑在放什么（本机实测已通）
- **`audio_record(source="loopback"|"mic")`** —— `loopback` 走上面那条；`mic` **如实失败**
  （本机 `waveInGetNumDevs=0`）
- 回环**格式由系统定**（官方约束：必须与渲染端点一致）—— 调用方传的 `rate` **不许覆盖它**，
  只如实提示；有专门用例钉住这条
- `silent=True` 的语义**显式写明**：那是"此刻系统没出声"，**不是采集失败**
  （`verified=true` 才代表链路通了）

### 1.7 用例：`test_omni_audio.py` 13/13 通过

新增 3 条：回环**可验证**（`verified=True` + 格式合法 + 字节数是块的整数倍 + 落盘复读一致）·
回环**格式不许被强制** · `source` 不认时明确拒绝。

## 二、读图能力：**量清了，三条路都在**（下一步落地）

| 依赖 | 本机 |
|---|---|
| `PIL`（Pillow） | ✅ |
| **`pytesseract`** | ✅ |
| **`easyocr`** | ✅（深度学习 OCR，中英文） |
| `cv2`（OpenCV） | ✅ |
| **`winrt`**（Windows Runtime 绑定） | ✅ |
| `tesseract.exe` | ✅ `C:\Program Files\Tesseract-OCR\tesseract.exe` |

⇒ **"读取所有图片"完全可行**，且**三条独立后端可互为兜底**：
**winrt 的 `Windows.Media.Ocr`（系统级，零额外模型）→ `tesseract`（已装）→ `easyocr`（深度学习）**。
落地口径（下一步做）：`omni_image.py` —— 按顺序试后端、**报出这次是哪个后端答的**、
互相不一致时**如实标冲突而不是挑一个**、非图片/损坏图片明确拒绝。
⚠️ 注意：WinRT OCR 的 `AvailableRecognizerLanguages` 在本机 PowerShell 里没取到
（类型加载方式问题），需要用 `winrt` 的 Python 绑定重新验一次才算数。

## 三、翻译能力：**底数已量，需补一个模型或一条通道**

| 路线 | 本机现状 |
|---|---|
| `transformers` | ✅ **有**（但 `sentencepiece` / `ctranslate2` 无）⇒ 本地 NMT 需下模型 |
| `requests` | ✅ ⇒ 可走在线端点（需 key） |
| `argos` / `deep_translator` / `googletrans` | ✗ |
| 我们自己的 LLM 网关 `llm/unified.py` | 存在，但**当前无 LLM 密钥**（老目标里那条阻塞仍在） |

⇒ 诚实的落地口径（下一步做）：`omni_translate.py` 三层次 ——
① **我们自有的术语表/词条层**（确定性、零依赖，专有名词与固定译法走它，不交给模型瞎译）；
② **本地 NMT**（`transformers` 已有，需确认模型可获取）；
③ **LLM 网关**（有密钥时用）。
**三层都不可用时如实说"现在翻不了"，绝不编一个译文出来。**
