## 2. Scrapling → 触手（本轮唯一动手实现的一件）

### 2.1 它到底是什么（读源码后）

**不是"抓取库"那么简单**，值钱的是三块：
1. **自适应元素重定位**（皇冠）：页面改版后按**相似度打分**找回元素。
2. 反爬头指纹（`engines/toolbelt/fingerprints.py` 用 browserforge 生成真实浏览器头）。
3. 爬虫引擎（`spiders/`：checkpoint 断点续爬、cache、robots、scheduler、session）。

### 2.2 自适应机制的完整契约（这是我们重写的依据）

来源：`agent-skill/Scrapling-Skill/references/parsing/adaptive.md`（211 行，逐字读完）+
`scrapling/core/storage.py`（155 行）+ `scrapling/parser.py`（1398 行，53 处 adaptive）+
`scrapling/core/utils/_utils.py` 的 `_StorageTools.element_to_dict`。

- **两阶段**：Save（存特征）→ Match（按相似度找回）。
- **存什么**：元素（标签名 / 文本 / 属性名+值 / 兄弟标签名 / 路径标签名）+ 父元素（标签名 / 属性名+值 / 文本）。
- **怎么比**：不是相等，是相似度；**连值里的顺序都算**（class 书写顺序）。
- **键**：`(域名, identifier)`，identifier 默认取选择器串；SQLite + WAL + `UNIQUE(url, identifier)`。
- **它自己承认的缺陷**（写在文档 Known Issues）：**只存选区里第一个元素**。

### 2.3 我们怎么实现（已落盘）

新模块 **`gbt_allinone/tentacle/omni_web.py`**（573 行）—— `OmniWebMixin`，6 个方法：
`web_parse` / `web_select` / `web_save` / `web_adaptive` / `web_text` / `web_stats`。

**关键设计决定（都是有理由的）**：

1. **零第三方依赖。** 本机实测 **没有 lxml / cssselect / tld / browserforge / bs4**。
   所以解析器（`html.parser` → 自建轻量 DOM）与 **CSS 选择器子集引擎**全部自己写：
   支持 `tag / #id / .class / [attr] / [attr=v] / [attr^=$=*=v] / :nth-child(n) /
   :first-child / :last-child / *` 与后代(空格)、子代(`>`) 两种组合子。
2. **完全不出网。** 本域输入是"已经拿到的 HTML"，取字节那一步走框架**已有**的 `browser`
   能力位（受 `browser_control` 管）。**本域不新增任何出网路径** —— 门只有一处。
3. **相似度权重表是我们自己定的**（合计 1.00）：
   `tag .12 / id .10 / classes .16 / attrs .14 / text .20 / siblings .08 / path .10 / parent .10`。
   而且**每次判定都回传逐项明细** —— 出问题要能指出"是哪一项不像"，不许只给黑箱数字。
4. **分数不够必须认输。** `min_score` 默认 0.55，不达标就 `relocated: False` 并写清原因，
   **不拿一个"勉强像"的充数**。
5. **许可义务写进文件头**：BSD-3 只要求"用了它的代码"时保留声明 —— 我们没搬代码，
   仍在 docstring 里写明出处与作者。

### 2.4 ⚠️ 状态：已落盘、**未运行验证**

`omni_web.py`（573 行）与验收用例 `gbt_allinone/tests/test_omni_web.py`（15 个用例）**都已写在盘上**，
但**还没跑过一次** —— 因为本机进程派生这一层挂了（见 §7）。**不许当"做好了"。**
验收用例覆盖：Scrapling 文档里那个商品卡改版场景（改版后必须找回 `data-id=p1`）、
双胞胎卡不能选错、无关页面必须认输、域隔离、空选择器拒绝、两级后缀域名。

## 3. Cradle → 操控能力（提炼什么、拉黑什么）

### 3.1 定性

「**纯像素进、键鼠出**」的通用电脑控制参考实现：4 段半结构化文本提示词把 GPT-4o 串成
固定六段循环（采集→反思→推断→技能策展→规划→执行），靠 **SAM 自动分割生成
Set-of-Mark 编号**让模型点「编号」而不是猜坐标。**MIT，但上游已停更一年多**
（`d7752fcc`，2024-11-07）。

### 3.2 ✅ 值得提炼的（每条都有落点）

| # | 技术点 | 为什么值钱 | 我们怎么重写 |
|---|---|---|---|
| 1 | **SoM 编号化点击** | VLM 直接吐坐标精度差且**不可验证**；点编号则可校验 | 自研轻量 UI 元素检测 + **稳定 ID = 画面内序号 + 跨帧内容哈希**，模型只回 ID，坐标查表 |
| 2 | **非法 ID 硬拦截** | 防幻觉乱点 | ID 查不到 ⇒ **拒绝执行并回灌错误，绝不 fallback 猜坐标** |
| 3 | **像素差缓存 + 画面未变标记** | SAM 是最大成本/延迟瓶颈 | 帧哈希做缓存键；"画面未变"写进提示词作硬约束；同时当**循环停滞信号** |
| 4 | **占位符空值即丢整段** | 避免 `Last executed action: None` 污染提示词 | 自研模板引擎 `{{#if}}` 语义 + 首段自动成 system + **token 预算报告（它完全没有）** |
| 5 | **`resolution` = 图像档位而非像素尺寸** | 多图长循环的视觉成本控制关键 | 显式「图像档位策略表」：历史帧 low / 当前帧 high，纳入成本看板 |
| 6 | **三段式技能检索** | 纯向量会漏掉"刚学会的"与"当前界面必需的" | 场景标签过滤（硬）+ 向量 top-K（软）+ 最近使用加权 |
| 7 | **AST 解析参数而非字符串模板** | 比字符串替换安全 | **我们要更严**：JSON Schema + 类型白名单，**永不 eval/exec 模型输出** |
| 8 | **六段固定循环 + 每段 pre/call/post** | 长程任务能定位失败在哪段 | 保留分段，但每段可独立开关/重试 + 结构化 trace + **成功判定换成显式任务断言** |

### 3.3 ⛔ 必须拉黑的（它最大的问题）

**它确实能操控电脑，而它没有沙箱、没有确认机制**：`sandbox.py` 404、`permission.py` 404、
无 approval/confirm/consent、无 HITL 断点、无回滚、无动作级审计账本。
唯一的 "Action Denied" 只是**把这一步注释掉**（防点关闭按钮，且默认关闭）。

四条高危路径：
1. **模型生成的代码直接 `exec`**（`register_skill_from_code`）⇒ 屏幕/网页内容 = 间接提示注入 → **RCE 完整链路**；
2. 屏幕内容即不可信输入，**零 prompt-injection 防护**；
3. 技能持久化成含 `dill` 序列化函数对象的 JSON ⇒ **`dill.loads` 反序列化本身即代码执行**，文件被换就是后门；
4. 无动作级审计。

> **对我们的意义**：我们的红线（`run_task` 唯一门 + 主人终端发授权 + `security/policy.py` +
> 镜像/房间先排练 + `shape_bytes`）**恰好补上 Cradle 的全部缺口**。
> 提炼操控能力时**必须把它缺的这层门加上，绝不把它的自由执行风格一起搬过来**。

另：**「自动新增技能」这条自我改进回路，在软件环境上根本是死的** ——
`cradle/runner/app_runner.py` 里 `def run_skill_curation(self): pass`，
而 `all_generated_actions` 的唯一写入点在 RDR2 专用后处理里。
**别照抄一个只在游戏上通了的回路。**

## 4. 协作电影生成（seedance + html-video + LTX-2）

### 4.1 三层分工（各自只干一件事）

| 层 | 用什么 | 只干这件事 |
|---|---|---|
| **A 导演层** | seedance-2.0 的**协议**（蒸馏，不装 skill） | 想法 → 可续拍的**状态机** + 当前片段 prompt。它不出画面 |
| **B 生成层** | LTX-2（本地）或外部 API | **出声出片的唯一来源**（唯一能音视频同步一次生成） |
| **C 程序化层** | html-video | 字幕 / 图表 / 标题卡 / 数据动画 / 片头片尾 —— 零 GPU、零按次费、完全可复现 |
| **D 门禁层** | 我们自己的镜像/房间/授权体系 | 一切写动作走门；成品过验证矩阵才允许晋升 |

### 4.2 阶段与交接物（关键：每段都有落盘产物，不靠对话记）

```
想法 → ① 导演读解 & 序列规划   → film-state.json（story/world_bible/scenes/beats/clips）
     →                             capsule.md（<50 行，跨会话可交接）
     → ② 引用权威分配           → reference_registry[] {tag, role, preserve_exact_tag:true}
     → ③ 当前片段任务单          → clip-contract.json（already_happened / this_clip_only / reserved_for_later）
     → ④ prompt 编译            → prompt.md（纯自然语言）+ prompt-spec.json（内部元数据，不进 prompt）
     → ⑤ 生成（LTX-2）          → take_<clip>_<n>.mp4（含 24 kHz 立体声）
     → ⑥ 抽帧 & 观察            → observed_start/end_state + confidence + uncertainties
     → ⑦ 审片裁决               → take-review.json（accept / accept_with_deviation / repair / reject）
     → ⑧ canon 调和             → state_revision++ / canon_revision++，已完成 beat 从未来删除
     → ⑨ 程序化包装（html-video）→ content-graph.json（nodes + edges + 拓扑排序）→ 字幕/图表轨
     → ⑩ 合成 + 门禁            → 验证矩阵 → run_task 显式声明落点
     → 成片
```

### 4.3 最值钱的五个协议（照抄字段与不变量，不抄实现）

1. **三文件状态机**：`project-state` / `clip-contract` / `take-review` 三分离，各带 required 字段与枚举。
2. **beat 三桶防泄漏**：`already_happened[]` / `this_clip_only[]` / `reserved_for_later[]` ——
   编译 prompt 时只写 `this_clip_only`，另两桶作**排除清单**显式写进 prompt。
3. **canonical vs transient 双源分离**：canonical 参考管**身份**；已接受素材只管**瞬态开场状态**。
   ⇒ 身份不会被上一段输出逐代污染。
4. **观察诚实性协议**：`observed_*_state` 优先于 planned；强制
   `observation_confidence ∈ {low,medium,high}` + `requires_user_confirmation` + `uncertainties[]`。
   ⚠️ 它自己承认 `observation_confidence` 是"置信轴不是来源轴" —— **我们要额外加一个 provenance 字段，这是能超过原版的地方**。
5. **三重校验缺一不可**：schema 校验（record 内部）+ project-state 校验 + **continuity 图级血缘校验**。
   它的原文说得对：`Schema success is therefore not graph validation.`
   ⇒ 与我们 `regression_stamp` 四元组印章是同一思路。

### 4.4 我先前的一个措辞错误，必须纠正

「quad-modal（四模态）」**只出现在仓库的 GitHub 描述与 `CHANGELOG.md:489`**，

### 4.5 LTX-2 的硬约束（比 GPL 还细，必须逐条记住）

- **§2.1 收入门槛**：年营收 ≥ **$10,000,000** 的实体**任何使用**都要买付费许可；
  §1.6 规定**子公司/关联方合并计算**。

### 4.6 seedance 侧两个"反预期"事实

### 5.1 定性

## 6. openhuman → 借鉴还是复刻（明确回答）

### 6.1 硬事实

- **GPL-3.0-only**：`LICENSE` 全文 34,886 B = 标准 GPL-3.0；
  `Cargo.toml` 显式 `license = "GPL-3.0-only"`，并注明 *"Declared explicitly as `only` — not `or-later`"*。
- 形态：**Rust 为主的 Tauri v2 桌面单体**（Python 仅 33 KB）；core 以 tokio 任务**同进程**嵌入。
- **插件 = 10 个 first-party `cdylib`**，编译期注册表白名单 + 下载 + SHA-256 校验 + `dlopen`。
  **它自己的文档把隔离问题写死了**：
  > `A loaded module shares this process's address space, privileges, and crash domain — it is first-party code that happens to ship separately, not a sandbox boundary.`
  > `Untrusted code belongs in a separate process, not in a module.`

### 6.2 结论：**借鉴重写，不复刻**

理由（法律层面）：
- GPL **§5(c)** 要求「整个作品整体」按 GPL 授权（`regardless of how they are packaged`）
  ⇒ 我们的闭源实现必须**整体** GPL。
- GPL **§1** 明确把 *"the source code for shared libraries and dynamically linked subprograms
  that the work is specifically designed to require, such as by **intimate data communication
  or control flow**"* 算作 Corresponding Source。
  而它的模块**共享地址空间、权限与崩溃域、永不卸载** —— 这是"intimate data communication"的
  教科书案例，**它自证不是 aggregate**。
- ⇒ **"把 GPL 代码混进我们的闭源实现"这条红线它自己就踩不过去。**

**借鉴合法**：GPL 覆盖**表达**不覆盖**思想/架构/协议/接口**。
但红线很具体：**不能抄 README/gitbooks 的行文、代码注释、agent prompt 文案、
`SKILL.md` 内容、字段名与路径命名**。
落地纪律：**读它的文档 → 写自己的设计说明 → 关掉参考文档再写代码**，并保留差异说明。

**如果哪天要引它的模块**（可选、非必须）：必须**独立进程 + 标准接口（JSON-RPC/HTTP）+
只调用未修改的官方二进制 + SHA-256 白名单**，且该模块自身仍按 GPL 提供源码。
⚠️ **最容易踩的坑：为了接线去 patch 它的源码** —— patch 之后你就是 modifier，必须按 GPL 发布改动。
**这条路要从制度上封死。**

### 6.3 最值得学的 7 点（含落点）

1. **命令分类学 + 三层自治 + 10 分钟 TTL + fail-closed**：
   五类命令 × 三层；`Unknown commands classify as writes`；`Every non-approve path resolves to Deny`
   （超时/持久化失败/通道断开**全部=拒绝**）；决策落 SQLite **跨重启存活**。
   ⇒ 把我们"缺授权=拒绝"升级为**显式三态 Allow/Prompt/Block**，补上我们最弱的**超时即拒绝**与**跨重启**语义。
   ⚠️ 但**不要**照抄它"后台/cron 回合绕过门"那一条 —— 我们的 `run_task` 唯一入口比它严格。
2. **只有编译期注册表能选装载物 + 摘要逐字固定**：
   > `Never compute a replacement digest from a local build — that would make the check agree with whatever was served instead of with what the release published.`
   ⇒ 硬规则：**任何外部二进制/插件入白名单，必须固定 release 侧 checksum，禁用本地重建摘要顶替。**
   这条直接对应我们 2026-09-19 那次"绕过授权门"的教训。
3. **路径加固：沙箱失效不豁免检查**（`Rust path checks still apply if the sandbox falls back.`）
   + 明令 *"Do not weaken ... to make a feature work."*
   ⇒ 补一条断言：**沙箱/房间隔离失效不构成检查豁免**。
4. **可插拔沙箱后端 + 运行时探测 + 后端入审计**（Docker→Bubblewrap→Firejail→Landlock→Noop）
   ⇒ 把"隔离强度"做成**可探测的降级链**，并把**当前实际后端写进审计** ——
   这样 `not_comparable` 时我们能解释"为什么这次读数不一样"。
5. **授权/审计三件套 + 稳定错误分类**（按 `kind` 分支，`never on message regexes`）
   ⇒ 跨口径 `not_comparable` 时**按 kind 逐名比对**，而不是判"代码坏了"。
6. **生成式文档 + 漂移看守**（`check-feature-forwarding.mjs` 专治"feature 没转发就静默失效"）
   ⇒ 加一致性守卫：**能力位必须有 handler、必须有 policy 作用域、必须在文档里出现**，三者缺一即失败。
7. **风险上限是运行时策略、不是常量**（ActionTracker / budget / risk caps）
   ⇒ 作用域授权升级为"作用域 + 配额 + 会话计数"。
