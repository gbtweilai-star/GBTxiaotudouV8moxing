## 二、条② `retry_hint` 真被用上：**按病因决定重不重、重几次**

新增 `RETRY_POLICY`（每类病一条：`max_attempts` / `action` / `why`）与 `retry(fn, ...)`：

| 病因 | 最大重试 | 动作 |
|---|---|---|
| `element_not_found` | 3 | `scroll_and_refind`（多半在视野外，先滚动再重找） |
| `stale_target` | 3 | `refetch_target`（界面重绘了，别复用旧引用） |
| `modal_blocked` | 2 | `dismiss_modal`（先关弹窗再重发） |
| `timeout` | 2 | `wait_longer`（改判据或拉长等待） |
| `action_no_effect` | 1 | `compare_frames`（先确认到底动没动） |
| `window_lost` | 1 | `reenumerate_windows` |
| **`backend_unavailable`** | **0** | `stop_and_report`（不是重试能解决的） |
| **`denied_by_gate`** | **0** | `stop_and_report`（**重试就是绕门**） |

实测：

```
element_not_found ：attempts=3 recovered=True trail=['scroll_and_refind','scroll_and_refind']
denied_by_gate    ：attempts=1 retried=False **实际调用次数=1**
   stopped_because = 策略禁止重试（**被门拒绝不许重试** —— 重试就是绕门的开始，如实上报缺哪个 scope）
backend_unavailable：实际调用次数=1（不许重试）
```

重试过程中**病变了就按新病重查策略**（不是死守第一次的判据）；每次重试都进病因账。

## 四、我自己又制造并当场修掉的**两个 bug**（同一类病，必须留档）

### bug A：接口在、链路断 —— 落盘写了 0 行

我写了 `_persist()` 却**从来没调用它**：`record_swallow` 只往内存环形缓冲塞。
`attach_log` 返回 `ok:True`、文件也建了，**但一行都没写进去**。

修法：收成一个**唯一记账口** `_note(row)`（进内存 + 落盘），三处记账全部改走它 ——
**谁都别绕过它记账**。

### bug B：静默失败 —— 钩子链压根没跑

`from hook_registry import …` 是**顶层导入**，而它在 `gbt_allinone/tools/` 下、
不在触手目录的 `sys.path` 上 ⇒ 导入失败 ⇒ 被我的 `except: pass` **吞掉** ⇒
`hooks=None`，而我可以照样报"已接线"。

修法：`_hr()` 三级稳健获取（包路径 → 顶层名 → **按文件路径直接加载**），
并且 `fire_failure_hooks` 的兜底**不再静默**：把失败原因写进 `hooks.why_not`
并记进病因账。

> 这两个 bug 与第9步的「假收口」是**同一类**：**表面绿、链路断**。
> 判别它们的方法始终是同一问：**这个字段/这条链，真的被生产路径走过吗？**
> 现在我给每一条都配了会红的断言（见 §五）。
