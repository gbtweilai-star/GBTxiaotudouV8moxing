关键澄清：「2D 显示不出特别之处」的担心，方向反了

调研结论很明确："活的感"不来自 2D 还是 3D，而来自动作质量、物理反馈和性格设计。

  • 真·写实数字人（DUIX/EchoMimic/HeyGem 这类"视频流数字人"）：本质是视频帧生成管线——常驻 GPU 推理风扇狂转、必须 NVIDIA 显卡（本机是 AMD RX 6500M，直接出局）、真人数据训练做不出二次元美少女、Windows 桌面端连现成 SDK 都没有。这是"能走但没必要"的路。
  • Live2D 骨骼动画：呼吸、眨眼、头发裙子物理摆动、撒娇动作、部件级点击反应（点她头会有专门反应）、情绪表情——全部有现成 API；渲染几乎不吃 GPU；全球 13.7k star 的 Open-LLM-VTuber 已用这条路线做出了完整的桌宠模式，证明"住在桌面的活人感"完全成立。
  • 她"来自未来的小孩 + 顶尖编程 AI"的气质，靠人设 Prompt + 动作编排 + 专属音色塑造，而不是靠渲染管线。

为什么选 PySide6 + live2d-py 而不是 Open-LLM-VTuber 直接用？

方案内存常驻定制自由度结论
Open-LLM-VTuber（Electron 前端）80–250MB受前端自定义许可限制（非商业）备选·快速验证
PySide6 + live2d-py 自研30–80MB形象/面板/行为/工具全链路自主主方案·推荐

本机 8GB 内存 + 已有大量常驻服务，轻量是硬指标；且全息面板、行为编排这些你的核心诉求都需要深度定制，自研壳子 + MIT 开源渲染库是自由度最高的组合。Open-LLM-VTuber 作为参考实现与兜底方案保留。

五、风险与未知项（诚实清单）

  • Live2D 商用授权：个人自用完全免费；未来若商业化，Cubism SDK 对中大型企业有授权门槛（年销售额 ≥1000 万日元）——当前场景无风险
  • edge-tts 属非官方接口：有 403 风险 → 设计三级自动降级，SAPI 永久兜底
  • 逐像素点击穿透：整窗穿透是原生能力，"只穿透明像素、身体可点"需 HitTest + 动态切换验证（预计可解，列为实测项）
  • GLM 免费政策变动：模型名做成配置项，主备热切换（4.5/4.7/5.3-Flash 三选一）
  • 60fps 与内存实测：live2d-py 性能基于架构推断，开工第一步就在本机实测
  • 音画同步延迟：TTS 流式与口型对齐需要缓冲设计，属打磨期问题
