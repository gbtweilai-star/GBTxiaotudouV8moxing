## 一、做了什么

在 `holo_pet/panel_server.py` 里**新建「设置」面**，密钥配置作为它**第一组**内容。

### 1.1 两个出口（遵守单一来源纪律，注册表 + 真实路由两处同步）

| 出口 | 方法 | 作用 |
|---|---|---|
| `/api/settings` | GET | 设置面读数（分组）。密钥组：探活 + 供应商已配/未配；**绝不下发明文密钥** |
| `/api/settings/action` | POST | 写动作 `op`：`probe / login / logout / providers / add_key / health` |

> 为什么是两条路径而不是同路径 GET+POST：`test_app_surface_matches_real_routes`
> 用**路由集合**对账并断言 `len(declared) == len(APP_SURFACE)`，
> 同路径两条会被判「APP_SURFACE 里有重复路由」。
> 按仓里既有惯例改开子路径（`/api/observer` 与 `/api/observer/voice` 就是分开的）。

### 1.2 设置面四组（密钥只是第一项）

| 组 | 状态 | 内容 |
|---|---|---|
| **密钥** | **已接** | FreeLLMAPI 探活 + 34 家供应商已配/未配 + 现场登录 + 加密钥 + 健康检查 |
| 模型与算力 | `pending`（如实标未建） | L1 官方独立口 / L2 免费池 / L3 本地 |
| 本体 | `pending` | 窗口 / 屏幕 / 输入 / 进程 |
| 变压器 | `pending` | 压缩与快速输出开关 |

`pending` 是**如实标"未建"**，不是假入口 —— 沿用仓里 `APP_PENDING` 的既有精神。

## 二、三条纪律（写进方法体，防止后来人放宽）

1. **绝不下发明文密钥**：任何密钥只回 `mask()` 过的打码值。
2. **不落盘 dashboard 密码/会话**：token 只活在内存 `self._ffl_token`，进程一停即失效；
   连登录返回里都把 token 抹成打码指纹（只回 `token_fp`），免得漏进日志或前端。
3. **没登录就如实说没登录**，不假装拿到了供应商清单。

`add_key` 还有一条：**写完必须过健康检查**，验不过就明说「已写入，但**健康检查没过** —— 不算配好」。

```
② op=probe -> ok=True，探到真服务
③ 未登录就 add_key -> {"ok": false, "status": 401,
                       "error": "还没登录 —— 先 login 再操作（密码不落盘）"}   ✔ 拒绝
④ login 用假密码 -> 真打到服务端，返回 "Invalid email or password"
   · 返回值含明文密码? False        ✔ 不泄露
   · 内存里存了吗?   False          ✔ 失败不残留
   ⇒ 证明**登录链路是通的**，只差主人的真凭据
⑤ 未知 op -> {"ok": false, "error": "未知设置动作 '乱来'", "supported": [...]}   ✔
```

> ④ 这条很关键：它同时证明了**链路通**与**不泄露**两件事。

## 四、顺手抓出并修掉的一个真 BUG（我自己的）

### 4.1 能力球的能量传输动画**从来没通过**

补登记 `/api/recent-calls` 时，双向对账测试把我拦下了，顺藤摸到：

- `capabilities.html` 用 `fetch('/api/recent-calls', {cache:'no-store'})` ⇒ **GET**
  （它自己的注释也写着「数据源：GET /api/recent-calls」）
- 但处理器被我写在了 **`do_POST`** 里（`panel_server.py:3241`，属于 L3160 的 `do_POST`）
- ⇒ **GET 请求根本没有分支接它**，那个动画**一次都没亮过**

**我此前说"已把能量传输动画接到 /api/recent-calls"是没端到端验过的声明。**
这正是「反假执行」要防的东西：字面量在、语法绿、看着像接好了，实际不通。

**修法**：挪到 `do_GET`（只读口本就该是 GET），并加 `getattr` 兜底。

### 4.2 同时补上两个漏登记的件
- `/api/recent-calls` 本身漏进 `APP_SURFACE`（本会话早先加出口时漏的）
- `_FakeBridge` 缺 `settings` / `settings_action` 桩 —— 该测试文件自己的注释就写着
  「**桩必须跟着真接口长**，否则 `test_every_declared_route_actually_answers` 会红
  —— 那正是这条门存在的意义：声明了就必须真能应答」

### 那 1 个失败：**跨文件测试污染，不是本次改动引起的**

```
FAILED G4OwnerSessionTests::test_eigenflux_send_marks_owner_session_at_runtime
E  AssertionError: 本用例要求进程未全局置位 GBT_OWNER_SESSION，否则正负对照失去判别性
```

**根因（直接证据）**：`gbt_allinone/tests/test_codex_bridge.py:15`
```python
os.environ["GBT_OWNER_SESSION"] = "1"      # ← 模块级！导入即置位
```
pytest 在**收集阶段**导入所有测试文件 ⇒ 这个全局 env 漏给面板测试。

**隔离实验（证明是收集期污染）**：
- 面板单独跑 → 3 passed
- 面板 + codex桥（且 `-k` **反选掉所有相关用例**）→ 仍然 failed
  ⇒ 与用例执行无关，是 import 时就污染了
- 面板 + 知识库 → passed

**顺带确认 `_owner_session()` 本身是对的**：`policy.py:88-93` 有 `finally: _TRUSTED_OWNER.reset(token)`。

**建议修法**（我**没擅自改**，因为它动的是别人测试的语义）：
把 `test_codex_bridge.py:15` 的 env 置位从模块级挪走 ——
要么放进 subprocess 隔离，要么让框架**惰性读**这个 env，要么在 conftest 里
saved/restored 包一层。**这条留给 Owner 定。**
