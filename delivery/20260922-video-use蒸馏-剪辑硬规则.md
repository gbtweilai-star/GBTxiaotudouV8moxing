## 二、蒸馏：它教的东西里，真正值钱的是那 9 条硬规则

它的定位是一句话：
> **Edit any video by conversation.** Transcribe, cut, color grade, generate overlay animations…

### 2.1 七条原则（值得抄的是第 2、3、7 条）

| # | 原则 | 对我们的意义 |
|---|---|---|
| 1 | LLM 只依据**原始逐字稿 + 按需画面**推理 | 不预生成一堆中间产物 |
| **2** | **音频为主，画面跟随**（切点来自语音边界与静音间隙） | 剪视频的**判据是音频**，不是画面 —— 反直觉但正确 |
| **3** | **问 → 确认 → 执行 → 迭代 → 持久化**；**用户确认前绝不动刀** | 这就是我们的**门纪律**：未授权不动生产 |
| 4 | **不要假设**这是什么类型的视频；看素材、问用户 | 零猜测律 |
| 5 | 艺术自由是**默认**（具体数值不该被写死） | 与"参数化"相反：给方向不给死值 |
| 6 | 素材需要没写过的技法时，**自由发明** | 不把 skill 当封闭清单 |
| **7** | **先验证自己的产出，再拿给人看**；"你不上架的东西，就别present" | **这就是我们的五维合一 verify**，一字不差的意思 |

### 2.2 九条硬规则（**真正的干货：静默失败陷阱**）

它自己写明「These are the things where deviation produces **silent failures**」：

| # | 硬规则 | 为什么是坑 |
|---|---|---|
| 1 | **字幕最后加**，在任何 overlay 之后 | 否则 overlay 会盖住字幕 |
| 2 | **分段抽取 → 无损 `-c copy` 拼接**，不要单趟 filtergraph | 单趟会**重新编码**，画质掉 |
| 3 | **每个接缝加 30ms 音频淡入淡出** | 不加就有**爆音** |
| 4 | overlay 用 `setpts=PTS-STARTPTS+T/TB` 对齐窗口起点 | 否则 overlay 从错误时刻开始 |
| 5 | 主 SRT 用**输出时间轴**偏移（`word.start - segment_start + segment_offset`） | 用输入时间轴 ⇒ **字幕整体错位** |
| 6 | **绝不在词中间切**，切点吸附到词边界 | 切在词中 ⇒ 半个字 |
| 7 | **每个切边都要 padding（30–200ms）**：原文「Scribe 时间戳漂移 50–100ms，padding 吸收它」 | **诚实承认 ASR 有误差**，不假装精确 |
| 8 | **只用词级逐字 ASR**，绝不用 SRT/短语模式（丢亚秒间隙数据）；绝不做"规范化" | 规范化 ⇒ 丢了切点判据 |
| 9 | **逐字稿按源缓存**，除非源文件变了才重转 | = 我们**最低能源律**（不重算） |

**三条与我们已有的律直接同构**：
- 第 7 条「承认漂移并留余量」 ≈ 我们的**零猜测律**（不假装精确）
- 第 9 条「按源缓存」 ≈ **最低能源律**
- 原则 7「先自验再示人」 ≈ **五维合一执行律的 verify**
- 原则 3「确认前不动刀」 ≈ **门纪律**

## 三、它和我们已有的 `html_video.py` 什么关系

| | 我们的 `html_video.py` | video-use |
|---|---|---|
| 输入 | **HTML/CSS/数据** | **已有视频**（转录 → 剪 → 调色 → 叠动画） |
| 输出 | MP4 | MP4 |
| 强项 | 从零**生成**动画 | 对**既有素材**做编辑 |

**⇒ 不是替代，是互补**：一个**造**，一个**改**。
对 Owner 的目标①（短视频/电影车间）来说：
- 做**新片** → 我们的 `html_video.py`
- 剪**已有素材**（访谈、口播、录屏）→ 蒸馏 video-use 的那套硬规则
- 它的 `manim-video` 子技能（17 个参考文档：动画设计/公式/相机3D/渲染/分镜/视觉设计/排错）
  是**数学与数据驱动动画**的成套知识 —— 与"数据图短视频"直接对口

## 四、建议落地形态（**未实施**）

**不装它**（MIT 也不要抄代码），而是**把它的硬规则变成我们自己的视频工具里的"必过检查"**：

```
gbt_allinone/tools/html_video.py  ← 已有（造）
      +
一个"剪辑硬规则检查器"（新）：
  · 输入：一条 ffmpeg 命令 / 一个 filtergraph
  · 按那 9 条逐条查：
      - 有没有在 overlay 之前加字幕？          → 报
      - 是不是单趟 filtergraph 而不是 -c copy 拼接？ → 报
      - 接缝有没有 30ms afade？                 → 报
      - 切点是否吸附到词边界 + 有没有 padding？  → 报
  · 每条带**稳定规则号**（沿用 skill_vetting 那套）
```

**为什么这么做**：那 9 条全是**静默失败** —— 错了不会报错，只会出个"看着还行但其实是坏的"片。
**这正是我们最该防的**（反假执行）。
**判据**：拿一条**故意违反**的 ffmpeg 命令，检查器必须报出对应规则号。
