## 二、装包钩子面（`prepare` / `postinstall` —— 装的时候就会跑的东西）

| 包 | 装包时会跑的脚本 | 判定 |

| `dshmarket` | `prepare = npm run build`（tsc + tsdown）· `prepack = npm run build && node scripts/preflight.mjs` | ⚠️ **从 git 装会跑 `prepare`（编译）**；装 npm 发布物则不跑。**没有 postinstall** |

**没有发现任何一个包带 `postinstall`。** 这是关键的一条 —— 上一轮 Ark CLI 那种"装完自动跑钩子"的情况，这三个都没有。

## 三、权限面（**还没读** —— 读完才装）

三者都用同一套机制声明自己改运行时哪些缝：

```json
"dsh": { "bundle": { "patch": "./cordis.patch.yml" } }
```

⇒ **`cordis.patch.yml` 就是它们的真实权限面**。三个包的这份文件**必须逐个读完**，
看清：改哪些 seam、是否注入 `tools/pre-execute`、是否碰凭据/网络/文件系统、是否 hook 审批门。

| 包 | client 注入声明 | 含义 |
|---|---|---|
| `dshmarket` | `inject: [client-locale, client-ui-settings, client-ui-theme]` · platform `web` | 进设置页 + 主题位（与我们的面板同域，需查是否抢插槽） |
| `@liustack/modlens` | `inject: []` · platform `web` · **`immediately: true`** | ⚠️ **立即加载**：启动即生效，权限面更要看清 |
| `dsh-click` | 无 client 注入（纯宿主侧） | 桌面控制走宿主侧 |

- 它与我们已有的 `desktop_control` 授权门是**同一条边界** ⇒ 要确认它**不会绕过我们的门**。
