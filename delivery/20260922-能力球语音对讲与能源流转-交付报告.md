## 一、语音对讲（链路：听 → 想+做 → 说）

| 环节 | 用什么 | 为什么 |
|---|---|---|
| **听** | 浏览器 `webkitSpeechRecognition`（Chrome 内建，中文） | 我们自己的 `voice_cap.asr()` 在**未配后端时会如实返回 `needs_dependency`、不伪造识别**——所以不在框架侧硬凑，用浏览器识别 |
| **想 + 做** | `POST /api/message` → `bridge.send(text)` → **大脑** | 面板既有出口；**能力调用一律由大脑经 `run_task` + 门** |
| **说** | 浏览器 `speechSynthesis`（零依赖） | 不需要新后端 |
| **回复** | `/api/events`（SSE）里带 text/reply 的事件 | 面板是「受理即回、回合在后台跑」，所以答案从事件流回 |

### 三条自律（写进代码，与本文件既有气质一致）
1. **拿不到就说拿不到**：没识别 API / 没麦克风 / `file://` 打开 ⇒ 按钮直接显示「语音对讲（受限）」并写明**缺哪一条**，不给一个会转的动画冒充"在听"。
2. **不伪造识别**：识别为空就**不往大脑发东西**，并明说「没听清——没往大脑发东西」。宁可空手，不编一句话去喂大脑。
3. **执行走大脑**：本页**不自己执行任何任务**，只把话交给面板。

## 二、能源流转特效（沿连线通电）

### 判据用 `HEAT`，不是我编的动画
`HEAT[kind]` 是「这个能力**被真正调过**」留下的余温，数据来自 `/api/recent-calls`
的**真实调用记录**（`store/audit.jsonl`）。而且它**随时间衰减**（`HEAT[k]*=0.972`）。

⇒ 由此得到三条自洽的行为：
- **没有热度的连线 = 死线**，一格电都不给（不给"假装在忙"的动画）
- **有热度的连线 = 通电**，能量从**冷端流向热端**（谁在干活，电就往谁那儿跑）
- **任务跑完、余温退去，电流自己消失**，不会永远亮着骗人

### 实现
在 `LINKS.forEach` 里，画完静态连线后追加：
- 每段 3 颗流光，相位 `(_T*0.55 + s/3) % 1` 随时间前进 ⇒ 真的在流动
- 时间源用 `performance.now()/1000` —— **注入确定性时钟时也跟着走**，所以渲片里同样能定住
- 热端再给一圈「到达光环」，让"跑到头了"看得见
- 透明度/半径都乘热度 `hh`：热度越高越亮，退温就淡出
