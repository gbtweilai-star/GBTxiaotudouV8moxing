## 二、设计

### 2.1 存储分类（先接上 Owner 的第一步：储存空间分类好）

知识库落点固定在框架 store 下，**不散落**：

```
gbt_allinone/store/knowledge/          ← 自进化知识库根（新增）
├── raw/                               ← 原始留痕（只追加，永不改）
│   └── YYYY-MM/YYYYMMDD-HHMMSS-<src>-<hash8>.json
├── techniques.jsonl                   ← 蒸馏出的技术要点（一行一条，可 grep）
├── own_voice.md                       ← **我们自己的输出方式**（衍生结果）
├── energy.json                        ← 自我能源补给度量（可证伪）
└── index.json                         ← 去重索引 + 统计
```

为什么放 `store/`：`gbt_allinone/store` 在待清清单里已被归类为
「框架运行时数据（有独立管理）· **不可清**」，落这里天然不会被误清。

### 2.2 模块：`gbt_allinone/knowledge_base.py`（新增，纯库）

四个动作，对应 Owner 四个词：

| Owner 的话 | 动作 | 说明 |
|---|---|---|
| 记录大模型的技术输出 | `deposit(record)` | 把 Codex/LLM 的技术输出原样落 `raw/`，带全溯源 |
| 提升自己、进化自己 | `digest()` | 从 raw 蒸馏出技术要点 → `techniques.jsonl` |
| 衍生出自己的输出方式方向 | `derive_voice()` | 归纳出**我们自己的输出方式** → `own_voice.md` |
| 自我能源补给 | `energy()` | 算出"补给量"= 新增条目 + 新蒸馏要点，**为 0 就报 0** |
| 自主输出、动脑输出 | `pulse()` | 一步跑完上面四步，供万能插脉冲调用 |

### 2.3 反假执行（这是全篇的底线）

1. **无溯源不收**：`deposit()` 必须拿到 `source`（谁产的）+ `sha256`；
   拿不到就**拒收并如实报错**，不许编一条空记录充数。
2. **不许假成功**：`digest()` 若一条也蒸不出，返回 `{"digested": 0, "reason": ...}`，
   **不是** `{"ok": True}`。
3. **能源不能注水**：`energy()` 读的是**磁盘上真实条目数**，不是计数器变量。
4. **保留 `stage_errors`**：沿用 `devour_pulse()` 2026-09-22 的修法 ——
   哪段挂了要能从返回值里看出来，不许跟"真的没有"长得一样（`devour.py:1140-1167`）。

### 2.4 提速三改（对应 G1 / G2）

| 改 | 做什么 | 为什么安全 |
|---|---|---|
| **S1** | `run_once()` 改用 `get_shared_server()`，跑完**不停**共享连接 | 与 `api.py:830-855`、`panel_server.py:728` 现有用法一致；30 个用例兜底 |
| **S2** | `run_once()` 把逐字增量**交出去用**（喂知识库），不再丢 | 只是多一个回流，不改返回值契约 |
| **S3** | 万能插加第 7 个操作 `pulse`，内部调 `knowledge_base.pulse()` | 万能插本来就是"并行编排"，脉冲是它的心跳 |

**S1 的爆炸半径（先量后改）**：
- `run_once` 调用点只有 2 处：`api.py:844`（生产路由）、`tests/test_codex_bridge.py:326,340`（测试）。
- `get_shared_server` 已有 4 处生产调用（api 3 处 + panel 1 处）。
- ⇒ 改动面小，且有 30 个用例（`test_codex_bridge.py`）守着。

### 2.5 门纪律（绝不越权）

- **不新增未登记 kind**。知识库不自己开 kind，而是**挂在已有的 `devour_pulse` 上**
  —— 那个 kind 在 `policy.py:271` 已有正式门（`data_export` + `filesystem_write` + `external_llm`）。
- 万能插的 `pulse` 操作走 `gbt_universal_plug` 既有工具路径，**需要主人会话**
  （现有 `op == "run"` 就是这么做的：`codex_bridge.py:1110` `with _policy.owner_session():`）。
- **绝不改 `security/policy.py`**；**绝不给自己发授权**。
- 若 Owner 想要一个独立的 `knowledge` kind，那需要他本人在 `policy.py` 加分支 ——
  我会**如实报缺**，不绕。
