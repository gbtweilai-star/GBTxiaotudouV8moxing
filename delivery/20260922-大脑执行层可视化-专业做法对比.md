## 二、逐条对比：我哪里对、哪里缺

### 2.1 我对上的四条

| 专业做法 | 我的设计 | 判定 |
|---|---|---|
| **分层/层次布局**（nnScheme、visualtorch 都是分层块图） | 四层分区：核心五维 / 同层能力 / 底座支撑 / 触手效应器 | ✅ 方向一致 |
| **有向流动用粒子/尾迹表示** | 起点暗→终点亮 + 硬芯 + 实心亮头 | ✅ 一致 |
| **状态与结构分开编码**（结构静态、状态动态） | 结构是分层位置；状态来自真实调用（HEAT 同源） | ✅ 一致 |
| **聚合，不把 158 条边全画出来** | `route → 「158 项能力」` 画成一个聚合节点 | ✅ 一致（这条我原本只是顺手做对了） |

### 2.2 我缺的五条（专业界有，我没有）

| # | 缺什么 | 专业界怎么做 | 为什么必须补 |
|---|---|---|---|
| **1** | **边捆绑（edge bundling）** | 边一密就按层次把边捆成束（[TP-Bundle](https://ieeexplore.ieee.org/abstract/document/11402527)、[多层次聚合捆绑](https://ieeexplore.ieee.org/document/5742389/citations?tabFilter=papers#citations)） | 我的图里 `route` 一出就可能连出几十条（域→能力）。不捆 ⇒ 变成我在能力球测试副本里看到的那种"毛躁一团" |
| **2** | **渐进披露 / 下钻** | 先看域的聚合，点开才展开明细 | 我只有"全画"或"不画"两种，没有中间态 |
| **3** | **每个视觉变量配图例** | 颜色/大小/亮度/线型**各管一个变量**，且各有图例 | 能力球有图例（形态即状态…），**大脑图我还没写**。没图例的编码等于没编码 |
| **4** | **邻接矩阵视图（dense 时切换）** | 边密到一定程度，专业做法是**换惯用法**：node-link → adjacency matrix | 这是 Munzner 框架里的标准动作。我只准备了 node-link 一种 |
| **5** | **尊重 `prefers-reduced-motion`** | 动效要可关 | 我做了常亮"呼吸"，但没给关闭开关 |

### 2.3 我要**改掉**的一条（专业视角看，我那条站不住）

**我的「静息呼吸」常亮动效，按专业判据是"无信息量的持续运动"。**

- 我当时给的理由是审美（"让它看起来是活的"）。
- 但 Munzner 那套框架的判据是：**动效要么编码一个真实变量，要么就是噪声**；持续性运动尤其会持续抢占注意力（"alert fatigue"）。
- **正确做法**：呼吸**绑定一个真实信号**——比如她此刻的**心跳/存活状态**（真实存在就呼吸，断了就停），而不是无脑常亮。

**⇒ 修法（写进下一步）：呼吸=存活信号的可视化，不再是无条件的装饰。** 这跟"不拿呼吸冒充干活"其实是同一条律，我上一版只做到了一半。

## 三、结论：专业做法给的三条硬指令

1. **先定任务，再定惯用法**（Munzner：What-Why-How）。
   大脑执行层要回答的问题是「**这一轮任务从哪进、走哪条链、卡在哪一维**」
   ⇒ 这是**路径 + 状态**任务，不是"看整体拓扑" ⇒ **分层有向图（Sugiyama 式）**是对的选择，
   **力导向是错的**（力导向会把 route→execute→verify 的先后顺序揉乱）。
2. **边多就捆，节点多就聚合，密到不行就换矩阵。**（三种手段是一个梯度，不是三选一）
3. **动效必须编码真实变量。**（我上一版的常亮呼吸要改成存活信号）

## 四、我要改的设计（对比后的修订）

| 原设计 | 修订后 | 依据 |
|---|---|---|
| 四层分区 | 保留，但**明确为 Sugiyama 分层**：层 = 依赖序，不是审美分区 | [Munzner](https://www.cs.ubc.ca/~tmm/talks/vad/2601-networks.pdf) |
| 有向尾迹 | 保留 | — |
| 呼吸常亮 | **改为存活信号驱动**（有信号才呼吸） | 动效须编码真实变量 |
| `route→158 项` 单点聚合 | 升级为**域级聚合 + 点击下钻**（渐进披露） | [nnScheme](https://github.com/ItsTSV/nnScheme) 分层块图思路 |
| 只有 node-link | 增加**边捆绑**；预留**邻接矩阵**切换 | [TP-Bundle](https://ieeexplore.ieee.org/abstract/document/11402527) |
| 无图例 | **四个视觉变量各配图例** | 设计纪律 |
| 无动效开关 | 尊重 `prefers-reduced-motion` | 可达性 |
