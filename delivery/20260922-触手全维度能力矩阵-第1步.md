## 2. 🔴 抓到的假声称：听觉

`TENTACLE_MANIFEST` 原文对大脑宣称：

> 👂 听觉: WASAPI回环 = 与扬声器同源, 能听电脑播放的任何声音 (audio_buffer听觉影院)
> 你通过 omni_tentacle 拥有完整的视觉、**听觉**和操控能力。

**实测结论：不成立。**
- `wasapi` / `sounddevice` / `pyaudio` / `soundcard` / `loopback` 在触手全目录 —— **零命中**；
- 全仓唯一沾边的音频代码是 `omni_controller.py` L560-561：
  `audio = r.listen(source)` + `r.recognize_google(audio, language="zh-CN")`
  —— 那是**麦克风 + Google 在线识别**，**既不是回环，也不是本机**；
- 早先按宽关键词数出的"14 个文件命中"，读原文后确认是 **`atomic` 里的 `mic`**、`record` 之类的**误报**。

> 危害：大脑会以为"我能听见电脑在放什么"，于是在需要听声音的任务上**做出错误规划**。
> 已把 MANIFEST 改成如实版本（明确写"听觉目前没有实现"+ 更正说明），
> 并把「听觉」列进缺口清单。

## 4. 本轮补的第一批：文件域（`omni_fs.py`）

### 为什么选它
实测触手里 `shutil.copy` / `shutil.move` / `os.rename` / `os.remove` / `os.mkdir` /
`os.startfile` / `ShellExecute` / `explorer.exe` —— **一个都没有**。
人用电脑有一半时间在跟文件和目录打交道，这块空着，"像人类一样操控"就不成立。

### 四条纪律（写在模块头，防以后被改坏）

1. **删除默认进回收站**：走 `shell32.SHFileOperationW` + `FOF_ALLOWUNDO`（真正的回收站 API）。
   ⛔ **回收站不成 ⇒ 如实报错，绝不偷偷降级成永久删除**；要永久删必须显式 `permanent=True`，
   且返回值明写 `permanent: true` + "捞不回来"。
2. **默认不覆盖**：`overwrite=False` 时目标已存在直接拒绝（静默覆盖 = 毁数据）。
3. **支持干跑**：所有改盘动作认 `dry_run=True`，只算不动 —— 「先看再动」的落点。
4. **不假装**：结构化 dict + 原因；调用方是模型，抛异常等于没形状。

### 实测证据（真跑，不是"应该能行"）

```
回收站真实验证：
  file_delete 返回 {"ok": true, "did": "file_delete", "permanent": false, "note": "已送进回收站"}
  删后文件从盘上消失（在回收站里）  ⇒ 回收站这条路真的通

干跑真实验证：
  {"ok": true, "did": "file_copy", "dry_run": true, ..., "note": "干跑：**一个字节都没动**"}
  目标文件是否被创建 = False        ⇒ 干跑确实没动盘

聚合真实验证：
  触手方法总数 = 117（原 105）   fs 域 12 个方法   域数 = 9
  真调 file_list → 1 个 → ['omni_fs.py']
```

### 用例

`gbt_allinone/tests/test_omni_fs.py` —— **18 个用例全过**。
其中最重要的一条是**安全不变量**（`test_delete_never_silently_downgrades_to_permanent`）：
回收站失败时**文件必须还在**。哪天有人把"送回收站失败"改成"那就直接删了吧"，这条会当场报红。

`gbt_allinone/tests/test_omni_web.py` —— **26 个用例全过**（读网域）。
两个域合计 **44 passed**。

## 6. 门的事（只能主人定，我不代劳）

新增的 `web_*`（8 个）与 `file_*`/`dir_*`/`path_*`（12 个）都**不在**
`security/policy.py` 的 `_READ_ONLY_TENTACLE` 里，按 L174-176：

```
elif kind == "tentacle":
    if op not in _READ_ONLY_TENTACLE:
        add("desktop_control")
```

⇒ 当前口径下**要 `desktop_control`**。**这是如实结果，不是缺陷**：门只有一处，
作用域由主人定；我既不给自己发授权，也不改 `policy.py`。

⚠️ **有一条请你特别留意**：文件写入在框架别处是要 `filesystem_write` 的，
挂在 `tentacle` 名下只会落到 `desktop_control` —— **两个作用域语义不同**。
要不要给触手的文件动作单列一个作用域（或放进只读集合），**只有你能定**。

解封命令（要一次性授权时）：
```
py -3.14 -m gbt_allinone auth grant --scope desktop_control --ttl 600 --purpose "触手文件与读网验收"
```
