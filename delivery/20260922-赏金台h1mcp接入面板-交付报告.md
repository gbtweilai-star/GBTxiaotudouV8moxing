## 一、先看：怎么定位到断点的（全部实测，零猜测）

### 1. 面板清单不在前端，在服务端

```
plugins/gbt-master/lib/client.js:  const BASE = "/gbt-master"
                                    fetch(BASE) → data.panels[]
plugins/gbt-master/lib/host.js  :  const PANELS = [ … ]   ← 清单在这里
```

活体实测（`GET http://127.0.0.1:3080/gbt-master`）：
`ok=True total=9`，九条页签 **全部「在」** —— 所以不是文件缺失。

### 2. 六页签是什么、h1 在哪

`holo_pet_w3/index.html` 的六个页签是
`四视图 / 工作树 / 故障矩阵 / 驾驶舱 / 工具 / 数字人`
（`data-view="quad|tree|matrix|cockpit|tools|pets"`）。
**h1 不在页签里，它是 Electron 子窗口**（`windows.json` 窗口 6）。

### 3. 真断点（三行代码 + 一道 CSP）

| 位置 | 原文 | 后果 |
|---|---|---|
| `shell/preload.cjs:31` | `h1: () => invoke("w3:h1")` | 唯一的 h1 数据口是 IPC |
| `shell/main.cjs:1204` | `ipcMain.handle("w3:h1", () => w3H1())` | 实现在主进程 |
| `h1/h1.js:8-9` | `var bridge = window.gbtW3 \|\| {}` → `if (!api)` | 没 Electron 就打「桥断」 |
| `h1/index.html:6` | `connect-src 'none'` | **第二道门**：就算补 fetch 也会被 CSP 当场挡死 |

`window.gbtW3` 只在 Electron 里存在 ⇒ 在 DSH 面板 iframe 里恒为 `undefined`。

### 4. 顺手查出的同类缺口

`brain.html`（大脑执行层排布图）**也不在 PANELS 里** —— 同一个「做了没接上」的病。一并补了。

### 通道设计的四条纪律（写在代码注释里，防以后被改坏）

1. **单一真源**：路径一律读 `holo_pet_w3/shell/windows.json`，与 Electron 侧 `h1ConfiguredPath` **同一份登记**，两处不各写死。
2. **零副作用**：只 `stat` / `read` / 读环境变量。不起子进程、不发网络、不写盘。
3. **凭据只报布尔**：不回显值，连用户名都不回显。
4. **取不到就不许绿**：`ok=false` 并带原因；只读声明**两条路都要过**（IPC 看 `bridge.readonly`，HTTP 看服务端回的 `body.readonly`）。

## 四、附带查出的既存缺陷（都不是我引入的，都是实测抓的）

### 1. 宿主里 `/gbt-master/api/*` 整条**内嵌反代是死的**

```
/gbt-master/api/state        → HTTP 404  GBT总面板: 该路径不在可服务白名单内
/gbt-master/api/recent-calls → HTTP 404  同上
/gbt-master/api/events       → HTTP 404  同上
```
DSH 的匹配规则是**最长前缀胜出**（`dsh-host-webserver/lib/index.js:321-331` 原文：
`/** Longest-prefix-wins over the prefix table after an exact-table miss. */`），
按这条规则 `/gbt-master/api` 本该赢过 `/gbt-master` —— 所以**它根本没注册**。

**根因**：DSH 进程自 **09-21 22:29** 起连续运行 19 小时未重启，
加载的是**没有反代那段代码的旧插件**；`host.js` 文件今天才写到 15:59。
⇒ **凡声明 `apiShim` 的页（能力球 / 主控台）在宿主内一直拿不到本机服务**
—— 能源流转、最近调用、事件流、语音，在面板里全是空的。代码已补，**待一次重启生效**。

### 2. 赏金台页**五张卡片全叠在一起**（页面从来没人真的看过）

`window.css` §10 的注释**早就把坑写明了**：
> `.gbt-wide` 的语义是「**单卡**铺满整屏」：position:absolute + inset:8px 在一个视图里只放一张才成立
> ……三张都带 `.gbt-wide` ⇒ 三张全 absolute 到同一格，**边界框逐字相同**

实测几何（真 Chrome，1020×1400，宿主源，改前）：

```
① y=54 h=1310   ② y=54 h=1310   ③ y=54 h=1310   ④ y=54 h=1310   ⑤ y=54 h=1310
实际相交的矩形对 = 10
```
五张边界框逐字相同、两两全相交 ⇒ 文字互相叠印，**只看得见最后一张**。
判据闭合：`holo_pet_w3/index.html` 是 `gbt-wide=5 + gbt-view=6`（有视图切换，每视图一张 → 正确）；
`h1/index.html` 是 `gbt-wide=5 + gbt-view=0`（无切换、五张全叠 → 踩坑）。

**改后实测**（同一脚本、同一视口）：
```
① y=54 h=403  ② y=465 h=100  ③ y=573 h=100  ④ y=680 h=100  ⑤ y=788 h=192
实际相交的矩形对 = 0        ← 10 → 0
```
修法与驾驶舱那次同款：**只在本页作用域**让卡回常规流，不碰 `window.css`。

### 3. 面板总索引页的自述**不诚实**

原页写着「本页由脚本自动扫盘生成 —— …… **全部现扫，不写死**」，
但卡片里的字节数是写死的旧数：`capabilities.html` 标 83 KB，**实际 129,745 B（127 KB）**。

## 五、还差一步：一次 DSH 重启（这个决定只能主人做）

实测过三条**不用重启**的路，全部走不通：

| 尝试 | 结果 |
|---|---|
| 改插件源码等 HMR | **不生效**。`DEFAULT_PROFILE_PATCH_RELOAD="live"` 只监听**配置补丁层**，不覆盖 `node_modules` 里的模块 |
| 改 `cordis.patch.yml` 触发 `entry.update()` | **不生效**。YAML 合法、组合未破、插件被 dispose/re-apply，但 ESM 模块仍走缓存（实测连探 4 次仍 `total=9`） |
| client 插件热载 | **不生效**。前提是 `pnpm run dev:web` 监听在跑 —— 实测 node 进程里**没有**它 |

所以：**页签（h1 / brain）与内嵌反代，都要 DSH 重启一次才生效。**
但主人明确交代过「**保留 DeepSeek Harness 运行对话页面的环境不去修改环境**」，
重启会中断当前会话、且新 URL 带新令牌要回终端取 —— **所以我没有擅自重启**。

**在不重启的前提下，本轮已让它现在就能用**：走面板总索引（活页签）→ 第 09 张卡「赏金台 · h1mcp」，
页面实测能拿真数据（通道自报「本机直连 8765」）。
重启之后它会自动改走同源反代那条，本机直连退成兜底 —— **代码不用再改**。

## 七、h1mcp 是什么、边界在哪（不夸大）

**归属（GitHub API 硬数据）**：`paysssk-creator/h1mcp` 是 **fork**，`"fork": true`，

> 🔴 **边界（必须说清）：接上 h1mcp ≠ 获得挖洞能力。**

> `close_report` / `update_report_severity` / `request_disclosure`。
