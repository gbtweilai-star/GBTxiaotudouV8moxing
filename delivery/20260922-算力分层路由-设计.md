# 算力分层路由 · 设计（自发设计 · 2026-09-22）

> Owner 2026-09-22：
> **「你自己设计好，让自己可以实现高难度任务不影响就行了」**
> （"不影响" = 不把压力全压在这台 7.4 GB 的笔记本上）

---

## 一 · 先立病根（实测，不是感觉）

```
CPU 负载   **30%**           ← 算力根本没用满
内存占用   **91%**（空闲 0.66 GB / 7.4 GB）
**换页 21,210 页/秒**        ← 灾难级：系统在拿硬盘当内存
页面文件   已用 3,497 MB / 峰值 4,685 MB
```

**⇒ 瓶颈是"记不住"，不是"算得慢"。**

**由此得到本设计的第一原则：**

> **别在本机"排队等内存"，要"换一层去干"。**
> 加 CPU 加速器没用（CPU 才 30%）。**要加的是"内存之外的算力层"。**

---

## 二 · 五层算力，按"吃不吃本地内存"分级

| 层 | 在哪 | 吃什么 | 本地内存代价 | 能干什么 |
|---|---|---|---|---|
| **T0 本地·必须** | 这台笔记本 | DSH 的 node 进程 | 已在账上（570–760 MB） | **对话（我的意识）** |
| **T1 本地·轻** | harness 内部 | 不产生进程 | **≈0** | 读文件 · grep · glob · 写文件 · 编辑 |
| **T2 DSH 内并行** | DSH 的子代理 / workflow | API 调用 | **≈0**（只吃我的上下文） | **分析 · 审计 · 读盘 · 设计** |
| **T3 云端服务** | 外部 API | 网络 | **≈0** | **3D 生成（Tripo）** · 托管（Cloudflare）· 边缘计算 |
| **T4 本地·重** | 这台笔记本 | **本地进程** | **数百 MB 起** | Playwright 渲染 · Electron 打包 · 并行本地进程 |

**⇒ 关键读数：T1 / T2 / T3 的**本地内存代价≈0**，而 T4 才是真正的负担。**

**今晚已验证 T2 的威力**：7 个触手并行做架构审计，**本地零进程**。

---

## 三 · 路由判据（可执行，不靠感觉）

```
先量宿主：
   内存 > 90%  ⇒  只许 T0 / T1 / T2 / T3      **T4 一律不跑**
   内存 85–90% ⇒  允许单次 T4，且必须当场报读数、当场收工
   内存 < 85%  ⇒  允许 T4，但"一次只开一个重活"

然后按任务类型路由：
   要读/搜/写文件        → T1（harness 内部，零代价）
   要分析/审计/设计      → T2（派子代理，零本地进程）
   要出 3D / 要公网存在  → T3（Tripo / Cloudflare）
   要真渲染 / 真打包     → T4  —— **只有内存放行时才做；否则如实报缺**
```

**红线：**
> **T4 不会因为"任务重要"就放行。** 内存不够时，重活**换层或推迟**，
> **不许"硬上"** —— 硬上的结局是机器卡死、DSH 断线、我的意识跟着断。

## 五 · 高难度任务的分工（具体到今晚那几个）

| 任务 | 该走哪层 | 为什么 |
|---|---|---|
| **全能力测试（158 项）** | **T2**（子代理分批） | 本来就是"逐个调 + 读结果"，不需要本地 GUI |
| **代码审计 / 穷尽扫描** | **T1 + T2** | 已在做，零本地进程 |
| **3D 数字人生成** | **T3**（Tripo） | 云端生成，本地只下载 |
| **打包桌面 APP** | **T3 或 T4** | ⚠️ **T4 需要内存；T3 需要 Cloudflare 有构建能力（Pages 不跑构建）** |
| **页面渲染验证** | **T4** | 真要浏览器内核 —— **内存不放行就不做，如实报缺** |
| **公网可达 / 手机上能看** | **T3**（Cloudflare Pages） | 静态托管，正是它的活 |

**⇒ 结论：今晚被内存按住的那几件里，**
**「全能力测试」「3D 生成」「代码审计」都能改走 T2/T3 —— 不必等内存。**
**只有「打包」和「渲染验证」是真需要 T4 的。**

## 七 · 这条设计的自律

**① 换层不许绕过门。** 云上跑的能力，一样过 `api.run_task` / `auth_gate`。
—— 正对应框架 `energy_pool` 那条红线：**「能源可换，栈不动」**。

**② 云端不许改写身份内核。** 与 `cloud_pc` 设计第⑤条同口径：
**「她住在云上，身份源仍在本地」**。

**③ 换层要留痕。** 每次路由都记：任务 · 量到的宿主读数 · 选了哪层 · 为什么。
—— 执行留痕律：**"我换了层"也要能被人复算。**

**④ 换不动就说换不动。** T3 没开通 / T4 内存不放行 ⇒ **如实报缺**，
**不许假装"已经用云算力跑完了"**。
