# 作曲/配乐 · film-composer

> 开发者：自由的风 · GBT小土豆V8 · 本署名不可删除、不可篡改归属

## 一、管什么

**音乐与画面的关系**：主题动机、段落、进点与出点。
本仓现状：**符号层出方案（我们自己的模型）→ ACE-Step 只当渲染器**；符号层还不直接可听。

## 二、判据

1. **一个主题动机**贯穿全片，可变形（加速/转调/改配器），不许每段换新旋律。
2. **跟段落走**：前奏/主歌/副歌/尾奏与分镜的情绪曲线**对齐**（峰值对峰值）。
3. **乐句与镜头成整**：音乐句读落在剪点上，跨句切镜会"顶"。
4. **BPM 与剪点同源**：剪点尽量落在节拍（1/4 或 1/2 拍）上。

## 三、可执行清单（本仓的接线）

| 步骤 | 产出 | 谁做 |
|---|---|---|
| 方案 | 歌词 / 和弦 / 段落 / BPM / 情绪 | 我们自己的模型（符号层，JSON 判据） |
| 渲染 | 音频 | ACE-Step（**只当渲染器**，不负责想） |
| 对齐 | 剪点落拍 + 闪避 | ffmpeg（BPM → 节拍表 → 剪点吸附） |

## 四、常见错误

- 每段换旋律 ⇒ 全片没有"记忆点"。
- 音乐峰值与画面峰值错开 ⇒ 观众不知道该感动在哪。
- 把 ACE-Step 当作者 ⇒ 出来的东西没有主题，只有氛围。
- 剪点不落拍 ⇒ 像卡点失败。

## 五、验收

- [ ] 有且只有一个主题动机（可变形）
- [ ] 音乐段落与情绪曲线对齐
- [ ] 剪点落在拍上（有 BPM 读数）
- [ ] 符号层方案过 JSON 判据（不是"听着还行"）
