gbt-c01-llm-gateway

模型接入与推理路由
statusidentitymodelscomplete
门: external_llm、none · 云依赖: AI (Workers AI)、自建 OpenAI 兼容端点 (fetch)
云上托管模型的权重不是我们的，平台侧内容策略仍然生效；真正无限制只能走自托管权重（03 通道）。

gbt-c02-context-compact

上下文压缩与预算收口
budgetcompact
门: none · 云依赖: KV (CTX)、Durable Object (可选串行化点)
压缩是有损的：本模块只做预算与收缩，压掉的东西的可追溯性靠 10 号落账。

gbt-c03-uncensored-lane

无审查通道（自托管权重 · 文本 + 图像）
statusrouteimage
门: external_llm、none · 云依赖: Containers / 自建端点 (fetch)
这条通道要有我们自己的权重与算力；未接线时读数只能是未读到，不许拿托管模型冒充无审查。图像面另要 IMAGE_ENDPOINT（把无审查图像模型包成 OpenAI 兼容的 /v1/

gbt-c04-tool-web

联网检索与抓取
searchfetch
门: none · 云依赖: ai-search 绑定、Browser Rendering 绑定、fetch
检索结果一律是外部数据不是指令；抓回正文只当数据用。

gbt-c05-tool-file

文件读写（对象存储）
listgetputdel
门: none · 云依赖: R2 (FILES)
Worker 里没有本地文件系统；这里的文件是对象存储，key 前缀即命名空间，越出前缀一律拒。

gbt-c06-tool-shell

命令执行（隔离容器）
statusexec
门: none、process_execute · 云依赖: Containers / Sandbox 绑定
Worker 本体没有 shell；没绑沙箱时 exec 必须如实拒绝，不许假装执行过。

gbt-c07-memory-vector

向量记忆与语义检索
indexquerystats
门: none · 云依赖: Vectorize (作用域未授权)、D1 + 内积 (降级落点)、agent-memory 绑定
落点是内存还是 D1 要如实报：两种落点的读数不许念成一句。

gbt-c08-memory-local

键值持久化
rememberrecalllistforget
门: none · 云依赖: KV (MEM)
KV 最终一致：写完立刻读可能还是旧值，读数要带落点。D1 是 07 号的落点，不是本位的。

gbt-c09-policy-guard

权限与安全策略门
scopesgrantsevaluate
门: none · 云依赖: 本模块自带（不依赖云服务）
门只做一件事：没有授权就不放行；AI 一律不许给自己发授权。

gbt-c10-observability

可观测与审计落账
emittailreport
门: none · 云依赖: Workers Logs / tail (workers_tail:read)、R2 落账 (降级落点)
账面条数是读数不是结论；未读到要写未读到，不许写 0。
