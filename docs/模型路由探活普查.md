## 二、🔴 发现 1（**安全**，最要紧）：`gbt-potato` 端点在公网上是**免钥匙开放**的

**证据链**（三处独立读数）：
1. 端点从本机访问 **HTTP 200**（`*.workers.dev`，公网可达）；
2. `worker.js` 的令牌闸是**可选且默认关**的：只在设了 `GBT_ENDPOINT_TOKEN` / `GBT_ENDPOINT_TOKENS`
   时才校验；**当前未设** ⇒ `/v1/chat/completions` 不校验 `Authorization`；
3. 它引用的 `GBT_POTATO_API_KEY` 在 **User 环境变量里不存在**，但路由照样能答 ——
   说明**根本不需要钥匙**，而不是"钥匙藏在别处"。

**⇒ 后果**：任何知道这个 URL 的人都能调用它，**烧的是你的 Workers AI 免费额度（10,000 neurons/日）**，
且**日志/审计上分不出是谁用的**。（本仓自己的「暴露面保护」写着：
*不要暴露内部地址/端口；发现异常开放配置要立即报告主人* —— 这条正是。）

**建议动作（安全向，与功能无关）**：
```bash
cd deploy/cloud-10
node -e "console.log(require('crypto').randomBytes(32).toString('base64url'))"   # 生成令牌
wrangler secret put GBT_ENDPOINT_TOKENS --config wrangler.toml                  # 写入（逗号分隔可多把）
wrangler deploy --config wrangler.toml                                          # 部署后闸才生效
```
> ⚠️ 开闸后**必须**把 DSH 那条 `gbt-potato` 路由用的钥匙放进同一份令牌列表
> （`apiKeyEnv: GBT_POTATO_API_KEY`），否则你自己的客户端先被 401。
> 多令牌支持已在代码里改好（`GBT_ENDPOINT_TOKENS` + 常数时间比较），**尚未部署**。

## 三、发现 2：`cordis.patch.yml` 的注释与事实不符（**声明比事实大**）

`cordis.patch.yml` L116 在 `gbt-potato` 段下写着：
> `# 🔐 钥匙：apiKeyEnv 指向的是**用户级环境变量**（现读已配 · 59 位）`

**实测**：User 环境变量 `GBT_POTATO_API_KEY` **不存在**；而 **59 位**那个值是
**`FREELLMAPI_API_KEY`**（属于 `gbt-free` 那条段，L120）。
**⇒ 那句注释把两条路由的钥匙张冠李戴了**，并且"已配"与事实相反。
（它不影响运行 —— 因为端点本来就不校验钥匙 —— 但会误导人以为已经锁上了。**这正是本仓最忌的"声明比事实大"。**）

## 四、发现 3：`gbt-free` 死透了（**积极拒绝**，不是超时）

```
WinError 10061 由于目标计算机积极拒绝，无法连接。
```
`gbt-free` 的落点是 `http://127.0.0.1:31415/v1`（FreeLLMAPI 桌面版）。
它承载 `auto` / `fusion` / `nemotron-*` / `muse-glimmer-30b` / `agnes-2.5-flash` / `gpt-oss-20b` 这一串模型 id
⇒ **你在界面上点 `auto` 或 `fusion`，拿到 `Connection error / TRANSPORT` 就是这条。**
（仓里 2026-09-22 已记过「实测死的」，今天复现。）
**而本机真正活着的服务在 `11434`（Ollama），却没有配成路由。**
