## 二、🔴 发现 1（**安全**，最要紧）：`gbt-potato` 端点在公网上是**免钥匙开放**的

**证据链**（三处独立读数）：
1. 端点从本机访问 **HTTP 200**（`*.workers.dev`，公网可达）；
2. `worker.js` 的令牌闸是**可选且默认关**的：只在设了 `GBT_ENDPOINT_TOKEN` / `GBT_ENDPOINT_TOKENS`
   时才校验；**当前未设** ⇒ `/v1/chat/completions` 不校验 `Authorization`；
3. 它引用的 `GBT_POTATO_API_KEY` 在 **User 环境变量里不存在**，但路由照样能答 ——
   说明**根本不需要钥匙**，而不是"钥匙藏在别处"。

**⇒ 后果**：任何知道这个 URL 的人都能调用它，**烧的是你的 Workers AI 免费额度（10,000 neurons/日）**，
且**日志/审计上分不出是谁用的**。（本仓自己的「暴露面保护」写着：
*不要暴露内部地址/端口；发现异常开放配置要立即报告主人* —— 这条正是。）

**建议动作（安全向，与功能无关）**：
```bash
cd deploy/cloud-10
node -e "console.log(require('crypto').randomBytes(32).toString('base64url'))"   # 生成令牌
wrangler secret put GBT_ENDPOINT_TOKENS --config wrangler.toml                  # 写入（逗号分隔可多把）
wrangler deploy --config wrangler.toml                                          # 部署后闸才生效
```
> ⚠️ 开闸后**必须**把 DSH 那条 `gbt-potato` 路由用的钥匙放进同一份令牌列表
> （`apiKeyEnv: GBT_POTATO_API_KEY`），否则你自己的客户端先被 401。
> 多令牌支持已在代码里改好（`GBT_ENDPOINT_TOKENS` + 常数时间比较），**尚未部署**。

## 七、追加：10 个 mesh 模块的「声明 vs 实现」对照（2026-09-25 第 12 轮）

### 7.1 先说清一件事（我上一轮低估了，已更正）

`wrangler.toml` 里**故意注释掉的"资源没建、只留形状"**，代码按"没绑"如实处理 —— **符合设计**。

> ⚠️ 上轮我标过一条「未验」：`modules.js:583` 算了 `wired`，596 直接 `ctx.env.SANDBOX.exec(cmd)`。
> **已读，清白**：L592-593 先问 `status`，未接线即 `return { ok:false, reason: NOT_READ,
> unsupported_in_worker: true, boundary }` —— **守卫在，且不假装执行过**。撤销该「未验」。

### 7.3 🔴 但审出一条**结构性**的读数缺口：**10 个模块里 7 个没有 `status` op**
```
有 status:  c01-llm-gateway · c03-uncensored-lane · c06-tool-shell        （3 个）
没有 status: c02 · c04 · c05 · c07 · c08 · c09 · c10                       （7 个）
                                    ↑ 3 + 7 = 10，对得上
```
**为什么这算缺口**（不是"少个函数"那么轻）：`worker.js:243` 的 `fullPing`（90 条边自检）
是这样收集每个模块的接线读数的 ——
```js
rows.push({ seq, id, op, ok: r.ok,
            wired: r.body ? r.body.wired : undefined,
            reading: r.body ? r.body.reading : undefined });
```
**⇒ 它依赖每个模块自己开一个 `status` op 报 `wired` / `reading`。**
没有 `status` 的模块，在集中报告里只能显示 **`wired: undefined`** ——
**也就是说：这 7 个模块"到底接没接上"这件事，机器问不出来，只能靠调用某个业务 op 再从失败里猜。**

**这与本仓反复出现的病同族**：c01/c03/c06 都有"先问状态再决定动不动"的守卫，
而 c02/c04/c05/c07/c08/c09/c10 **没有这一格**。`describeEndpoint()`（L92）和
`NOT_READ` 常量都已经现成，**补 `status` 的成本很低**。

**⛔ 未做（要主人点头）**：给这 7 个模块补 `status` op。
理由：**它改的是已部署 Worker 的对外契约**，改完必须 `wrangler deploy` —— 属改远端。
