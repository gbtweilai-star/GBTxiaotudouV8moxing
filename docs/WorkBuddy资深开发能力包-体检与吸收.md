## 三·补、本轮"缺的"里当场落地的三条

1. **L3 防复发**：修完必答"怎么让同类问题**不可能**再发生而不被发现"（今晚两例：假绿→退出码进判据；GOP/时间基→写进清单）；
2. **清单字段 = 契约（BREAKING 表）**：加字段安全；**删/重命名/改类型/改含义 = 破坏性**（`dur` 从"秒"改"拍"就是 BREAKING），必须标注 + 给迁移；
3. **"虚报高危"纪律**：无法构造攻击路径/无法复现的，**只能标为加固建议或待验假设**，不许混进 P0——与我们的"假绿/假红"对称。

## 四、本轮吸收（三条 · 可直接用）

### 1. 交付格式统一（P0–P3 + 结论先行五段）

```text
结论：<一句话判定，含严重度与是否阻断>
依据：<文件:行号 / 复现步骤 / 度量 —— 可验证，禁止「感觉」「可能」不附证据>
影响：<不修会怎样：谁受影响、什么场景、概率与后果>
动作：<可直接执行的补丁 / 命令 / 步骤>
验证：<改完怎么证明有效>
```
外加两条硬纪律：**P0 阻断（数据/安全/正确性/破坏性变更无迁移）**·
**一次评审里 P3 类意见不得超过 10% 篇幅**（人工注意力花在 P0/P1）。
**与我们的合并口径**：本仓原有「报告层红线」「未验账」照旧，**只是把"结论/依据/影响/动作/验证"作为默认骨架**——
我们今晚每条汇报其实已经在用（"读数 + 依据 + 影响 + 下一步"），现在把它**写成纪律**。

### 2. 一页式主检查清单（**已采纳为本仓交付前清单**）

落点：`docs/交付前主检查清单.md`（原文 + 出处）；使用时机：**改代码/上线前**过一遍，
**先过 P0 段，P0 有一条不过，后面不用看**；时间极紧时只问「五分钟快查六问」：
钱/数据/权限会错吗 · 谁能调用它他应该能吗 · 失败了有人知道吗 · 重复执行会怎样 ·
上线后怎么知道它是好的 · 出问题怎么退回去。

### 3. 故障台账补两栏（把"债务雷达"接到我们的未清故障上）

我们 `state/排查台账.json` 的 `open_faults` 10 条，本质就是一本债务台账，但缺它这两样：
- **业务成本量化**（次数/天数/人数/金额）——把"F10 是 3 条路径不合法"换成"每次交付都会撞、影响哪条产线"；
- **「明确不还」一节**（附原因）——它的原话：**这一节是资深与教条的分界线**；
- 排序判据也从我们的"按严重度"升级为 **改动频率 × 缺陷率 × 复杂度**（只烂但没人动的，不进计划）。

**动作**：下次台账改账（主人权项清完时）按这个格式补；本轮**不动台账**（那 10 条归属主人拍板）。
