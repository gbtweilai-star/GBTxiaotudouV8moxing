**⇒ 它是静态网格：没有骨架、没有蒙皮、没有动画。"绑骨"这一步是从零建的。**

### 坐标口径（实测，不是猜的）

Blender 4.2 的 glTF 导入器把 Y-up 换成 Z-up。导入后**现读** `matrix_world = 单位阵`，
局部 AABB 变成 `min=[-0.1948,-0.0871, 0.0000] max=[0.1949, 0.0870, 0.9801]`，于是：

| 语义 | glTF | Blender（脚本内实际用） |
|---|---|---|
| 横向 | X | **X** |
| 身高 | Y | **Z** |
| 前后 | Z | **Y**（角色面朝 **−Y**） |

身高轴 = **Z**；脚本里所有"身高比例"都作用在 Z 上（见 `AX_LAT/AX_DEP/AX_UP`）。

## 2. 阈值 — 单位 — 依据（三列，免得复算时扯单位）

模型是 Tripo 的**任意尺度**，没有真实世界单位，所以**一律用身高百分比**：

| 判据 | 阈值 | 单位 | 依据 |
|---|---|---|---|
| 四末端累计位移（"全肢体"） | **≥ 3% 身高 = 0.02940** | 模型单位 | 身高 = 输入 GLB 的 AABB 高度 = **0.98004** 单位（脚正好在 0 面，`foot_z` 直接可比） |
| 蹲起髋部竖直位移 | **≥ 5% 身高 = 0.04900** | 模型单位 | 同上（主人原话 10cm 按 170cm 人形折 5.9%，取 5% 更稳） |
| 走两步"脚离地" | **≥ 1% 身高 = 0.00980** | 模型单位 | 同上；另一脚同帧位移须 **< 0.2×抬脚量**（否则记"双脚一起飘"，不算交替） |
| 关节"参与" | 世界角变化范围 **> 0.5°** | 度 | 噪声底噪实测；六段动作实际 18~19 / 19 关节参与 |
| 左右对称（骨长） | 差 **≤ 1e-4** 单位 | 模型单位 | ≈ 1e-4 × 身高 = 0.01% 身高；实际 **4.2e-09** |
| 左右对称（镜像夹角） | **≤ 0.5°** | 度 | 实际 **0.000e+00°** |
| 骨骼动画通道 | animation 数 ≥6 且每段通道数 >0 | 条 | 真读 GLB 字节；实际 6 段 × 57 条 |

> 口径补充：上表写"cm"会算错（任意尺度）。所有脚本（`dh_rig.py` 的 `stage_ratio`、
> `dh-rig-check-rig.py`、台账 `state/digital-human-rig.json`）读的是同一份 `stage_ratio`，单一来源。

**落位口径（三条，都可复算）**：
1. **关节高度** = 人体解剖比例 × 模型实测身高 H（髋 0.5300 / 膝 0.2850 / 踝 0.0390 / 趾 0.0180 /
   肩 0.8200 / 颈 0.8550 / 头 0.8950）—— 高度用解剖比例最可靠，不含表面包裹误差；
2. **关节横向/前后** = **实测肢轴**：按身高每 5%（腿）/ 4%（臂）分层，取该层"左右腿簇中心"/
   "最外侧 18% 点"的均值做线性拟合，再按上述高度取值；
3. **脚尖** = 实测：该侧底部（<5%H）离踝最远的水平点（真测的朝向，不是猜 ±Y）。

### 3.3 左右对称（**量化**）

| 骨 | 左长 | 右长 | 骨长差 | 镜像后夹角 |
|---|---|---|---|---|
| shoulder | 0.20770 | 0.20770 | 4.2e-09 | 0.000e+00° |
| upper_arm / forearm / hand / thigh / shin / foot | 同上量级 | — | ≤4.2e-09 | 0.000e+00° |

```
max_len_diff        = 4.234e-09   单位
max_mirror_angle    = 0.000e+00   度
```

**怎么保证的（诚实口径）**：骨架**只实测一侧**——取"自然下垂那条臂 + 一侧腿"，另一侧**镜像**得到
（镜像面 = 实测身体中轴 X=0.0084 处的平面）。所以对称是**构造保证**的，量化结果必然接近 0。
这条避开了一个真坑：网格本身**不是对称姿势**（见第 3.4），若两侧各自实测，骨架必然歪。

**哪条臂是"自然下垂"的**（实测）：取 0.42~0.52H 高度带的外侧外伸量 —— `+X=0.1496` vs `−X=0.1159`，
外伸大的一侧说明有手垂在那；⇒ **静置参考侧 = +X**。结合朝向前方 F=(0.355,0.935,0)（由实测脚尖−踝得到）
算出"角色右手方向 = 前×上 = (−0.997,−0.078,0)" ⇒ **角色右手在 −X 一侧**。

### 3.4 🔴 网格自带的不对称姿势（这条决定了后面几处妥协）

实测：**−X 侧（角色右臂）的几何被烘焙成"手扶头发"的抬起姿势**（手在世界 z≈0.885H，肘在 z≈0.72H），
而 **+X 侧（角色左臂）是自然下垂**。所以：

* 骨架按**下垂侧镜像**建 ⇒ `_L`（=+X）一侧"几何与骨骼一致"；`_R`（=−X）一侧**骨骼在静置位、几何却在抬臂位**。

**这不是脚本 bug，是网格烘焙的结果**（原始 GLB 里就这样，见第 1 节的 `skins=None` ⇒ 没有静置姿势可继承）。

## 4. 蒙皮

### 4.1 方法（自动权重失败 ⇒ 自写包络蒙皮）

| 步骤 | 结果 | 读数 |
|---|---|---|
| 自动权重（Bone Heat） | **失败** | 原话：`Warning: Bone Heat Weighting: failed to find solution for one or more bones`，覆盖顶点 **85977/85977 = 0 个拿到权重** |
| 抽稀后焊接重合点 | 必需 | 抽稀后网格碎成 **358 个连通分量**（最大块仅 2509 点=2.14%）⇒ Bone Heat 无解。按 0.0006 焊接重合点后 **358→2 个分量，最大块 2509→85973（100%）** |
| 自写包络蒙皮（实际使用） | 成功 | 组=19 · 无权重顶点=**0** · 平均权重和=**1.00000** · 零覆盖骨=**无** |

### 4.2 自写蒙皮的参数（逐项，改了哪个值）

```
包络半径 R(×H)：hips 0.068 | spine 0.050 | chest 0.055 | neck 0.025 | head 0.060
               shoulder 0.025 | upper_arm 0.030 | forearm 0.024 | hand 0.024
               thigh 0.028 | shin 0.029 | foot 0.022
判定规则：顶点归"归一化距离 D/R 最小"的骨；第二根骨仅当**骨架跳距 ≤2 跳**时才共享权重（权重上限 0.45×blend）
跨侧压制：顶点明显偏一侧时，对侧肢体骨的 D/R 被放大 1/(0.30+0.70·clip(|u|/0.09H,0,1))
髋缝软化：髋关节高度 ±0.06H、|u|≤0.15H 的一圈，把大腿权重的 60% 转给 hips
沿网格平滑：K=4 次，λ=0.35（行归一邻接平均）
死骨兜底：某骨若管到 <20 个顶点，把它最近的 40 个顶点权重抬到 ≥0.45 再归一（保证无死骨）
每顶点影响数：裁到 ≤4 并归一（glTF 默认）
```

**为什么不是纯"最近骨"**（用距离数字说清）：髋线附近到 **thigh 骨线段 ≈0.030**，
到 **hips 竖线 ≈0.037~0.094**，到 **hand/forearm 骨段 ≈0.047** ——
纯最近骨会把**髋/臀整片判给大腿**，还会让**手骨抢到髋部顶点**；一抬腿/一抬臂，
那片壳体被拽走 ⇒ 拉丝、刀片、翻边（第 8.4 节有实测）。

## 5. 六段动作（全肢体）

动作帧率 24fps，关键帧每 2 帧一个（`FRAME_STEP=2`）。每一段都是**独立可导**的 Blender Action。

| 动作 | 帧 0..N | 驱动方式（哪些关节、怎么驱动） |
|---|---|---|
| `01_呼吸` | 0..48 | hips 绕竖轴 1.4° ± 横移 0.030H·sin + 纵向微沉；spine/chest/neck 俯仰 ∓；head 侧倾；双肩/上臂/前臂微动；**双脚轮流提踵 16°** |
| `02_打招呼` | 0..48 | **左臂**四级联动（肩带绕前后轴 20° + 上臂/前臂/手腕目标方向 + 摆动 2 次/周期）；右臂安全小角 ≤12°；重心移右腿（右膝下沉 + 右脚原地碾转 15°/8°），**左脚整体离地 0.016H** |
| `03_走两步` | 0..48 | 2 个步态周期；hips 横移 0.016H + 绕竖轴 7°；两条腿由 **2 连杆 IK** 驱动（步幅 0.060H、抬脚 0.045H、脚尖抬 15°）；**反向摆臂 24°** |
| `04_转身` | 0..48 | hips 绕竖轴 55° + spine 18° + chest 9° + neck 7° + head 12°（**分级**）；双脚踝目标绕身体竖轴原地碾转 |
| `05_蹲起` | 0..56 | hips 竖直下沉 0.235H + 后移 0.055H；腿用 IK 把脚踝钉住 ⇒ **thigh/shin/ankle 三关节同时弯**；提踵 20°；双臂前伸 |
| `06_伸懒腰` | 0..56 | **左臂**上举（目标方向从静置按 upp 混到"上举"）；右臂限幅 ≤14°；spine −17°/chest −20°/neck −14°/head −12° 逐级后仰；双脚提踵 24° |

### 8.2 为什么动作帧用 EEVEE 而不是 Cycles（**退档原因 + 内存读数**）

* **Cycles GPU 实测不可用**，原话：
  `Failed to load HIP kernel from '...\cycles\lib/kernel_gfx90c.fatbin.zst' (Shared object initialization failed)`
  —— 本机 GPU = AMD Radeon RX 6500M(4GB)；HIP 设备能被枚举但内核载不进去 ⇒ **GPU 渲染不可用**。
* Cycles **CPU** 实测 **34.6 秒/帧 @1080×1350 / 128spp + OIDN 降噪**：
  六段动作 ×10 帧 = 60 帧 ⇒ 单这一项就要 **≈35 分钟**；而动作帧只需要证明"真在动 + 撕裂修好"，
  所以按主人"六段动作的帧可以用够看动作的档"口径走 **EEVEE_NEXT 256spp（实测 5.9 秒/帧）**。
* 高清预算集中到**英雄静帧**（3 张 × Cycles CPU 96spp，1536×1920）与**面部特写**。
* 内存纪律：`Get-CimInstance`/`GlobalMemoryStatusEx` 现测空闲物理内存，最低实测见第 9 节；
  任何一步都是**量了再上**。

### 8.3 材质：法线确认 + 皮肤单开一份（治"抹了油/湿塑料"）

**法线贴图真的接上了**（现读节点树，不是感觉）：


**法线开/关同帧对比（结论）**：同帧同机位同档，只把 `Normal Map.strength` 1.0→0.0：
两张图**像素级差别极小**（640×800 全身档 mean |ΔL| ≈ 0.2/255，锐度读数 161.2 vs 161.9，差 0.4%）
⇒ **全身档下"看不出差别"**。原因：basecolor 4096² 本身已把细节烘进去了 + 全身档下每个纹素不到 1 像素。

### 8.4 撕裂：诊断三判别 + 实测根因 + 修法

主人先看到的是 `03_走两步/f021` 抬腿侧大腿根"黑皮装被拉成一片肤色/撕裂感"。按三种可能各做判别：

| 假设 | 判别方法 | 结论 |
|---|---|---|
| ① **权重撕裂**把服装壳拉开 | 渲染**静置姿势**（无动作）的同一区域 + 看权重分布 | **是这条**（见下）；静置姿势干净、动起来才撕 |
| ② 材质 alpha/transmission 设错 | 现读 BSDF：`Alpha = 1.0 linked=False`；材质里**没有** transmission/alpha 链接 | **排除**（全不透明） |
| ③ 法线贴图方向反了导致"糊" | 同帧 `Normal Map.strength` 1.0↔0.0 对比 | **不是**：反了会整片变暗/错光；实测开关差别极小，且方向正确（TANGENT, strength 1.0） |

**实测根因（两层）**：

1. **手骨抢髋**：手臂自然下垂时 `hand/forearm` 骨段紧贴髋部（髋线到 hand 段 ≈ **0.047**）⇒
   纯最近骨会把髋部顶点判给手骨；一抬臂，髋部壳体被拽走 ⇒ **刀片/拉丝**。
   证据：修复前跨侧权重**峰值 6.0693**（一个顶点上跨侧骨权重之和超过 6，权重和都没归一）。
2. **大腿抢髋**：(见 4.2 的距离数字) ⇒ 髋部服装壳整片跟大腿走。

**修法（两件一起，各带数字）**：

* ① **收紧/重配权重**：包络半径（hips 0.068H 大包络）+ **骨架跳距门（≤2 跳才共享权重）** +
  跨侧压制 + 髋缝软化（大腿权重的 60% 转 hips）+ 沿网格平滑 4×λ0.35 + 死骨兜底 + 每顶点 ≤4 影响。
  ⇒ 髋带第一影响骨 **hips 2161→3116**、跨侧权重 **峰值 6.0693→0.4974 / 均值 1.1881→0.0947**。
* ② **关节限位**（因为壳体不耐大角度形变）：走两步 大腿摆幅 **30°→22°**、小腿 **−34°→−26°**、
  脚 **−18°→−14°**、步幅 **0.085H→0.060H**、抬脚 22°→15°；伸懒腰右臂限幅 **≤14°**；打招呼右臂 **≤12°**。

**修前/修后同帧**（同档同帧号，一眼可对）：
`frames/03_走两步/f021_before.png`（修前）vs `frames/03_走两步/f021.png`（修后）。

**案例 A：04 的"转身"其实是把骨盆绕横轴侧倒 54°**
- **问题**：观感"像深弯腰不像转身"；同相位左右腿世界角 16.33° vs 45.84°（差 29.5°）；左脚抬高约 0.057H。

3. **会撕裂哪处**：本轮"拆壳封边"实测（切 3229 面 + 补盖 10104 面）在**髋/大腿留下可见碎片与补盖斑**（`_diag_r3/s5x2_*.png` 对 `base_r_*.png`）。右臂重姿需要同量级切割，且会**同时把头发补盖与右腋补盖暴露到最显眼处** ⇒ 等于用两处新瑕疵换掉"手挡脸"。
