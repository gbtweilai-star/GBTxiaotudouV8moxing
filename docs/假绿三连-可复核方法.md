# 假绿三连 · 可复核方法（GBT小土豆V8）

> 开发者：自由的风 · 守护者：公主土豆 · 本署名不可删除、不可篡改归属

**这份文件只讲一件事**：怎么让「**看起来成功、其实没干**」这类**假绿**在**机检层面活不下来**。
它是 2026-09-24～25 这一整段实战（账 §一百三十七–§一百四十九）蒸馏出来的，**每一条都有真案例**。

**为什么值得单列一页**：本会话反复出现的**不是"功能坏了"，而是"量具坏了"** ——
坏判据不报错，它**给你一个看着合理的错数**。所以这一页的重心在**判据**，不在功能。

## 一、三类假绿（本会话都真抓到过）

### ① 报成功但什么都没干（外层 ok、内层空）

| | |
|---|---|
| **真案例** | `claude_code` / `codebuddy` / `ul_tars_desktop`：登记在 `BENIGN_CAPS`（框架认为**可用**），真调返回 `{"status": "ok", "result": None}` |
| **根因** | `api.py::_run_benign` 末尾**没有兜底 return**（隐式返回 `None`），`api.py:1543` 又**无条件**包成 `status: ok` |
| **为什么比"没这能力"更坏** | 没有时会**如实说** `unknown capability`；现在它**说 ok** ⇒ 调用方**分不清"干了没输出"和"根本没干"** |
| **检测** | `caps-registry-guard.py check`（第 ⑥ 条：登记 vs 接线） |
| **修法** | 兜底**如实报** `not_wired`（已做，走护照 `fc-20260925T061256-bdrr`） |

### ② 登记了但没着落

| | |
|---|---|
| **真案例** | 同 3 位：`BENIGN_CAPS` 里有名字，**整个 `api.py` 零出现**（无分派分支、无模块、无实现） |
| **检测** | 同一道闸：`**真没着落（红）**` = 「名字在 BENIGN 里，却在整个 api.py 里一次都没出现」 |
| **判据要点** | 只认 `kind == "X"` **与** `kind in (…)`（**元组分支也要认**）；**排除 `UNIMPLEMENTED_CAPS`**（那张表设计上就没有实现） |
| **🔴 我第一版判据错了** | 只认 `kind ==` ⇒ 把 `film_intel`（`if kind in ("music_intel","video_intel","film_intel")`）等 **22 位冤枉成"没接线"**。**上报前先拿已知能跑的位验一遍**，才没把假数发出去 |

### ③ 空话分支（有分支，但不干活）

| | |
|---|---|
| **为什么单列** | 光靠 ② 拦不住这种手法：**加一个什么都不做的分支**，② 就绿了，而能力**依然不存在** |
| **检测** | 分支体**只有** `return` / `return None`，或**只回**一个含「未实现」字样（`not_implemented`/`not_wired`/`stub`/`todo`/占位/未实现）的字典 ⇒ 点名 |
| **宁松不枉** | 分支里**只要有一次真调用**（import / 函数调用）就不算空话 —— 防误伤 |
| **一句话** | **"用一句空话把闸糊绿"这条捷径，现在会被点名** |

## 二、四条铁律（每条都有被咬过的记录）

1. **每个判据都要有负控** —— 种一段**真缺陷**进去，必须被咬出来。
   反例（本会话）：`checkup.py --self` 写死 `len(steps) == 5`，体检长到 20+ 步后**恒假**，
   而它挂在神经末梢 P25 上 ⇒ **红了好久没人看**（`nerve.py probe P25` ⇒ ⛔ 痛 rc=4）。
   **不进体检的自检 = 没写。**
2. **条数一律现算，不许写死** —— 本会话修过 **4 处**同型：`== 5` / 「16 道闸」 / 「296 个 .py」 /
   哨兵的 `EXPECT_TOTAL = 168`（注册表被扩到 171 后**把合法增长判成故障**）。
   **该写死的是"不许跌破的下限"与"Owner 定过的口径"，不是条数。**
3. **措辞统一** —— 「**未读到**」是唯一表示"没读到"的词。
   本会话吃过两次：写「读不了」被判成「用 0 冒充」（台架 D3）；「读不到 vs 未读到」假红过一次。
4. **单一真源** —— 判据只写一份，消费方 import 它。
   反例：某轮我为了绕开引号地狱**把 `soft_only_kinds()` 重写了一份** ⇒ 两份分叉，
   **审计说 9 位、本工具说 0 位，两者不可能同时对**。

## 三、判据本身的三种自杀方式（都要防）

| 自杀方式 | 长什么样 | 防法 |
|---|---|---|
| **文本子串判据** | `("def foo(" % n) in 源码` | 用 **AST**；本会话被咬 **3 次**（最狠一次：**判据匹配到了判据自己**） |
| **自指判据** | `"locked_append_text" in src` 而 `src` 就是本文件 ⇒ **恒真** | `criterion_bench` 的 D6；自指要先分清**前置筛**与**定胜负** |
| **该定义的地方** | `ast.walk` 找到**嵌套函数**却当模块属性用 ⇒ `getattr` 崩 | **「在哪里定义」和「叫什么名字」一样重要** |
| **位置当存在** | 查「有没有署名」却只查**最后一行**（`-Tail 1` / `[-1]`）⇒ **末行不是署名** 被念成 **没有署名**，差点去改两份没坏的文件 | **台架 D7**：`MARK in X[-1]` / `X[-1].startswith(…)` 一律记 🟡 **提示**（可能只是"解析末行"的正当写法，**但必须被看见**） |

**D7 上线时的三条命中**（全部是**既有代码**、且**只提示不判决**）：
`checkup.py`（取命令列表末项看是不是 `.py`）· `design-inventory.py`（看正文里有没有那个文件名）· `vrm-pack.py`。
⇒ **模式真、缺陷假** —— 这正是它只记 🟡 的原因：**工具负责浮现，人负责判决。**

## 五、边界（这套方法**查不了**什么，如实标）

**先给一条"怎么定判据宽窄"的办法**（2026-09-25 用数据换来的）：
> **加广覆盖面之前，先量信噪比。**
> ① 数命中 → ② **抽查**（不全看、也不不看）→ ③ 判"抽到的**是不是我要抓的那个病**"
> → ④ 是噪声就**收窄**，并把**测量过程**写进棘轮备注。
> **别让"覆盖面变大"冒充"质量变好"。**
>
> 实例：D7 只认 `[-1]` 时 **3 处命中**；推广成"任意下标 + `pop()`"后 **46 处**，
> 抽查 8 条**全是"操作首/末元素"的正当代码** ⇒ **噪 > 信，收窄回尾部负下标**（回到 3 处）。
> ⇒ **后来那 3 处逐条核完**：1 处是**真位置依赖**（`checkup.py` 先看命令表末位是不是脚本，
> 而末位常是参数）⇒ **等价改写，现读 2 处**；另 2 处**位置就是语义**（取路径末段 = 取文件名 ·
> 去 `mixamorig:` 命名空间前缀）⇒ **不该改**。**"命中"不是"有罪"，"没核过"也不许挂着。**

**另一条同源纪律：负控必须与判据同宽。**
判据收窄了、负控里还留着**判据已经看不见的形状** ⇒ 那行**永远咬不到**，
而且会让读的人**以为那个形状被覆盖了**。台架现在会机检它：
把负控里**判据形状的行**单独喂给检测器，**单独也咬不到**就点名（这条控制**自己也有反控**）。

---

- **查不了语义正确**：判据能证"分支里有一次真调用"，**证不了那个调用做对了事**。
- **查不了"将来"**：静默/无变动类判据只能**降低**误判概率；
  "他以后不会再写"这种话，**只有事后时间能证**（本会话把阈值从拍脑袋的 10 分钟
  改成由数据推的 30 分钟：活跃期最大间隔实测 **16.4 分钟** ⇒ 10 会误判）。
- **查不了外部世界**：生产开关、别人的意图、真机能否跑动 —— 那些要**真跑**或**给人看**。
- **假绿三连只覆盖"结构性假绿"**：还有"**数据假绿**"（读错源、读旧缓存）与
  "**模型假绿**"（模型答得理直气壮但是编的），那两类要另外的判据。

## 七、把「控制会咬」做成机检（**判据的判据**）

前面六节都在讲"判据要真会咬"。**这一节把它变成一条命令** —— 因为"我已加了负控"是**声明**，
不是读数；读数只有一种：**把判据打坏，它按名字红了。**

### 本仓三次「控制是装饰」（都被真人抓到，而不是被闸抓到）

| 事故 | 形状 | 谁发现的 |
|---|---|---|
| `checkup._self_check` 写死 `len(steps) == 5` | 体检长到 20+ 步后判据**恒假**，还挂在神经末梢上 ⇒ **红到没人看** | 人肉读代码 |
| 署名覆盖面闸 `--trees` 默认只有 `STAMPABLE` | `docs/` **整棵树没人看**，两份自动生成的页长期无署名而不报警 | 改造闸时 |
| 位级写目标抽样两次抽错 | 判据**恒 `None`**（先 `p.get(` 抽错、后切片吞注释） | 人肉对差 |

共同点不是"判据写错了"，而是**没有任何东西验证过判据会咬**。

### 四条硬纪律（`tools/codex-scripts/mutation-proof.py`）

1. **原件逐字节不动** —— 只在靶同目录写 `_mut_*.py`、`finally` 删、跑完查残留，
   并**前后比 sha**。这一条不许只写在注释里（`原件未被改: true` 就是读数）。
2. **锚点必须恰好出现 1 次** —— 0 次或 ≥2 次**一律拒绝**，绝不 `replace-all` 猜。
3. **点名要红的那条控制必须红** —— 红在别处**不算咬住**（宽判据 = 假绿）。
4. **崩 ≠ 咬住** —— 默认只认靶自报的 `"不通过"` 字段；**读不到一律不许当咬住**（fail-closed）。

### 造这台机器时我自己踩的两处（**比正确更值得记**）

- **崩被念成咬住**：第一版判"咬没咬"看**退出码**。合成靶的 `✗` 在 Windows 默认 **GBK** 下
  `UnicodeEncodeError` 崩掉（stdout 空、rc=1）⇒ 机器把**崩溃**报成了「咬住」。
- **负控自己假绿**：那条"红在别处也要判没咬住"的负控，**第一版是被崩溃路径喂饱的** ——
  它同时满足"没咬住""红灯数 0""理由含别处"。修法：**判据必须证明"确实红了"**
  （读数真读到 `「不通过」`，且红灯行里点名的那条**不是**要的那条）。
- 附带：这台新工具进仓**当场被旧台架咬了两次**（`D3 用0冒充`）——
  `len(d.get("刀") or [])` 会把"字段不在"**静默印成 `刀数: 0`**。
  改法就是本页铁律：**缺字段 ⇒ 拒绝 + 明写「未读到」**，可选字段用 `in` 判断，不用默认值顶替。
