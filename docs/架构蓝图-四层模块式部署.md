> 主人令（2026-10-09）：「不管多大的项目，你只要设计好架构和蓝图，后面就开始使用我们自己独有的模块式部署」
> 「每天重启之后自动排查是否有故障和报警，不管是什么报警都要给我追踪根因修复好」
> 「生产面板上面禁止说下任何污点」「每一个能力必须单独跑通闭环才能交付」「每天所有的执行动作都要登记避免重启之后无脑操作」

**本文不是散文，是契约**：每条都写清「模块 / 判据 / 现在读数 / 谁来跑」。
蓝图自带判据件 `tools/codex-scripts/blueprint-check.py`（会红、有负对照）——**口号不会自己红**。

## 一、四层总览

| 层 | 名字 | 管什么 | 模块（真件） | 判据（会红的） | 现读数 |
|---|---|---|---|---|---|
| **L1** | **账** | 每个动作/变更/报警**只追加**入账 | `tools/codex-scripts/action-ledger.py` · `logbook.py` · `gbt_allinone/store/audit.jsonl` | `action-ledger.py --selftest`（3 负对照） | 台账 8+ 条 · selftest 全红 |
| **L2** | **门** | 改框架自己要有护照；能力调用走唯一门 | `gbt_allinone/tools/framework_gate.py` · `security/policy.py` · `auth_gate.py` | `framework_gate verify`（红=有未认领改动） | **green · 红 0**（基线 728 件） |
| **L3** | **巡检** | 每天证明「它还活着」 | `tools/codex-scripts/capability-audit.py`（341 项·五态） · `checkup.py`（一条命令体检） | `capability-audit.py`（断连/缺失置顶） | 总 341 · **断连 0 · 缺失 0** · 按需未启用 3 |
| **L4** | **重启** | 重启后先读账：别重做、未闭合接着做、报警追根因 | `action-ledger.py boot` + `checkup.py` + 计划任务 | `action-ledger.py boot`（有报警/未闭合/重复=红） | **PASS** |

**层与层之间只有一条约束**：上层的结论必须能被下层现读复算 —— 不许「我在报告里写了绿」。

### 🔴 停工规则（主人令 2026-10-09 · 与我一起改的）

**整体没完善就不停工，除非用户要求停止。**

「整体完善」不是感觉，是**五处现读**（判据件 `gbt_allinone/ux_doctrine.py::completeness`
+ 体检步「不停工判据」）：

| # | 项 | 现读处 |
|---|---|---|
| ① | 报警 0（断连+缺失） | `state/capability-audit.json` |
| ② | 禁交付 0 | `delivery_gate.audit()` |
| ③ | 未闭合动作 0 | `state/action-ledger.jsonl` |
| ④ | 框架门 `verdict=green` | `framework_gate verify` |
| ⑤ | 四层蓝图判据 PASS | `blueprint-check.py` |

**任一处不绿 ⇒ 不许停工**；**局部活干完 + 带证据**也**不够**（必须整体全绿），
且停下时必须**点名还差哪一项**。两个**唯一例外**：① 危险清单里的授权动作（AI 不许自授权）；
② **主人明确喊停** —— 这条优先级最高，压过一切判据。

## 二、每层的契约（输入 / 输出 / 不做什么）

### L1 账 · action-ledger
- **输入**：一次动作（动作名 + 目标 + 证据 + 结果 + idem 幂等键）
- **输出**：`state/action-ledger.jsonl`（**只追加**，不删不改）
- **三条口径**：① idem = 动作+目标 归一化；② 同 idem 再登记 ⇒ 点名「疑似无脑重做」；③ 报警现读 `capability-audit`，**不自己编一份**

### L2 门 · framework_gate
- **输入**：受监视件的改动
- **输出**：`verdict = green|red` + 逐条 `no_passport`/`stale_passport`
- **监视面口径（三条全中才算生成物，可排除）**：
  ① 文件**自己声明**「自动生成，别手改」② 给了**重建命令** ③ 由**运行中的生成器持续覆盖**
- **排除面必须打印**（范围看得见才敢收）
- **不做什么**：不因为「红太多」就放宽 —— 收窄监视面**必须**声明式重立基线（`snapshot --force --reason`），理由入账

### L3 巡检 · capability-audit
- **五态**：接上 / 断连 / 缺失 / 未探测 / **按需未启用**
- **按需未启用**的定义：只在用到那个 provider 时才需要、且凭据在主人侧 ⇒ **没跑不是故障**；逐条附**拉起命令**与「谁能给」
- **不做什么**：不把「按需」混进「断连」（那会让面板永久挂假污点），也不把真断连说成「不影响运行」

### L4 重启 · boot guard
- **输入**：L1 台账 + L3 报警
- **输出**：今天做过的 · **已完成（别重做）** · 未闭合（接着做） · **疑似无脑重做点名** · 报警
- **不做什么**：**不装计划任务**（机器级配置要主人点头）——只打印可用的调度命令

## 三、模块式部署（我们自己独有的那套）

**一个模块 = 四件套齐了才算部署完**：

| # | 件 | 判据 |
|---|---|---|
| 1 | **实现** | 件在盘上、能跑 |
| 2 | **门** | 走 `run_task`（能力位）或写明「不是能力位」的理由 |
| 3 | **判据** | 有会红的检查件（含**负对照**：喂坏数据必须红） |
| 4 | **账** | 每次动作进 L1 台账 |

**部署顺序（照 L1→L4 依赖，不许跳）**：
```
L1 账 → L2 门 → L3 巡检 → L4 重启
        ↑ 每加一个模块，都要把它的判据挂进 L3 的巡检清单
```

**新增即清旧**：新模块上线的**同一步**把被它取代的旧件送回收站（`supersede-check.py --recycle`），并跑 `supersede-check.py --check`。

## 四、每日重启自动排查（L4 的落地形状）

```powershell
# ① 体检（一条命令串起所有闸，fail-closed）
py -3.14 tools/codex-scripts/checkup.py

# ② 重启守卫（读账：别重做 / 未闭合 / 疑似无脑重做 / 报警现读）
py -3.14 tools/codex-scripts/action-ledger.py boot

# ③ 面板报警（生产面板的数据源）
py -3.14 tools/codex-scripts/capability-audit.py
```

**调度**（机器级配置 ⇒ **要主人点头才装**；`checkup.py` 自己也只打印命令、不擅自装）：
```powershell
schtasks /Create /TN "GBT-每日体检" /SC DAILY /ST 09:00 /TR "py -3.14 tools/codex-scripts/checkup.py"
```

## 五、每条报警的处理纪律（主人令）

1. **不许说「不影响运行」就算过** —— 报警一律追到**根因**；
2. 根因分三类：**真故障**（修）/ **语义错位**（改口径，但信息要放对格子）/ **历史欠账**（声明式重立 + 逐条落清单）；
3. 修完必须留**前后读数**与**负对照**。

已按此办过两例：绑定台账 242→247（语义错位）· 框架门 354→0（历史欠账 + 生成物口径）。

## 六、能力交付门（每一个能力必须单独跑通闭环）

**能力位 = 248 条**。交付前必须：
1. `py -3.14 -X utf8 tools/codex-scripts/caps_sweep.py --only <kind>` —— **真过门调用**，逐位一条读数；
2. 判据六档：通 / 如实否 / 如实拒 / 要参数 / 缺依赖 / 真坏；
3. **真坏 = 0** 才许交付；「如实拒」要写清缺哪张票、「要参数」要写清缺哪个参数；
4. 实测（2026-10-09 全量）：**通 206 · 如实否 3 · 如实拒 16 · 要参数 21 · 缺依赖 1 · 真坏 0**。
