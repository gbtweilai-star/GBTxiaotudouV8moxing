# 主检查清单（一页式）

> 出处：WorkBuddy《资深开发工程师能力包》· `senior-dev-dispatch/references/master-checklist.md`
> **本仓采纳版**（Owner 2026-09-27 给料 · 体检通过后收录 · **原文未改**）
> 使用时机：**改代码 / 上线前**；**先过 P0 段 —— P0 有一条不过，后面的检查没有意义**。
> 全量体检报告与吸收映射见 `docs/WorkBuddy资深开发能力包-体检与吸收.md`。

> 用途：把 14 个专项技能的核心检查项压缩到一页，供评审、上线前把关、自检时快速过一遍。
> 原则：**先过 P0 段，再往下。** P0 有任何一项不通过，后面的检查没有意义。

---

## A. P0 阻断项（任一不过 → 阻断合并/上线）

### A1 安全
- [ ] 输入进入 SQL/命令/模板/反序列化，是否**参数化**或白名单化？
- [ ] 每个「改/删/查他人资源」的入口是否做了**对象级鉴权**（不只检查「登录了没」）？
- [ ] 密钥/token/私钥是否**不在**代码库、日志、错误响应、前端产物中？
- [ ] 密码/敏感字段是否用**慢哈希**（bcrypt/argon2/scrypt），而非 MD5/SHA1/明文？
- [ ] 依赖是否有已知被利用漏洞（CVE）？

### A2 数据与事务
- [ ] 写操作是否在**事务**内？事务边界是否覆盖了全部相关写入？
- [ ] 是否存在「先查再改」的竞态（check-then-act）？是否用条件更新/唯一约束/悲观锁兜住？
- [ ] 幂等：重复请求/重试是否会重复扣款、重复发货、重复创建？
- [ ] 迁移：是否有**回滚方案**？大表 DDL 是否锁表？是否可在线执行？

### A3 正确性与可用性
- [ ] 错误路径是否有明确处理（不是 `catch {}` 吞掉）？
- [ ] 外部调用是否设**超时 + 重试（含退避）+ 熔断/降级**？
- [ ] 空值/边界/分页末页/时区/浮点金额/字符编码（UTF-8 与中文路径）是否考虑？
- [ ] 破坏性变更是否标注 `BREAKING` 并给出迁移路径与并存期？

### A4 资源
- [ ] 连接/文件/锁/流是否在**所有**分支（含异常分支）释放？（优先 try-with-resources / `with` / defer）
- [ ] 是否有无上限的集合累加、递归、队列消费？是否有背压？

---

## B. P1 本迭代必修

### B1 结构
- [ ] 单个函数是否超 ~50 行或圈复杂度 > 10？职责是否单一？
- [ ] 是否存在跨层调用（HTTP 处理里直接写 SQL、领域层直接依赖框架请求对象）？
- [ ] 重复逻辑：同一业务规则是否出现在 ≥3 处（未来会漏改）？
- [ ] 依赖方向是否单向？是否有循环依赖？

### B2 性能
- [ ] 循环内是否有查询/远程调用（N+1）？
- [ ] 列表接口是否**有分页且分页有上限**？
- [ ] 查询字段列表是否显式（避免 `SELECT *` 带来的隐式契约与传输浪费）？
- [ ] 热点读是否有缓存，**且**缓存是否有一致性/穿透/雪崩处理？

### B3 可测试性
- [ ] 核心业务分支是否可被单测覆盖（无隐藏的全局状态、时间、随机数、网络耦合）？
- [ ] 是否给「失败路径」写了用例，而不仅是 happy path？

### B4 可观测性
- [ ] 关键路径是否有日志（含关联 ID）？日志是否含敏感信息？（含则属 P0）
- [ ] 新功能是否可被度量（指标/埋点），以便上线后判断成败？

---

## C. P2 待办

- [ ] 命名是否表达意图（`data` / `tmp` / `flag` / `process()` 属欠债）？
- [ ] 注释是否解释**为什么**（而非复述代码）？过期注释是否清除？
- [ ] 是否有死代码、注释掉的代码块、未使用的依赖与配置？
- [ ] 文档：README / 接口文档 / 部署说明 是否与代码一致？
- [ ] 测试缺口清单是否已记录（而非仅口头知晓）？

---

## D. 交接口径（团队统一术语）

- **P0**：阻断，立即修
- **P1**：本迭代必修
- **P2**：排期修
- **P3**：交给 linter，不进人工评审
- **BREAKING**：破坏性变更，必须有迁移路径
- **假设**：未验证的判断，必须附验证方法，不得当作结论
- **本次未覆盖**：明确声明范围外内容

---

## E. 五分钟快查（时间极紧时）

只问 6 个问题：

1. 这段改动会让**钱/数据/权限**出错吗？
2. 谁能调用它？他应该能吗？
3. 失败了会怎样？有人知道吗？
4. 重复执行一次会怎样？
5. 上线后怎么知道它是好的？
6. 出问题怎么退回去？

## F. 本仓追加（在原文之上 · 每一条都有实测血账 · 2026-09-27）

> 原文未改；以下是**我们自己踩出来的**条目，与上面 A–E 同等效力。

### F1 退出码必须进成功判据（**假绿**血账）
- [ ] 任何"跑完了"的判据里，**退出码（returncode）在场吗**？（只看"文件在/体积够"会拿**上一版旧产物**报 ✔，还给旧产物打新指纹）
- [ ] 失败时**不打任何"通过"类印记**（指纹/台账/报告）

### F2 读数不许被自己筛丢（**假读数**血账）
- [ ] 取数字的那一步，**日志级别/过滤条件没把本次要读的行筛掉**吗？（实测：`-v error` 把 info 级的 SSIM 摘要筛没了 ⇒ 四档全 None）
- [ ] 非有限值（`nan`/`inf`）**必须滤掉**再用（实测：首帧 nan 毒化均值 ⇒ 误判"画面太糊"并触发错误重做）

### F3 阈值必须是量出来的（**假红**血账）
- [ ] 任何门槛（timeout/清晰度/运动量）是否**有标定证据**？（实测：清晰度阈值靠三档实拍标定 1.455/0.683/0.129 → 定 0.6；运动区间按 静止 0.001/剧情 1.185/动作 7.228 定 [0.4,60]）
- [ ] 标定值写进代码/文档了吗（别人能复核）

### F4 时空口径
- [ ] 时刻用**按索引乘法**算（`t = round(i × BEAT, 6)`），**禁 `t += Δ` 累加**（长片会累出可测漂移）
- [ ] 有 BPM 时**帧率由 BPM 反推**（每拍必须整数帧）；剪辑点落在拍上
- [ ] 关键文件（清单/参考片）的**分辨率/时长现读**，不写死

### F5 契约与回滚（清单字段即契约）
- [ ] 改字段**含义/类型/名字**或删字段 = **BREAKING**：标注 + 给迁移（加字段才是安全的）
- [ ] 改清单/规格前**先备份**（本仓惯例：`.bak-<工具>-<时间戳>`）
- [ ] 有**回滚方式**吗？（⏳ 本仓尚未做"回滚演练"，见吸收清单）

### F6 修完问一句 L3（**防复发**）
- [ ] 这次修完，**同类问题怎么才"不可能再发生而不被发现"**？（加判据/加门禁/进清单——不是"下次注意"）
- [ ] 同一个坑**第 3 次出现**了吗？→ 立刻变成机器判据

### F7 不虚报高危（与 F1 是对称的纪律）
- [ ] 无法构造路径/无法复现的，**只能标"待验假设/加固建议"**，不许混进 P0（虚报消耗信任与注意力）
