## 一、熔出来的那一条（回炉的核）

三件事**不是三件**，是**同一条原理的三个落点**：**用一次便宜的选择性，替掉一次昂贵的全量。**

| 件 | 昂贵的那次"全量" | 换成的"选择性" | 出处 |
|---|---|---|---|
| AirLLM | 整个模型常驻显存 | 只搬这一 token 真正要碰的**层/专家** | `airllm_base.py:748-774`（钩子）、`:841-854`（专家级） |
| express_bridge | 主模型**完整推理一次**去猜该走哪根触手 | 快尺**单遍打分**直达（0.17s P50） | 《触手双向绑定架构-表格版》表 2/表 3 |
| decision（快尺） | 生成自由文本再解析 | 单遍打分**只回概率**，决策权留调用方 | 同上 表 8 |

⇒ **回炉后的东西 = 把"按需"从"路由"一路贯到"显存"。三层落点：**

```
① 路由层「谁来做」   快尺判 → 直达能力/触手      （不烧主模型完整推理）
② 搬运层「搬哪一块」 只 materialize 本次真要碰的层/专家，算完即放（meta 骨架 + 钩子）
③ 内存层「什么可以不留」 embedding → 磁盘 mmap；resident 只留最小集；其余全 meta
```

## 二、三层各自的接口与判据（施工用）

**① 路由层** —— 三层回退链**照抄设计**，不许只留一层：
`轻量打分`（0.17s，需凭据）→ `本地语义路由`（毫秒级，无凭据）→ `名字面匹配`（毫秒级，恒标 degraded）。
**判据**：三层各造一个负例（打分超时 / 语义未命中 / 名字不匹配），**每一层都要能独立触发并如实标 degraded**；不允许"静默回退当成功"。

**② 搬运层** —— 骨架必须建在 `meta`，搬运走前/后钩子；**MoE 走专家级**（不是层级）。
**判据**：① 显存峰值读数 ≈ **单层**（不是全模型）；② 同一提示两次跑，**峰值不随模型总大小变**；③ 未命中的专家**不许被 materialize**（读钩子命中日志点）。

**③ 内存层** —— 大表走 file-backed mmap；resident 白名单必须**逐个写明为什么它必须常驻**（默认拒绝常驻）。
**判据**：resident 集合的字节数**有上限且能报数**；超限即红。

## 三、🔴 硬约束（写死，不许在宣传里丢掉）

1. **压的是"显存"，不是"权重总量"。** 权重仍旧躺在磁盘/内存里 —— AirLLM 自己 README:286 逐字：*"the VRAM you need depends on the model's **layer size** — not its total size"*。⇒ "人手一个"的**真约束是权重总量 + 每 token 搬运量**，不是显存。
2. **不许承诺"又快又省"。** 每 token 都要把整模型（或活跃专家）重读一遍 ⇒ 瓶颈在磁盘/PCIe 带宽。**它是拿速度换内存。**（源码里没有任何"更快"的表述；"慢多少"我没实测，**不编数字**。）
3. **它与"不幻觉/输出精准"无关。** 它只搬内存。输出质量靠"能力位＝器官 + 自证读数"那套。**两条目标不许混成一条。**
4. **本机零算力。** 仓里 `train_recipe` 能力位逐字："**本机零算力 ⇒ 不接真训练**"；主人 2026-10-11 令「本地不要大模型」（本机 ollama/llama/vllm 进程实测 0 个）。⇒ 真搬运/真推理**只能在云上**。
5. **那两件还没进仓。** `tentacle/express_bridge.py` 与 `llm/decision.py` **本仓、V9 树都没有**（我搜过）。《触手双向绑定架构-表格版》里那两栏写「✅ 已实现 self-test 通过」是**别处的现状**，**不是本仓的现状** ⇒ 本仓现在要走这条直达路，是**重造**，不是搬运。
