## 六、顺带查实的两处框架缺陷

### 6.1 `voice_orchestra op=query` 的门**挂错了**（从源码读实）
```python
def __init__(self):
    self.registry = VOICE_SKILL_REGISTRY
def query(self, domain=None, keyword="") -> List[VoiceSkill]:
    results = self.registry      # ← 纯本地静态查表
    return results               # ← 不联网、不写盘、不导出任何东西
```
**而它被挂了 `data_export` + `external_llm`，其中 `data_export` 是**一次性消耗**的。**
**⇒ 一个纯本地查表被判成"把数据发送到外部服务或持久化到框架外"** —— 门挂错了，
而且与 `voice_orchestra` 自己 `status` 报的 `readonly: true` 自相矛盾。
（副作用很实在：主人为一个只读查询要烧掉一张**一次性**授权。**未改，等拍板。**）

### 6.2 `voice_orchestra op=pipeline` 对**非法 scene** 返回 `ok: true`
```
{"op":"pipeline","scene":"配音克隆"}
 → {"ok": true, "steps": {"提示":"请指定场景（实时对话/有声书/视频配音/跨语言配音/歌声转换/无障碍语音修复）", …}}
```
合法 scene 是**固定 6 条**；传不在这 6 条里的，**不报错**、`ok` 仍是 `true`。
**⇒ 只检查 `ok` 的调用方会以为拿到计划了。** 与本次排雷一路抓到的是同一类病。
（对照：同样少传参数的 `op=pipeline`（**不带 scene**）倒是如实报 `ok:false` + `missing:["scene"]` —— 所以这不是"设计如此"，是不一致。）

## 十一、闭环第二腿：**只差授权**（2026-09-25 · 第 10 轮）

### 11.1 `voice.tts` 的签名（现读）
```
tts(text, voice=None, rate=0, out=None)      ← **本来就有 out 参数，能落盘**
```

### 11.2 第二腿（音频落盘）差的**只是授权**，不是功能
```
带 out=<路径> 调用 → denied：
  {"denied":true, "reason":"需要人工授权（filesystem_write）",
   "scopes":["filesystem_write","audio_output"], "missing":["filesystem_write"]}
```
**⇒ 门很精确：只缺 `filesystem_write` 这一个**（`audio_output` 已到位）。
**⇒ 终端发一张 `filesystem_write`，第二腿立刻能跑**，并会生成真 WAV 供第三腿（ASR）用。

### 11.3 🔴 又实测到一例「报了成功但什么都没做」（确凿）
参数名写成 `path=`（**不是它的参数**）：
```json
{"ok": true, "backend": "win-sapi", "spoken": true, "auth_consumed": "grant-…"}
```
**而文件根本没生成**（落盘存在? **False**，0 字节）。
**⇒ 参数名写错时它不报错，回 `ok:True + spoken:True`，参数被静默忽略。**
**与本次排雷一路抓到的是同一类病**（参数静默丢弃 / 报成功但没做事）。
**建议**：`tts` 收到未知参数时应如实报 `unknown_param`，而不是静默吞掉。**未改，等拍板。**
