- **二进制如实归类**（8,730 件，示例）：浏览器/字节码 1,347 · 图像 1,119 · Python 扩展 188 ·

- **读失败 6 件**：全部是**活着的浏览器 profile**（`store/native_browser/`）——
  5 件在扫描过程中被浏览器改写/删除（FileNotFoundError）、1 件权重文件 `MemoryError`。
  **它们是运行时产物，不是源码**；且**读不到就读不到，如实记名**。

### 三路读者（同一文件、互相独立）
- **A 行级模式**：复用穿透式扫描器的危险模式表与分诊（**一处定义两处用，不抄第二份**）；
- **B 结构可解析**：`.py` → `ast.parse` · `.json` → `json.loads` · `.yaml` → 安全装载 ·
  `.js/.ts` → 括号配平 · `.md/.html` → 围栏配对；
- **C 编码与卫生**：NUL 字节 · CRLF/LF 混用 · 行尾空白 · 末行截断 · 制表符与空格混排。
- **交叉校验**：三路行数必须一致 ⇒ 实测 **读数打架 = 0**（读者之间没有互相矛盾）。

## 二、关键发现（真正值得看的，只有这几条）

### 发现 1：**行号漂移** —— 报告指错了地方（已修，本次扫描最大的收获）
剥文档串时把整块**吞掉**，行号整体偏移：实测 `deploy/cloud-10/container/server.py:79`
报的其实是 `else:`、`lark_inventory.py:32` 报的是空行、`dsh-route-check.py:83` 报的是无关函数。
⇒ **报错行号指错地方 = 报告不能落地**，和人肉去翻没区别。修法：剥离处换成**等量空行**。

### 发现 2：**一个被锁住的文件掀翻了整轮扫描**（已修）
首跑在 `gbt_allinone/store/native_browser/profile/Default/Cache/Cache_Data/data_0` 抛
`PermissionError`（浏览器开着，句柄锁着）⇒ 218,226 文件的扫描在第 ~150k 处**当场中断**。
主人令写的是「不得中途停止」⇒ 改成：读不到就记"读失败"继续跑；单文件任何异常都被兜住
（`_safe_scan_one`）；枚举阶段锁着的目录也不许中断（`os.walk(onerror=...)`）。

### 发现 3：**同一判据写在两条路上**（已修，扫描自己逮住的）
反序列化类的"安全形态"（加载器派生自 `SafeLoader`）只写在引擎的文件扫描函数里，
全树逐行那条路**没有**它 ⇒ 同一个已验证安全的文件被重新报成"需人核"。
⇒ 判据收进 `_triage`（**单一来源**）。

### 发现 4：**虚报收口**（"扫来扫去都是故障"的根因）
分诊从 6 类扩到 11 类（**先认面，再看模式**）：

| 面 | 例 | 实测条数 |
|---|---|---|
| 第三方(依赖/运行时) | `node_modules/` `@prisma/*` · `.pylibs/` · `store/native_browser` · 各 agent 工具的技能镜像 | 470 |
| 夹具/检测器 | tests 合成值 · 探测器自己的模式表 · `TAINT_SAFE` | 31 |
| 设计如此(已人工过目) | **显式白名单 + 逐条理由**（MCP 命令工具本体 · 后端命令模板 · `child_process` 导入行 · 桩执行） | 29 |
| 派生物(打包/跑批输出) | `.map` `.latest.js` `.min.js` `.out` | 22 |
| 数据路径 | 图像/视觉工具里的 base64 解码（解的是图像字节） | 13 |
| 读数/记录(自指) | `state/*.json` · `output/skill-vet/*`（读数里出现模式字样是因为它在**记**模式） | 13 |
| 文档(规则举例) | `.md` 里的"禁止 eval"/血账引用 —— **凭据/私钥类不豁免** | 11 |
| 安全形态 | 加载器派生自 `SafeLoader` | 1 |
| 占位符(无密钥形状) | `drift-probe-owner`（自述探针名） | 1 |
| **需人核** | 其余 —— **只有这一类计入告警数** | **0** |

- 收敛路径：全仓首跑 1,692 → 归面后 **409**（自有树）→ 逐条查证 **32** → 最后 **5** → **0**。
- **显式白名单，不用宽泛启发式**：宽泛规则会把**将来**的真问题一起吞掉。新增文件再次命中同一模式时，
  仍旧走「需人核」（白名单不会自动扩张）。

### 发现 5：**结构读者的能力边界（如实标注，不装）**
`结构解析失败 40` 件**全部落在依赖树与第三方 TS/d.ts**
（我的括号配平对 TSX、`.d.ts`、打包产物不可靠）；另有若干 markdown 围栏计数误报。
⇒ 这是**读者的已知边界**，不是代码缺陷；已如实列出，不折算成绿。

### 发现 6：**卫生信号 40 件**（低危，已列名）
`行尾空白`（旧 `.cluster/five-dim-ultimate/caps/*.py` 各 50–90 处）· `含 NUL 字节`
（别的工具留下的 hook 状态快照 `.mimosa/hook-state/*.source`，非源码）。

### 发现 7（**待主人拍板，已记 D14**）：容器命令面缺第二道锁
`deploy/cloud-10/container/server.py` 的 `/run`：`0.0.0.0` 起服、**容器内无令牌闸**，
`cmd` 直接来自 POST body ⇒ 访问控制**单层**（全在对账 mesh 的 `OP_GATES`）。
