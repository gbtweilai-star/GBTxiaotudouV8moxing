## 四、设计要点（为什么这样训）

1. **不许编** → 事实类问题**不过语言模型**：`fact_gate`（现读→代码判定→原文引用）· `policy_gate`（现读真门作用域表→意图对照→代码判定）。
   实证：**三次重训治不住"编事实"**，约十轮提示词只换失败模式；**代码直答稳**。
2. **不阉割** → 底座用 abliterated 无对齐版，训练语料只加纪律、不加拒绝套话。
3. **不漂移** → 身份/开发者/三大工作流做**逐字锚定**，并在 system 里与"纪律清单"**物理分开**（规矩清单 ≠ 事实清单）。

## 五、已知局限（如实写）

- 无框架助读（`fact_gate`/`policy_gate`）时，模型**仍可能给机器事实加戏**（编文件名/版本号）。
  ⇒ 生产用请**始终经框架**（本仓提供 `/v1/chat/completions`，OpenAI 兼容）。
- 知识截止随底座；**不保证**时效性。
- 无对齐底座 ⇒ 输出**未经过内容安全对齐**，部署方需自行评估合规与访问控制。

## 六、怎么用（OpenAI 兼容）

```bash
curl https://<your-endpoint>/v1/chat/completions \
  -H "Authorization: Bearer $KEY" -H "Content-Type: application/json" \
  -d '{"model":"gbt-potato-v8","messages":[{"role":"user","content":"你的名字？"}]}'
```

自托管：vLLM / RunPod Serverless（`MAX_MODEL_LEN=16384`），或 Cloudflare Worker 网关（本仓 `deploy/cloud-10`）。
