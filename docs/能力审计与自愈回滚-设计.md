## 一、审计口径（**不许假绿**是第一纪律**）

### 1.1 四态定义

主人说的是「三态」，本件落成**四态**，因为**「断连」与「缺失」是两件不同的事**：
一个「真探过、失败了」，一个「清单里有它、实物压根不在」。混在一起就说不清是谁的锅。

| 态 | 定义 | 证据要求 |
|---|---|---|
| **接上** | **真探过**且符合该条自己的验收口径（文件在盘非空 / HTTP 命中） | `probe.at` 非空 + `probe.ok is True` + 原始读数 |
| **断连** | **真探过**、失败 | **必须落原始串**（HTTP 状态码 / 异常名 + 原文），不许吞 |
| **缺失** | **清单/真源里有它、实物不在** | 写明「哪张单点名的 + 查的是哪个路径」 |
| **未探测** | **没条件探**（没跑过探针 / 源件读不到 / 被守卫拦下） | **必须写明为什么** |

> 与主人「三态」的对应：主人的三态意图 = 「接上 / 不通（含断连+缺失）/ 未探测」。
> 本件把「不通」再切开成**断连**（探过失败）与**缺失**（实物不在）——信息更多，不更少。

### 1.2 铁律

1. **不许假绿**：**没探过的项一律「未探测」，不许画成「接上」**。任何「应该能通吧」式结论算违规。
   → 判据 `C4` 专门钉这一条：`state==接上` 必须有 `probe.at` + `probe.ok is True`；`state==未探测`
   的项**不许**带探测记录（带了就报红）。
2. **断连必带原始串**：HTTP 状态码 / 异常名 + 原文，一字不改。
3. **缺失必说清**：哪张清单点名的、查的哪个实物路径。
4. **云插件复用旧口径**：`deploy/cloud-10/mesh.json` 是**现役真源**（10 位），
   `plugins50.json` 是 **50 槽蓝图**（未部署 · 无 ops · 无端点）—— **蓝图不算接上**，且**不探测**
   （对未部署的槽发请求只会造假红）。host 校验与 `/health?_probe=<id>` 台账口径**直接复用**
   `tools/codex-scripts/cloud-status.py`（以文件路径 import 它的函数，**不另发明一套，也不改它**）。
5. **本机回环探测**是**为自愈服务的**：面板桥起没起、DSH 接没接上、本机依赖服务在不在。
   只探**登记在册**的回环地址（下表），守卫是**正向白名单**（不是反向拦截）。

## 二、报警条件

一条报警 = 该项 `state ∈ {断连, 缺失}`。报警清单在面板上**置顶**（断连在前、缺失在后），
`watch` 子命令也把它按「可自愈 / 升级给人」两栏打出**逐条原文**。

| 情形 | 报警 | 处置 |
|---|---|---|
| 文件在盘但 **0 字节** | 断连 | 产物类 → 自愈；源码类 → 升级给人 |
| 文件**不在盘**（清单点名） | 缺失 | 产物类 → 自愈；源码/注册表类 → 升级给人 |
| 产物**落后源件超过宽限**（快照类 0s / 只追加类 600s） | 断连（陈旧） | 产物类 → 自愈（重跑生成器） |
| HTTP **非 200 / 超时 / 连接被拒** | 断连（带原始串） | 回环在册且在白名单 → 自愈；其余 → 升级给人 |
| 回包 `ok != true` / 行内缺本插件那一行 | 断连 | 升级给人（外部服务） |
| 守卫拦下，未发请求 | **未探测**（不是断连） | 不报警；面板单列「未探测清单」 |

> **关于「陈旧」这类断连的宽限窗口（600s）—— 一条**由实测逼出来的**设计**：
> `state/logbook.jsonl` 是**只追加的活账本**，而纪律要求**每一次自愈动作都往它 append 一条**。
> 于是「产物比源件旧」这条判据会**自己把自己触发**：`heal` 修好 `logbook-data.js` 那一刻，
> 它顺手写的那条记录又让 `logbook.jsonl` 更新了 ⇒ 下一步审计马上又说「陈旧」⇒ **死循环**
> （本轮真跑就撞上了）。对策不是撤掉判据，而是给**只追加源件**留**一个渲染周期的宽限**：
> 产物允许落后源件 ≤ 600s；只有源件被追加了**超过宽限还没重渲**，才算「陈旧」⇒ `heal` 重跑
> `logbook.py render` 即恢复。这不是给假绿开口子 —— **落后一小时的页照样报红**；
> 快照类源件（`state/cloud-status.json` 等）宽限为 **0**（一秒钟的滞后也照报）。
> 实测：同一对 `logbook-data` / `logbook-digest` 在加宽限前会周期性进报警，加宽限后稳定为「接上」。

## 三、自愈动作清单（**白名单只有三类**，逐个写清）

> 每个动作**三步走**：① 先备份 → ② 再执行 → ③ 后复验；**复验不过就自动回滚**并把原文打出来。
> 每个动作（含回滚）都往记录本 `append` 一条（`state/logbook.jsonl`，只追加 · 自链哈希）。

### 动作 ①：缺/旧的**生成产物** → 重跑它**自己的**生成器

| 项 | 做什么 | 备份什么 | 怎么回滚 | 复验判据 |
|---|---|---|---|---|
| `artifact.brain-data` | `py -3.14 tools/codex-scripts/brain-feed.py --out holo_pet_w3/brain/brain-data.js` | 把 `holo_pet_w3/brain/brain-data.js` **复制**进 `state/_heal_backup/<id>/` | 复制回该备份（文件类） | `probe_item("artifact.brain-data")` 真重探 = 接上 |
| `artifact.logbook-data` / `artifact.logbook-digest` | `py -3.14 tools/codex-scripts/logbook.py render` | 复制 `logbook-data.js` / `logbook-digest.md` | 复制回 | 同上（真重探） |
| `artifact.cloud-status-ledger` | `py -3.14 tools/codex-scripts/cloud-status.py probe` | 复制 `state/cloud-status.json` | 复制回 | 真重探 |
| `artifact.cloud-status-page` / `-data` / `artifact.cloud-plugins-page` / `-data` | `py -3.14 tools/codex-scripts/cloud-status.py render` | 复制该页/该数据件 | 复制回 | 真重探 |
| `artifact.capability-audit-ledger` | `py -3.14 tools/codex-scripts/capability-audit.py probe` | 复制 `state/capability-audit.json` | 复制回 | 真重探 |
| `artifact.capabilities-page` / `-data` | `py -3.14 tools/codex-scripts/capability-audit.py render` | 复制该页/该数据件 | 复制回 | 真重探 |

> **真读数里的一个真缺陷（由复验抓出来）**：`brain-feed.py` 的 `--out` 默认是**空串**——
> 不给 `--out` 它**只打屏、不落盘**。首轮自愈就撞上了：生成器 `rc=0` 但文件仍是 0 字节，
> **复验判「断连」⇒ 自动回滚**，没有假装修好。修法 = 把生成器命令补成
> `brain-feed.py --out holo_pet_w3/brain/brain-data.js`。这正是「复验」这一环的价值。

### 动作 ②：面板桥没起 → 起 `holo_pet/launch_panel.py`

| 项 | 做什么 | 备份什么 | 怎么回滚 | 复验判据 |
|---|---|---|---|---|
| `bridge.panel-8765` | `py -3.14 holo_pet/launch_panel.py --no-browser`（起**一个**） | 只记「起之前 8765 是否在听」（**不动已有进程**）+ 本次 spawn 的 pid | **只停本次 spawn 的 pid**（`taskkill /PID <自己的 pid>`）；不碰别人的进程 | 真重探 `GET 127.0.0.1:8765/api/state` = 200 且 `ok=true` |

### 动作 ③：DSH 没接上 → `dsh web --no-open`

| 项 | 做什么 | 备份什么 | 怎么回滚 | 复验判据 |
|---|---|---|---|---|
| `dsh.web-3080` | `dsh web --no-open`（`shell/dsh-launch.cjs` 的既有做法） | 只记「起之前 3080 是否在听」+ 本次 pid | 只停本次 spawn 的 pid | 真重探 `GET 127.0.0.1:3080/` 取得任何 HTTP 响应（401 是预期）= 接上 |

### 有界（硬性）

- **不许杀不属于自己的进程**（进程类动作只回滚**自己 spawn 的那个 pid**）；
- **不许删文件**（备份是**复制**，回滚是**复制回去**；备份落 `state/_heal_backup/<id>/`）；
- **不许改配置**、**不许动 `~/.dsh`**、**不许改**主人在册「别动」清单里的任何文件；
- 生成器命令**只跑在册的那条**，不做任何额外动作。
