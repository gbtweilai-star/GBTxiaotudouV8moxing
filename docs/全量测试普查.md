## 二、🔴 自纠：**我的普查器第一版跑法错了，给出的是完全错误的图景**

第一版是「直接 `python <文件>`」。实测：这样跑时 `sys.path[0]` 是**脚本所在目录**
（`gbt_allinone/tests`）而不是仓根 ⇒ `import gbt_allinone` 失败 ⇒
`ModuleNotFoundError: No module named 'gbt_allinone'`。
我据此报了「17 个测试加载不起来」—— **那是假警报。**

**受控对照**（同一个文件 `test_absorb_loop.py`）：

| 跑法 | 结果 |
|---|---|
| 直接跑文件 | ❌ ModuleNotFoundError |
| `python -m unittest gbt_allinone.tests.test_absorb_loop` | ✅ OK（17 项） |
| 从仓根跑（cwd 在 sys.path 里） | ✅ OK（17 项） |

**根因**：100 个文件里 **79 个自带 `sys.path` 引导**、**21 个没有** ⇒ 两种跑法并存；
没有引导的那些**必须从仓根跑**（本仓口径也是 `-m unittest`）。
**修法**：普查器改成 `-m unittest gbt_allinone.tests.<名字>` + `PYTHONPATH=仓根`。

**改对之后的差异有多大**（同一批文件，两种跑法的读数）：

| 文件 | 错跑法（第一版） | 对跑法（第二版） |
|---|---|---|
| `test_awesome_tools_index.py` | ERROR（0 用例） | **246 项 OK** |
| `test_h3_video_gen.py` | ERROR | **99 项 OK** |
| `test_sync_exec_nail.py` | **13 项失败** | **17 项全 OK** |
| `test_native_browser.py` | ERROR | 6 项 OK |

⇒ **第一版的"17 个加载不起来 + 13 项失败"全部作废。**

**第二处盲区（也已查明，非缺陷）**：另有 8 个文件在我口径下"跑 0 个用例"——
它们是 **pytest 风格**（无 `unittest.TestCase`，但有 10~41 个 `def test_*`）：

```
test_call_graph · test_long_run_supervisor · test_nav_etiology · test_omni_audio
test_omni_fs · test_omni_web · test_scan_engine · test_silero_vad
```
用 `pytest` 跑：**156 passed, 1 skipped** ⇒ **它们是好的**，是普查器缺一种跑法。
