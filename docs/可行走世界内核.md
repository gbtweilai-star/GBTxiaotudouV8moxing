## §0 一句话

**它给 GBT 补的是"空间"这一维**：以前能生成文字 / 图像 / 视频 / 音乐，
现在能生成**一个能走进去的世界** —— 有天空、太阳、雾、地形、树木、风；
你走进去，指着一个地方说"这里树太多"，它就改了，出新版，还留着上一版。

**从"看作品"到"走进作品"。**

它**不是图像生成**，是「**世界生成 + 可行走验证 + 反馈迭代**」。

| 传统图像生成 | 可行走世界 |
|---|---|
| 生成一张图 | 生成一个可探索的 3D 世界 |
| 看，不能进 | **能走进去看** |
| 不满意重画 | **打别针 → Agent 编辑 → 保留每版** |
| 提示词驱动 | **参考图驱动**（从真图读懂世界） |

## §1 五原语（缺一不可）

| 原语 | 做什么 | 判据 | 本版现状 |
|---|---|---|---|
| **READ** | 读参考图 + 分析（天空色 / 地平线 / 太阳 / 雾 / 地面纹理 / 植被色调） | 参考图存在且可读 | ⚠️ 契约在，分析端 `not_wired` |
| **BUILD** | 构建世界（env / terrain / scatter / refcam / hero） | **必须有参考图**（红线①） | ⚠️ 落点与版本目录写实，生成端 `not_wired` |
| **WALK** | 走进世界（**人看**） | 世界存在且版本目录在 | ⚠️ 无 3D 世界查看器 |
| **PIN** | 打别针（**人指**）：位置 + 视角 + 快照 | pin 三要素齐（红线③） | ✅ **契约已写实** |
| **EVOLVE** | 读反馈 → 编辑 → 新版本 / revert | 每版必留、可 revert（红线②） | ✅ **契约已写实** |

> 不 READ 就是瞎造，不 BUILD 就是空谈，不 WALK 就没法验，
> 不 PIN 就没反馈，不 EVOLVE 就是一次性作品。

## §2 四个最值钱的设计

### ① 参考图驱动：从图里"读懂"世界

| 从参考图提取 | 从 spec 提取 |
|---|---|
| 天空色、地平线颜色 | 生物群系 |
| 地平线倾斜 → **相机角度** | 一天时间 |
| 太阳位置（若在画面） | 密度 |
| 雾的浓度 | 地形高度 |
| 地面纹理（**从图里裁**） | 长什么 |
| 植被色调 | |

**不靠纯文字想象，靠真图当锚点。** 这与 GBT 已有的**场景锚定**完全同源 ——
场景不是想象出来的，是从真图里读出来的。

### ② 可行走验证：让用户走进去
生成完不是"看图"，是**进世界走一圈**。这解决了"生成的东西对不对"的终极验证问题 ——
**好不好，走进去就知道**。

### ③ 别针反馈：从"说"变成"指"
走动时按 Feedback，在**具体位置**打一个 pin：
"这里树太多" / "天空太饱和" / "这个石头太大"。
每个 pin 保存**位置 + 视角 + 快照** —— 不是模糊反馈，是**精确到坐标与视角**的反馈。

### ④ 版本保留 + revert
每次编辑出新版本，**每一版都保留**，可以 `revert_world` 回退。
与 GBT 的**护照 + 回滚点**完全对齐。

---

## §3 五条红线（写死）

1. **参考图驱动，不许凭空造** —— 无参考图即拒
2. **每版必留，可 revert** —— 版本目录只增不改，回退靠切换指针
3. **反馈 pin 必须可追** —— 每个 pin 带 position + view + snapshot
4. **写操作走门禁** —— create / edit / revert 都过 `auth_gate`（scope=`filesystem_write`）
5. **每次操作留痕** —— 写 `trace_store`，`source_kind="bepic_world"`

## §8 诚实边界（写进代码常量）

> **可行走世界内核保证「从参考图构建、可走、可反馈、可 revert」；
> 它保证不了「世界一定好看」—— 好不好看，走进去的人说了算。**

以及本版的额外边界（**不许读成"已完成"**）：
- 五原语**契约与留痕已写实**，但 **READ/BUILD/WALK 的生成端一律 `not_wired`**
- 理由：上游 `bepic_worlds` 库本机不存在、公开检索也查不到
- **不假装能跑** —— 每处未接线都在返回值里明写 `status: "not_wired"` 与 `why`
