### 4.1 主人令：「**内存不够就让触手继续加插件**」——本仓把它落成一条设计原则

- 不要把"出图 + 超分 + 视频"塞进同一个进程；
- 每一段是一个**能力位 + 一个模块**，各有自己的落点与审计；
- 内存不够时**加的是"件"（触手），不是"给同一件加压"** —— 这与本仓"主控面板按触手根数排班"同构。

## 十九、「拼接」的技术原理（显示屏）→ 我们的方案能不能这么拼（2026-09-25）

主人令：**「你去抓取一下技术层精准抓取我们这样拼接技术是可以实现的，就好比如显示屏的连接原理」**。

### 十九·一 显示屏拼接的三层原理（取自 [Wikipedia · Video wall](https://en.wikipedia.org/wiki/Video_wall)）

1. **简单菊花链 / 内置矩阵分割器**：一块输入铺满全墙。
   🔴 原文的硬约束：「**it is impossible to use full pixel resolution of the video wall because the
   resolution cannot be bigger than the resolution of the input signal**」—— **总分辨率不能超过那一路输入**，
   而且**同时只能显示一个输入**。
2. **硬件控制器**：一个输入切成 N 块、各自驱动；支持 **bezel correction**（边框补偿）。
   优点高性能可靠，缺点贵、不灵活。
3. **软件/渲染集群**（SAGE · Chromium · Media Fusion）：**每个节点渲染自己那块**，
   把像素流进"虚拟高分辨率帧缓冲"，按 **viewport / tile 坐标**把流路由到对应显示节点，
   **依赖高带宽网络**；硬件侧靠 **genlock / 多输出卡（AMD Eyefinity、NVIDIA Mosaic，6–12 路）** 做同步。

### 十九·二 逐层映射到我们的算力拼接

| 显示屏那层 | 我们的对应物 | 现读状态 |
|---|---|---|
| ① 简单菊花链（上限=那一路输入） | **1 个模型端点 + N 个插件客户端** | ✅ **已验**：10 客户端 / 并发 2 / 排队峰值 9 / 全成功；**上限就是那个端点** |
| ② 硬件控制器（切块 + 边框补偿 + genlock） | **模型切块并行**：张量并行 / 流水线并行 / 专家并行 + **NCCL/NVLink 同步** | 🟡 **章节级已取证**（见 §二十）：vLLM 文档明确有 `Distributed inference strategies for a single-model replica` · `Single-node / Multi-node deployment` · `Running vLLM on a Ray cluster` · **`Optimizing network communication for tensor parallelism`** · **`Enabling GPUDirect RDMA`** ⇒ **机制存在、且"卡间互联"是独立课题**；**正文散文未逐页读**、性能数字不写；**本机无可用 GPU ⇒ 跑不了** |
| ③ 渲染集群（各渲染各的，靠网络汇像素） | **分离式推理 / 多节点服务**（prefill 与 decode 分开、KV 走高速网络） | 🟡 同上（同属 §二十 取到的章节范围：`Multi-node deployment` · `Disaggregated Prefilling`）；**需要多台机器 + 高速互联** |

### 十九·三 结论：**"拼接"能拼到哪一层，数字说了算**

- **编排层（①）：能拼，已经拼好了** —— 600/600 全互通 + 队列背压（`§十八` 与 `shared-endpoint-queue.py`）。
- **算力层（②③）：原理成立、本机不成立**：
  - 27B 最小量化档现读 **5.77 GiB**；若**两张 4 GB 卡做 2 路张量并行** ⇒ 每卡约 **2.89 GiB**，**理论上装得下**；
  - 但**要有两张卡 + 卡间高速互联 + 框架支持**；本机唯一的 GPU 是 **AMD RX 6500M（3.98 GB）**，
    且本机 `torch` 是 **CPU 构建**、`directml` 未装 ⇒ **连第 1 张卡都算不上可用**。
- ⇒ **"拼接"救不了"没有卡"**：显示屏拼接的前提是**每块屏都在**；算力拼接的前提是**每张卡都在且能互相同步**。

### 十九·四 一句归结

**你的模型是对的**：显示屏靠控制器 + 同步把 N 块屏拼成一块；
算力靠**切块并行 + 卡间同步（NCCL/NVLink）**把 N 张卡拼成一台。
**两者的前置条件也一样：部件得先在。** 我们缺的正是那"第一块屏"（一张可用 GPU 卡）。
