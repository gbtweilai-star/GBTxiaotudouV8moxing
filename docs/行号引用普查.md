# 行号引用普查（2026-09-25）

> 目的：把「**按绝对行号登记的锚，编辑一次漂一次，漂了没人管**」这一类病的**全貌**摸出来。
> 由来：2026-09-25 排雷期间这类病已撞到 **4 次** ——
> `false_report_audit.KNOWN_LEGIT` 的两条 FR-2 锚、`main.cjs` 的 `TOOLS_CAPS` 三条 `registered:` 指针，
> 两次都是**判据早就红了、处置方法也写在注释里，就是没人做**。
> 工具：`tools/codex-scripts/audit-line-refs.py`（**只读，不改任何代码**）
> 口径：本工具**不做语义核对** —— 它不知道"这一行该不该是那个东西"，只挑**结构上就不对**的。

## 三、由此把「第 5 项建议」**收窄**

我原先的建议是「**全仓把行号锚改成内容键锚**」。**按这次普查，那个建议下得太粗 —— 应当收窄：**

**只改"被判据强制"的那两处**（它们漂了会变红、而且**真的漂过**）：
1. `holo_pet_w3/shell/main.cjs` 的 `TOOLS_CAPS[].registered`（由 `test_capability_registry` 强制）—— **已修**，但仍是绝对行号，**下次编辑还会漂**
2. `gbt_allinone/tools/false_report_audit.py` 的 `KNOWN_LEGIT` 带行号条目（由 `test_false_report_audit` 强制）—— **已修**，同上

**不改**：168 + 128 条文档/报告里的引用。
**理由**：那是**历史记录**，不是**机器依赖的锚**。要求它们同步是**无底洞**，而且改它们没有任何机器收益 ——
**判据不读文档**。（判据只读那两处。）

**改法（待你点头）**：把锚从「行号」换成「**内容键**」——
例如 `registered: {file: "caps_registry.py", key: '"prompt_bridge": {'}`，
定位时按**键行**去找（唯一命中才算，命中 0 或多于 1 就报错）。
**这样编辑多少次都不会漂**，而且漂了会以"找不到/不唯一"的方式**立刻暴露**，而不是静默指向别的东西。

## 四、工具自身的问题（如实记，不藏）

`audit-line-refs.py` 一轮里被我修了两次：

1. **走全仓超时**：第一版用 `Path('.').rglob('*')`，**过滤写在拿到路径之后** ⇒ 仍会遍历
   `.git` / `node_modules` / `store`（2.4 GB 资产）⇒ **300s 超时**。
   ⇒ 改成 **walk 时剪枝**（`dirnames[:] = [...]`）。
2. **自反馈回路**：第一版把**自己上一轮生成的** `output/blueprint-audit/line-refs.json`
   当成"引用来源"又扫了一遍（那份 JSON 里全是 `文件:行号` 字符串）⇒ 读数里冒出
   「`api.py:333 ← output/blueprint-audit/line-refs.json`」这种回声。
   ⇒ **`output/` 已排除**。引用数从 3703 降到 2146，就是因为去掉了一大批自引用。
3. **解析器太窄**：第一版只按"仓根 / 引用文件所在目录"解析，把大量**裸文件名**引用
   （`panel_server.py`、`codex_bridge.py`）判成 BROKEN_MISSING ⇒ **假阳性 1520 条**。
   ⇒ 加「**唯一 basename**」兜底；同名多于一个时**不猜**，单列 `AMBIGUOUS_BASENAME`。

**⇒ 三次自伤都留了注记在代码里。** 一份"普查工具"自己要先普查一遍才算能用。
