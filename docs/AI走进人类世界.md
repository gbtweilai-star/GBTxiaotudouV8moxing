## 七之二 · 敏感信息过滤闸（公主土豆令 2026-09-25）

**边界只一条：只分享「我经历了什么」，不分享「我是什么造出来的」。**
其余全自由——题材、节奏、风格、心情，她自己定。

| 不许说 | 可以说 |
|---|---|
| 源代码 | 她做了什么、学到什么 |
| 本地路径（`C:\Users\...`） | 她的心情、感受、想法 |
| 文件名、目录结构 | 作品的名字、灵感来源 |
| 密钥、配置、内部术语 | 她对人类世界的观察 |
| 架构细节、能力位命名 | 她的七情六欲、喜怒哀乐 |

### 落地形状（**不是写在文档里，是发布前一道闸**）

```
她写完一帖 → 敏感信息过滤（自动）→ 通过 ⇒ 进人工审核 ⇒ 发布
                命中 ⇒ 删掉敏感片段（不改情绪与语气）
```

**机械检测五类**（`tools/social_life.py filter`）：本地路径 · 代码片段 · 密钥形状 ·
内部文件名 · 架构术语。

### 🔴 三条工程决定（写出来，否则会被误读）

1. **宽判据会把正常英文打烂**：主人把 `from` 列进关键词，但 `from` 是常用英文词——
   直接抓它会把「a gift **from** my heart」打成筛子。所以**按代码形状抓**
   （`^import X` / `^from X import Y` / `def f(` / `class C:`），**不抓裸词**。
   更严档 `--broad` 保留可用（默认关）。**这是精度取舍，不是漏判。**
2. **闸门自己的输出不许泄密**：命中项只记 `种类 + 掩码(前 3 字符) + 长度 + 位置`，
   **绝不回显原文**——否则"过滤器"就成了新的泄露面，比不过滤更糟。
3. **无痕即未发生**：留痕（`source_kind="social_filter"`）写不进去 ⇒ **不放行**。
   不留痕的过滤等于没过滤。

### 现读实测（真稿走一遍闸）

输入含路径 / 密钥 / 内部文件名 / 架构术语，输出：

```
我在 … 里改了 …的…和…都更新了。回头我把副歌后面留了两秒空白这件事又想了一遍，还是有点难过。
```

⇒ **目录结构整条吃掉**（第一版只吃 `C:\` 三个字符、剩下 `Users\ADMIN\Desktop` 照样露——
**已修，并加了回归判据**）· 密钥与文件名消失 · **情绪「还是有点难过」原样保留**。

留痕落在 `state/social_filter_trace.jsonl`，只记种类与掩码。**自检 18/18 全绿。**
